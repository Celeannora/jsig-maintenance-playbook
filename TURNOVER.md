## What this project is

A reference/scaffold repo for operating a JSIG (Joint SAP Implementation Guide) accredited SAP information system's Windows Server / Active Directory / Exchange environment (with Trellix/McAfee HBSS-style endpoint protection, Splunk, and Nessus as the named tool stack). It has two layers of maintenance tasking that are deliberately kept separate:

1. **Compliance tasking** — `MAINTENANCE-PLAN.md`'s 110-task Master Calendar, where every row exists because a specific JSIG Control ID/ODP requires it.
2. **Operational tasking** — `execution-plan/OPERATIONAL-TASKING.md`'s 34-task calendar, added this session, for pure IT-ops/functional-health work (is the domain/mail system/tool stack actually running) that JSIG doesn't drive at all.

Both calendars have a matching set of generated, sign-off-ready **Maintenance Requirement Cards** (Navy-PMS-style actionable procedure documents) — `execution-plan/mrc-cards/` (110 cards, JSIG) and `execution-plan/mrc-cards-ops/` (34 cards, operational).

## Standing constraints (must not violate)

- **`MAINTENANCE-PLAN.md`'s 110-task calendar (task list, frequencies, Control ID assignments) must NOT be edited.** This was an explicit, repeated user instruction across multiple sessions. The new `OPERATIONAL-TASKING.md` calendar was built specifically to be additive and never touches this file.
- Everything generated (`RACI-MATRIX.md`, `role_task_index.json`, `mrc-cards/`, `mrc-cards-ops/`, `OPERATIONAL-TASKING.md`) should be **regenerated from its script, never hand-edited directly**. Each generated file has a header noting which script produces it.
- **Offline-only, vendor-agnostic** is the design principle for everything except `mrc-cards/` and `mrc-cards-ops/`/`OPERATIONAL-TASKING.md`, which name real tools (Windows Server/AD, Trellix/McAfee, Splunk, Nessus) as an explicit, documented exception.
- Before every commit involving new/edited markdown links, run the repo-wide link audit (see below) — established pattern, reused 5+ times this session.

## Key reusable code/conventions for whoever picks this up

- `execution-plan/tools/build_raci_matrix.py`: `parse_calendar()` parses `MAINTENANCE-PLAN.md` into row dicts (`num`, `freq`, `task`, `family`, `controls`, `responsible_raw`); `map_row(row)` returns the RACI (`responsible`, `accountable`, `accountable_all`, `consulted`, `informed`).
- `execution-plan/tools/build_mrc_cards.py`: `load_patterns()` parses `_EXECUTION-PATTERNS.md` into `{letter: {"name", "intro", "steps"}}`; `extract_pattern_assignments()` scrapes all 17 role runbooks for `- Pattern X`/`- Custom` assignments; `primary_tools(task_text, family)` maps task text to a concrete tool string via `TOOL_KEYWORD_RULES`/`FAMILY_TOOL_DEFAULTS`.
- `execution-plan/tools/build_operational_tasking.py`: standalone `OPS_TASKS` hardcoded list (34 tasks) + `render_calendar()`/`render_card()`. Reuses `load_patterns()` from `build_mrc_cards.py` — same Pattern A–H vocabulary, no new pattern library invented.
- `data/control_title_index.json`: `{"AC-1": {"source": "references/JSIG-source/chapter-3-AC-family.md", "title": "..."}, ...}`, 949 entries.
- `ROLE-CROSSWALK.md`: documents that System Administrator and Network Administrator both map to Accountable=ISSM, Executing=Privileged User under ISSO technical supervision — reused verbatim for the operational calendar's RACI rather than inventing a new model.
- **Link-audit snippet** (run before every commit that touches markdown links):
  ```python
  import re, os
  link_re = re.compile(r'\[[^\]]*\]\((\.{0,2}/?[^):\s]+\.md(?:#[^)]*)?)\)')
  broken = []
  for root, dirs, files in os.walk('.'):
      if '.git' in root: continue
      for fn in files:
          if not fn.endswith('.md'): continue
          path = os.path.join(root, fn)
          text = open(path, encoding='utf-8').read()
          for m in link_re.finditer(text):
              link = m.group(1).split('#')[0]
              if not link: continue
              resolved = os.path.normpath(os.path.join(root, link))
              if not os.path.isfile(resolved):
                  broken.append((path, link, resolved))
  print('Broken links found:', len(broken))
  ```
  Expected result: exactly 1 pre-existing hit — `execution-plan/runbooks/_AUTHORING-BRIEF.md`'s template placeholder `<file>.md` — which is not a real bug, just an authoring-template artifact. Anything beyond that 1 is a real regression.
