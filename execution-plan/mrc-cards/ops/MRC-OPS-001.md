## 4. Safety / Handling Precautions

No physical hazard is inherent to this task. `repadmin.exe /replsummary` and `/showrepl` (run without any state-changing switch, as specified below — never `/replicate`, `/removelingeringobjects`, `/removeref`, or `/options`) are read-only against Active Directory replication metadata; they do not modify configuration or force replication. Running them against a production domain controller does not require a change-control window on its own, but if a failure is found and remediation is attempted afterward, that remediation follows the organization's standard change-control/maintenance-window process. Do not export diagnostic output (which can include hostnames and internal site topology) to unauthorized media or systems. If using the companion PowerShell script (Section 5.1), review it and test in a non-production environment first — see the disclaimer in [`scripts/README.md`](../scripts/README.md) and the script's own `.NOTES` block.

## 5. Procedure

This card assumes access to a Windows Server domain controller, or a management workstation with RSAT (Active Directory Domain Services and Lightweight Directory Tools) installed, and an account permitted to run `repadmin.exe` against the domain's DCs (local Administrators on a DC, or an equivalent delegated read-level account per organizational RBAC — `repadmin`'s read-only summary/show commands do not require Domain Admin rights).

### 5.1 Automated path (recommended)

1. On a domain-joined management workstation or a DC itself, open an elevated PowerShell session.
2. Obtain [`execution-plan/mrc-cards/scripts/MRC-OPS-001.ps1`](../scripts/MRC-OPS-001.ps1) from this repository (copy it locally if the repository is not directly reachable from the management host).
3. Run:
   ```powershell
   .\MRC-OPS-001.ps1
   ```
   — Expected result: the script runs `repadmin /replsummary` enterprise-wide (no scope argument, which defaults to `*` — every DC repadmin can reach), parses each DC's outbound ("Source DSA") and inbound ("Destination DSA") rows, and — for any DC showing one or more failures — automatically runs `repadmin /showrepl <DC>` for a verbose per-partner drill-down. — Capture: the script writes a timestamped report to `.\reports\MRC-OPS-001_<yyyyMMdd-HHmmss>.txt` by default (note the console-printed path; use `-OutputPath` to direct it to a shared evidence drive). — Stop/continue: if the script errors before producing any report (e.g., `repadmin.exe` not found on this host — RSAT AD DS tools not installed), fall back to the manual path in Section 5.2 for this cycle and log the tooling gap as a routine finding.
4. Read the script's console summary line (`Repadmin replication check complete. X passed / Y failed / Z warning(s).`) and check `$LASTEXITCODE` (`0` = every row passed with no staleness warnings; `1` = at least one replication failure, one stale link, or an unreachable scope). — Expected result: exit code `0`. — Capture: console output. — Stop/continue: if exit code is `1`, proceed to step 5.
5. Open the report file. Its `SUMMARY` section lists every row with `Target`, `CheckName` (`Replication-Outbound` or `Replication-Inbound`), `Result`, and `Detail` (delta time, fail count, and repadmin's own error text if present). Locate every row where `Result` is `Fail` or `Warning`. — Expected result: either zero non-Pass rows (clean cycle, file the report and close the cycle) or an identified list of affected DCs and directions. — Capture: the full report file (summary table + raw `/replsummary` output + any `/showrepl` drill-down) filed as this cycle's evidence. — Stop/continue: for any `Fail` row, check the error code/text against the triage table in Section 5.3 before deciding urgency; a `Warning`-only row (stale delta, zero failures) is a lower-urgency watch item — see Section 5.3.
6. If the script's default 24-hour staleness threshold does not match local policy, re-run with an explicit value, e.g. `.\MRC-OPS-001.ps1 -MaxDeltaHours 12`.

### 5.2 Manual path (fallback / spot-check verification)

1. On a DC or RSAT-enabled workstation, open an elevated Command Prompt or PowerShell session and run:
   ```
   repadmin /replsummary > repsummary_<yyyy-MM-dd>.txt
   ```
   — Expected result: a two-table report (Source DSA / outbound, then Destination DSA / inbound), one row per DC, each showing largest replication delta, fails/total, and (if any failures) an error code and message. — Capture: the redirected output file, added to the evidence package. — Stop/continue: continue to step 2 regardless of result.
2. Review every row. A row is a finding if its `fails/total` column shows any failures, or if its largest-delta value looks abnormally high for local policy (a common starting threshold is 24 hours, but confirm against organizational policy). — Expected result: a complete list of affected DCs/directions (may be empty). — Capture: annotate the saved output file with which rows are findings. — Stop/continue: check every failure's error code/text against the triage table in Section 5.3 to decide escalate-now vs. log-routine.
3. For any DC with a nonzero fail count, get verbose per-partner detail:
   ```
   repadmin /showrepl <DCName> > showrepl_<DCName>_<yyyy-MM-dd>.txt
   ```
   — Expected result: per-naming-context inbound/outbound neighbor detail, including last success time, last failure time, consecutive failure count, and the specific error for each replication partner link. — Capture: append or file alongside the summary output. — Stop/continue: continue.
4. File all output files (from either path) in the cycle's evidence location (Section 6). — Expected result: a complete file set covering this cycle's findings. — Capture: the evidence bundle. — Stop/continue: this cycle's data collection is complete.

### 5.3 Common failure signatures (triage reference, not exhaustive)

| Repadmin error code / text | Typical meaning | Immediate action |
|---|---|---|
| `1722` — The RPC server is unavailable | Network path, firewall, or the destination DC's RPC service is blocking/down between the two DCs | **Escalate immediately** per Section 6; replication between this pair of DCs is not occurring at all |
| `1753` — There are no more endpoints available from the endpoint mapper | RPC dynamic-port range is blocked (commonly a firewall/network-path issue between sites) | **Escalate immediately** |
| `8524` — The DSA operation is unable to proceed because of a DNS lookup failure | The source or destination DC cannot resolve its replication partner's name — usually a DNS health issue | **Escalate immediately**; also consider running [MRC-OPS-003](MRC-OPS-003.md) (DNS zone health review) out of cycle |
| `1256` / `1256` "The remote system is not available" | Destination DC is unreachable (offline, network segmented, or powered down) | **Escalate immediately**; confirm whether the DC is a planned outage before treating as an incident |
| `-2146893022` (Kerberos: target principal name is incorrect) or other Kerberos-auth failures | Usually a time-skew issue between DCs, or a broken secure channel/computer-account password mismatch | **Escalate immediately**; check time sync (`w32tm /query /status`) as a first troubleshooting step |
| `8606` — Insufficient attributes were given to create an object / lingering object errors | A lingering object or USN rollback condition — can indicate a DC was restored from an old backup/snapshot outside supported tombstone lifetime | **Escalate immediately**; do not attempt `/removelingeringobjects` without following the organization's own remediation procedure — this script/card is detection-only |
| Zero failures, but largest delta exceeds the `-MaxDeltaHours` threshold (default 24h) | Replication is succeeding but infrequent — could be an intentional low-bandwidth site schedule, or a link that is technically up but rarely triggered | Log as a routine finding; confirm against the site link's configured replication schedule before treating as abnormal |

This table reflects general `repadmin` error semantics for the assumed Windows Server/AD baseline and is not exhaustive. For an error not listed here, use the plain-language message repadmin itself prints, together with organizational AD-support experience, to judge urgency.
