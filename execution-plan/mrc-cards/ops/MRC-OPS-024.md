## 4. Safety / Handling Precautions

This is a read-only verification task. The companion script (Section 5.1) never triggers a scan, launches a plugin update, or modifies scanner configuration — it only calls `GET` REST endpoints using API key authentication. Store the Nessus API access/secret key pair as securely as any other privileged credential (this is a full-access key pair by default unless scoped to a restricted account) — never hardcode it in the script invocation history or a shared script copy; pass `-SecretKey` as a `SecureString` at run time, per the script's `.PARAMETER` documentation.

## 5. Procedure

This card assumes network access to the target Nessus instance's REST API port (default 8834) and a valid Nessus API access/secret key pair (generated under the scanner's My Account > API Keys, per [Tenable's authorization documentation](https://developer.tenable.com/docs/authorization)) for an account with at least read access. No Nessus web console session is required for either path below.

### 5.1 Automated path (recommended)

1. On a workstation or server with PowerShell and network access to the Nessus REST API port, obtain [`execution-plan/mrc-cards/scripts/MRC-OPS-024.ps1`](../scripts/MRC-OPS-024.ps1) from this repository.
2. Run:
   ```powershell
   .\MRC-OPS-024.ps1 -NessusHost nessus01.example.mil -AccessKey $ak -SecretKey (Read-Host -AsSecureString)
   ```
   — Expected result: the script calls `GET /server/status` (flagging Fail if the engine does not report a ready state) and `GET /server/properties` (flagging Warning if the loaded plugin feed's date-coded identifier, e.g. `202607071632`, is older than `-MaxFeedAgeDays`, default 7). **It never triggers a scan or plugin update.** — Capture: the script writes a timestamped report to `.\reports\MRC-OPS-024_<yyyyMMdd-HHmmss>.txt` by default; use `-OutputPath` to direct it elsewhere. — Stop/continue: if the script cannot reach the REST API (commonly a firewall/port-8834 issue or an expired/incorrect API key), fall back to the manual path in Section 5.2 for this cycle and log the tooling gap as a routine finding.
3. Read the script's console summary line and check `$LASTEXITCODE` (`0` = scanner is ready and the plugin feed is within the age threshold. `1` = the scanner is not ready, the feed is stale, or the API could not be queried). — Capture: console output. — Stop/continue: if exit code is `1`, proceed to step 4.
4. Open the report file's `SUMMARY` table and locate every row with `Result = Fail` or `Warning`. — Expected result: either a clean cycle (file the report and close) or an identified engine/feed issue needing follow-up. — Capture: the full report filed as this cycle's evidence. — Stop/continue: for any Fail/Warning, proceed to Section 5.3 for triage.

### 5.2 Manual path (fallback / spot-check verification)

1. Check scanner engine status via a browser or `curl`/`Invoke-RestMethod` against the REST API, authenticating with the `X-ApiKeys` header per [Tenable's documentation](https://developer.tenable.com/docs/authorization):
   ```
   GET https://nessus01.example.mil:8834/server/status
   Header: X-ApiKeys: accessKey=<access-key>;secretKey=<secret-key>
   ```
   — Expected result: the response's `status` field is `ready`. — Capture: the JSON response, or a screenshot of the Nessus web console's status indicator if checking there instead. — Stop/continue: any other status (e.g. `initializing`, `corrupt`) is a finding; note how long the scanner has been in that state.
2. Check the loaded plugin feed's currency:
   ```
   GET https://nessus01.example.mil:8834/server/properties
   Header: X-ApiKeys: accessKey=<access-key>;secretKey=<secret-key>
   ```
   — Expected result: the returned plugin feed identifier (date-coded, e.g. `202607071632` = 2026-07-07 16:32 UTC) is recent — normally within the last day or two, since Tenable typically ships new feeds daily. — Capture: the feed identifier value and the date it was checked. — Stop/continue: a feed older than roughly a week is a finding, since it indicates the scheduled plugin update is not running.

### 5.3 Common failure signatures (triage reference, not exhaustive)

| Finding | Typical meaning | Immediate action |
|---|---|---|
| `server/status` not `ready` (e.g. `initializing` persisting for a long time) | Nessus service may be mid-restart, corrupted, or resource-starved | Check the Nessus service/process status and system resource utilization on the scanner host directly before assuming a transient state |
| Plugin feed older than `-MaxFeedAgeDays` | The scheduled plugin/feed update task is failing or was disabled, or the scanner cannot reach Tenable's feed servers (offline/air-gapped environments require a manual feed import process) | Check the scanner's own plugin-update scheduling/logs for the specific failure reason; for air-gapped scanners, confirm the manual feed import (`nessuscli update`) cadence is being followed per this organization's process |
| API key authentication fails (401/403) | Key pair expired, was revoked, or lacks sufficient permission for these endpoints | Regenerate the API key pair under My Account > API Keys rather than attempting to reuse a stale key; confirm the associated account has at least a read-only role |

This table reflects general practice for the assumed Nessus baseline and is not exhaustive.
