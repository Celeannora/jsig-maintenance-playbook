## 4. Safety / Handling Precautions

This is a read-only verification task. The companion script (Section 5.1) never revokes, renews, requests, or removes any certificate, and never modifies AD CS configuration — it only pings the CA's RPC/DCOM interface and enumerates the `Cert:\LocalMachine\My` store. Certificate stores can contain private keys; run the script with an account that has read (not export) access to the target stores, and never copy/export a private key as part of this check. This is a spot-check of the certificate stores on the hosts you specify, not a substitute for a full enterprise-wide PKI/certificate-lifecycle-management inventory — see Section 5.3 for scope notes on what this check does and does not cover.

## 5. Procedure

This card assumes network access to the target CA server(s) (for the `certutil -ping` RPC/DCOM check) and, for any `-CertScanTarget` host other than the local computer, WinRM/PSRemoting access with permission to read the Local Machine Personal certificate store. No AD CS/PKI console (`certsrv.msc`) session is strictly required for either path below, though it is a convenient way to cross-check findings.

### 5.1 Automated path (recommended)

1. On a workstation or server with PowerShell and network access to the CA server(s), obtain [`execution-plan/mrc-cards/scripts/MRC-OPS-025.ps1`](../scripts/MRC-OPS-025.ps1) from this repository.
2. Run:
   ```powershell
   .\MRC-OPS-025.ps1 -CAServer ca01.example.mil -CertScanTarget ca01.example.mil,ex01.example.mil
   ```
   — Expected result: the script runs `certutil.exe -ping` against each `-CAServer` to confirm the CA's RPC/DCOM interface answers (Fail if it does not), then enumerates `Cert:\LocalMachine\My` on each `-CertScanTarget` (defaults to the local computer) and flags Warning for any certificate expiring within `-ExpiryWarningDays` (default 30). **It never revokes, renews, or removes any certificate.** — Capture: the script writes a timestamped report to `.\reports\MRC-OPS-025_<yyyyMMdd-HHmmss>.txt` by default; use `-OutputPath` to direct it elsewhere. — Stop/continue: if `certutil -ping` cannot reach a CA (commonly an RPC/firewall issue), fall back to the manual path in Section 5.2 for that CA and log the tooling gap as a routine finding. If a `-CertScanTarget` cannot be reached via WinRM, note it in the report and check that host manually.
3. Read the script's console summary line and check `$LASTEXITCODE` (`0` = every CA responded and no certificate is within the expiry-warning window. `1` = a CA did not respond, a certificate is expiring/expired, or a target could not be queried). — Capture: console output. — Stop/continue: if exit code is `1`, proceed to step 4.
4. Open the report file's `SUMMARY` table and locate every row with `Result = Fail` or `Warning`. — Expected result: either a clean cycle (file the report and close) or an identified CA-connectivity or certificate-expiration issue needing follow-up. — Capture: the full report filed as this cycle's evidence. — Stop/continue: for any Fail/Warning, proceed to Section 5.3 for triage.

### 5.2 Manual path (fallback / spot-check verification)

1. From an elevated command prompt on a workstation or server with network access to the CA, ping the CA's RPC/DCOM interface:
   ```
   certutil -ping -config "ca01.example.mil\CA-Name"
   ```
   — Expected result: `certutil` reports the ping succeeded. — Capture: the command's console output. — Stop/continue: a failure here means the CA's Certificate Services role service is unreachable or stopped; escalate per Section 6 before assuming a network-only issue.
2. As a cross-check, open the Certification Authority console (`certsrv.msc`) on or against the CA and confirm the CA service shows as running (green icon, no error banner). — Capture: a screenshot or note of the console state. — Stop/continue: this step is optional if step 1 already succeeded, but useful corroboration if step 1 failed.
3. On each host to be checked for expiring certificates, open the Certificates MMC snap-in (`certmgr.msc` for the current user, or `certlm.msc` for the Local Machine store) and navigate to Personal > Certificates. — Expected result: no certificate's "Expiration Date" column falls within the next 30 days (or this organization's chosen warning window). — Capture: a list or screenshot of any near-expiry certificate, including its subject/friendly name and expiration date. — Stop/continue: any certificate within the warning window, or already expired, is a finding.

### 5.3 Scope notes and common failure signatures (triage reference, not exhaustive)

**Scope note:** this check enumerates the `Cert:\LocalMachine\My` store only on the specific hosts listed in `-CertScanTarget`. It is not a substitute for an enterprise-wide certificate inventory across every server, workstation, and network device issued a certificate by this CA — if this organization has a dedicated PKI/certificate-lifecycle-management tool, that tool's inventory remains the authoritative enterprise-wide view, and this task should be understood as a targeted spot-check of the specific hosts named in the script invocation (typically the CA itself and other especially critical servers).

| Finding | Typical meaning | Immediate action |
|---|---|---|
| `certutil -ping` fails against a CA | CA service stopped, RPC/DCOM port blocked by firewall, or DNS resolution failure to the CA name | Check the Certificate Services role service state directly on the CA host before assuming a network-only issue |
| Certificate within `-ExpiryWarningDays` of expiration | Certificate approaching its natural expiration and has not yet been renewed/re-enrolled | Initiate the standard certificate renewal/re-enrollment process for that certificate's owning service well before expiration, since an expired certificate used by a running service (e.g. IIS, LDAPS, RDP) can cause an outage |
| Certificate already expired | Renewal process was missed | Escalate immediately if the certificate is bound to a production service — an expired service certificate typically causes an active outage or client-trust failure, not just a future risk |

This table reflects general practice for the assumed AD CS baseline and is not exhaustive.
