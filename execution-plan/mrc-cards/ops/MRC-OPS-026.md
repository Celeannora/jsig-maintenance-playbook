## 4. Safety / Handling Precautions

This is a read-only verification task. The companion script (Section 5.1) never enables, disables, runs, or modifies any scheduled task — it only calls `Get-ScheduledTask` and `Get-ScheduledTaskInfo`. Tasks under `\Microsoft\...` (built-in OS maintenance tasks) are excluded by default, since this task is about organization-defined/application scheduled jobs rather than the operating system's own maintenance tasks; only include them (`-IncludeMicrosoftTasks`, i.e. `-ExcludeMicrosoftTasks:$false`) if this organization has a documented, site-specific requirement to review OS-maintenance task results as part of this cycle.

## 5. Procedure

This card assumes the ScheduledTasks PowerShell module (built into all supported Windows Server versions) is available on the host running the check, and, for any `-ComputerName` other than the local computer, WinRM/PSRemoting access to the remote host. No Task Scheduler GUI (`taskschd.msc`) session is strictly required for either path below, though it is a convenient way to cross-check findings.

### 5.1 Automated path (recommended)

1. On a workstation or server with PowerShell and (for remote targets) WinRM access, obtain [`execution-plan/mrc-cards/scripts/MRC-OPS-026.ps1`](../scripts/MRC-OPS-026.ps1) from this repository.
2. Run:
   ```powershell
   .\MRC-OPS-026.ps1 -ComputerName fs01.example.mil
   ```
   — Expected result: the script enumerates enabled scheduled tasks on each `-ComputerName` (excluding `\Microsoft\...` tasks by default) via `Get-ScheduledTask`, reads each task's `LastTaskResult` via `Get-ScheduledTaskInfo`, and flags any task whose `LastTaskResult` is non-zero (any value other than `0x0`/success) or that has never run. Use `-TaskPath` to scope the check to a specific folder (e.g. `'\MyOrg\*'`) if this organization keeps its scheduled jobs under a dedicated path. **It never enables, disables, runs, or modifies any task.** — Capture: the script writes a timestamped report to `.\reports\MRC-OPS-026_<yyyyMMdd-HHmmss>.txt` by default; use `-OutputPath` to direct it elsewhere. — Stop/continue: if a `-ComputerName` cannot be reached via WinRM, fall back to the manual path in Section 5.2 for that host and log the tooling gap as a routine finding.
3. Read the script's console summary line and check `$LASTEXITCODE` (`0` = every checked enabled task's last run result was 0/success. `1` = any task's last run result was non-zero, a task has never run, or a target could not be queried). — Capture: console output. — Stop/continue: if exit code is `1`, proceed to step 4.
4. Open the report file's `SUMMARY` table and locate every row with `Result = Fail` or `Warning`. — Expected result: either a clean cycle (file the report and close) or an identified failed/never-run task needing follow-up. — Capture: the full report filed as this cycle's evidence. — Stop/continue: for any Fail/Warning, proceed to Section 5.3 for triage.

### 5.2 Manual path (fallback / spot-check verification)

1. On the target host, run the equivalent PowerShell commands directly:
   ```powershell
   Get-ScheduledTask | Where-Object { $_.State -ne 'Disabled' -and $_.TaskPath -notlike '\Microsoft\*' } |
       Get-ScheduledTaskInfo | Select-Object TaskName, TaskPath, LastRunTime, LastTaskResult, NextRunTime
   ```
   — Expected result: every listed task's `LastTaskResult` is `0`. — Capture: the command output (screenshot or copy/paste into the evidence file). — Stop/continue: any non-zero `LastTaskResult`, or a `LastRunTime` that is unexpectedly blank/never (task has never run), is a finding.
2. As a cross-check, open Task Scheduler (`taskschd.msc`), navigate to the relevant task folder, and confirm the "Last Run Result" column reads "The operation completed successfully. (0x0)" for each task of interest. — Capture: a screenshot if a discrepancy from step 1 needs documenting. — Stop/continue: this step is optional corroboration if step 1 already produced a clear result.

### 5.3 Common failure signatures (triage reference, not exhaustive)

| `LastTaskResult` (hex) | Typical meaning | Immediate action |
|---|---|---|
| `0x1` (`0x00000001`) | Incorrect function call, or the task's action/executable itself returned a generic failure | Check the task's configured action (path, arguments, working directory) and the target application's own logs |
| `0x41303` (`SCHED_S_TASK_RUNNING`) | Task is still running at the time of the check — not necessarily a failure | Re-check after the task's expected run duration; only escalate if it remains "running" well past its normal duration (possible hang) |
| `0x8004131F` (`SCHED_E_TASK_NOT_READY`) / task never run | Task is disabled, missing required triggers, or was never manually run once after creation | Confirm the task's trigger configuration and enabled state in Task Scheduler |
| Access-denied-style result | The task's configured "Run as" account lacks permission for its action, or its stored credential has expired/changed (e.g. a service account password rotation per [MRC-OPS-027](MRC-OPS-027.md)) | Verify the task's "Run as" account credential is current and has the necessary rights for its action |

This table reflects general Windows Task Scheduler behavior and is not exhaustive; consult the specific failing application's own documentation/logs for application-level result codes.
