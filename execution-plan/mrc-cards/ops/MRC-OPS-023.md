## 4. Safety / Handling Precautions

This is a read-only verification task. The companion script (Section 5.1) never restarts a Splunk service, never disables a forwarder, and never modifies index or license configuration — it only calls `GET` REST endpoints. Use a dedicated, least-privilege Splunk account for this automation rather than the full `admin` role where the organization's Splunk role-based access control permits a scoped role with `list_health`/`list_settings`-equivalent capabilities. Per [Splunk's own documentation](https://community.splunk.com/t5/Deployment-Architecture/List-Universal-fowarders-disconnected-from-the-Deployment-Server/m-p/759746), the `deployment/server/clients` endpoint's `lastPhoneHomeTime` values are only authoritative when queried directly on the Deployment Server instance — running this check against a non-DS Splunk instance will not reflect true forwarder connectivity, and the script's `-SkipForwarderCheck` switch exists specifically for that scenario.

## 5. Procedure

This card assumes network access to the target Splunk instance's management (REST API) port (default 8089, HTTPS) and a Splunk account credential with read access to the `server/health`, `deployment/server/clients`, `data/indexes`, and `licenser/usage` endpoints. No Splunk Web / browser console session is required for either path below.

### 5.1 Automated path (recommended)

1. On a workstation or server with PowerShell and network access to the Splunk management port, obtain [`execution-plan/mrc-cards/scripts/MRC-OPS-023.ps1`](../scripts/MRC-OPS-023.ps1) from this repository.
2. Run:
   ```powershell
   .\MRC-OPS-023.ps1 -SplunkHost splunk-ds01.example.mil -Credential (Get-Credential)
   ```
   — Expected result: the script calls the four REST endpoints listed in Section 1 and flags Warning (not Fail — see Section 4's rationale) if splunkd health is not `green`, any deployment client's phone-home is older than `-ForwarderStaleMinutes` (default 15), any index exceeds `-IndexCapacityWarnPercent` (default 90), or license usage exceeds `-LicenseWarnPercent` (default 85). **It never restarts a service or modifies configuration.** — Capture: the script writes a timestamped report to `.\reports\MRC-OPS-023_<yyyyMMdd-HHmmss>.txt` by default; use `-OutputPath` to direct it elsewhere. — Stop/continue: if the script cannot reach the REST API (commonly a firewall/port-8089 issue or an expired/incorrect credential), fall back to the manual path in Section 5.2 for this cycle and log the tooling gap as a routine finding. If this Splunk instance is not the Deployment Server, re-run with `-SkipForwarderCheck` and check forwarder connectivity separately against the actual DS.
3. Read the script's console summary line and check `$LASTEXITCODE` (`0` = every check passed. `1` = any check returned Warning or could not be queried). — Capture: console output. — Stop/continue: if exit code is `1`, proceed to step 4.
4. Open the report file's `SUMMARY` table and locate every row with `Result = Warning` or `Fail`. — Expected result: either a clean cycle (file the report and close) or an identified health/capacity/license issue needing follow-up. — Capture: the full report filed as this cycle's evidence. — Stop/continue: for any Warning/Fail, proceed to Section 5.3 for triage.

### 5.2 Manual path (fallback / spot-check verification)

1. Check overall splunkd health via a browser or `curl`/`Invoke-RestMethod` against the REST API:
   ```
   GET https://splunk-ds01.example.mil:8089/services/server/health/splunkd?output_mode=json
   ```
   — Expected result: the returned health feature tree reports `green` at the top level. — Capture: the JSON response or a screenshot of Splunk Web's Monitoring Console health report. — Stop/continue: any color other than `green` is a finding; note which sub-feature (e.g. indexer, search scheduler) is reporting the issue.
2. Check forwarder phone-home recency (run this against the Deployment Server specifically):
   ```
   GET https://<deployment-server>:8089/services/deployment/server/clients?output_mode=json
   ```
   — Expected result: every expected forwarder's `lastPhoneHomeTime` is recent (within a few phone-home intervals of now). — Capture: the returned client list. — Stop/continue: a forwarder missing or with a stale `lastPhoneHomeTime` is a finding.
3. Check index capacity:
   ```
   GET https://splunk-ds01.example.mil:8089/services/data/indexes?output_mode=json
   ```
   — Expected result: `currentDBSizeMB` well under `maxTotalDataSizeMB` for every enabled index. — Capture: the per-index size figures. — Stop/continue: any index above roughly 90% of its max is a finding.
4. Check license usage:
   ```
   GET https://splunk-ds01.example.mil:8089/services/licenser/usage?output_mode=json
   ```
   — Expected result: `peers_usage_bytes` well under the license `quota`. — Capture: the usage figures. — Stop/continue: usage above roughly 85% of quota is a finding, since exceeding the license triggers Splunk's license-violation warning banners and can suppress search results.

### 5.3 Common failure signatures (triage reference, not exhaustive)

| Finding | Typical meaning | Immediate action |
|---|---|---|
| splunkd health not `green` | A specific health feature (indexer clustering, search scheduler, resource usage) has an active alert | Drill into the Monitoring Console's health report to identify the specific red/yellow feature before escalating |
| Forwarder `lastPhoneHomeTime` stale | Forwarder is offline, has lost network connectivity to the Deployment Server, or its `deploymentclient.conf` is misconfigured | Check the forwarder host directly (service running? network path to DS open on the configured port?) rather than assuming a DS-side issue |
| Index nearing `maxTotalDataSizeMB` | Retention/rolling policy may be misconfigured, or ingestion volume has grown beyond the index's sizing | Review `indexes.conf` retention settings for that index before assuming more disk is the only fix |
| License usage nearing quota | Ingestion volume has grown, or a rogue/misconfigured source is over-forwarding data | Review the license usage report by source type to identify the largest contributor before requesting a license increase |

This table reflects general practice for the assumed Splunk baseline and is not exhaustive.
