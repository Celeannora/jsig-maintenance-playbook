# MRC-OPS-030 — Windows Server / Exchange licensing and CAL compliance review

> **Guide status** (hand-authored, exact tool-specific steps) — upgraded from Stub per [`AGENTS.md`](../../../AGENTS.md) rule 8. See [`../README.md`](../README.md) for the full Stub/Guide tracking matrix. Assumed baseline environment: Active Directory / Windows Server, Exchange Server.

> **No companion automation script** (Script = N/A on the tracking matrix). This is fundamentally a **compliance/administrative review**, not a technical health check — it compares actual usage (active user/device counts, mailbox counts) against a contractual licensing entitlement record that lives outside any queryable server API (a Volume Licensing Service Center agreement, a reseller invoice, or a locally maintained license-tracking spreadsheet). PowerShell can help gather the *usage* side of this comparison (Section 5.3 identifies the relevant cmdlets), but the entitlement side has no technical source of truth to query against, so a fully automated pass/fail script would either hard-code entitlement numbers that go stale the moment a license is purchased or reconciled, or silently report a false compliance status. This was flagged to the user during authoring and confirmed as Guide-only rather than assumed.

## 4. Safety / Handling Precautions

This is a read-only reconciliation task performed by comparing usage counts against the organization's existing license-entitlement records. Do not use a shortfall finding as justification to independently purchase additional licenses or CALs during this review — license procurement is a separate, deliberate action that goes through the organization's normal contracting/purchasing process, not something initiated ad hoc by the person performing this check. Likewise, do not remove or disable user/device accounts as a way to "fix" an over-count finding without going through normal account-lifecycle change management — an account may be counted against the license pool for a legitimate reason (e.g. a device CAL for a shared kiosk) that isn't obvious from the count alone.

## 5. Procedure

This card assumes access to Active Directory (read access sufficient), the Exchange Admin Center or Exchange Management Shell (read access sufficient), and this organization's license-entitlement record (Volume Licensing Service Center portal access, or the locally maintained tracking document/spreadsheet, whichever this organization uses as its system of record).

### 5.1 Determine the licensing model in use (do this before counting anything)

1. Confirm whether this organization licenses Windows Server access via **User CALs** or **Device CALs** (an organization typically standardizes on one model, though mixed environments exist) — check the Volume Licensing Service Center agreement or the local license-tracking record. — Expected result: a clear answer to "are we counting unique users, or unique devices, against our CAL pool?" — Capture: note which model applies before proceeding, since this determines which count in Section 5.2 is the relevant one. — Stop/continue: if this is not immediately clear from the records available, treat that ambiguity itself as a finding — the organization needs a documented answer to reconcile against, and consult the ISSM/procurement contact who manages the licensing agreement.
2. Confirm the Exchange Server edition(s) deployed (Standard: 1–5 mailbox databases; Enterprise: 1–100 mailbox databases) and which CAL tier(s) are entitled (Standard CAL only, or Standard + Enterprise CAL) per the [Exchange Server licensing overview](https://www.microsoft.com/en-us/microsoft-365/exchange/microsoft-exchange-server-licensing-licensing-overview). — Expected result: a clear picture of which Exchange CAL feature tier this organization's users are entitled to use. — Capture: note the deployed edition and entitled CAL tier(s). — Stop/continue: if users are actively using Enterprise CAL-tier features (e.g. archiving, advanced information-protection/compliance features) without an Enterprise CAL entitlement on record, that is itself a finding regardless of the raw count reconciliation in Section 5.2.

### 5.2 Reconcile usage against entitlement

1. Determine the active count on the usage side matching the model identified in step 5.1.1:
   - If **User CAL** model: count unique enabled user accounts requiring access to the licensed server software (Windows Server file/print/etc. and Exchange mailbox access). In Active Directory Users and Computers, or via PowerShell (`Get-ADUser -Filter {Enabled -eq $true}` scoped to the relevant OU(s)), get the enabled-user count. Cross-reference against Exchange mailbox-enabled users (Exchange Admin Center → **Recipients → Mailboxes**, or `Get-Mailbox` in Exchange Management Shell) since not every enabled AD user necessarily has a mailbox, and not every mailbox necessarily corresponds to an active human user (shared/resource mailboxes typically do not require a separate CAL — confirm this organization's specific licensing agreement terms rather than assuming).
   - If **Device CAL** model: count unique active computer/device accounts accessing the licensed server software. In Active Directory Users and Computers, or via PowerShell (`Get-ADComputer -Filter {Enabled -eq $true}`), get the enabled-computer count, scoped to devices that actually access the relevant server software (exclude servers, and any device population this organization's agreement explicitly excludes).
   — Expected result: a current usage count for this cycle. — Capture: the count and the date/method used to derive it. — Stop/continue: proceed to step 2 to compare against entitlement.
2. Compare the usage count from step 1 against the licensed entitlement quantity recorded in the Volume Licensing Service Center or this organization's local license-tracking record. — Expected result: usage count at or below the entitled quantity. — Capture: both numbers side by side in this cycle's findings. — Stop/continue: usage exceeding entitlement is this task's core finding — proceed to Section 5.3 for triage; usage at or below entitlement with reasonable headroom closes this cycle cleanly.
3. Separately confirm the Exchange CAL tier reconciliation from step 5.1.2 — count users actually assigned or using Enterprise-tier features versus the number of Enterprise CAL entitlements on record, using the same source (Exchange Admin Center recipient/feature reporting, or the vendor's compliance-reporting tooling if in use). — Expected result: feature usage at or below entitled Enterprise CAL count. — Capture: both numbers side by side. — Stop/continue: a shortfall here is a separate, distinct finding from the base CAL count in step 2 even if the base count itself is compliant.

### 5.2b Common failure signatures (triage reference, not exhaustive)

| Finding | Typical meaning | Immediate action |
|---|---|---|
| Usage count exceeds base CAL entitlement | Organic user/device growth outpacing the last licensing true-up, or stale/orphaned accounts inflating the count | Before assuming additional licenses must be purchased, check for disabled-but-not-removed accounts or duplicate device records that may be inflating the count artificially |
| Enterprise-tier Exchange features in use without matching Enterprise CAL entitlement | Feature was enabled (e.g. by a policy change or user self-service) without a corresponding licensing review at the time | Escalate to whoever manages the licensing agreement — this is a compliance gap that needs either a licensing true-up or disabling the feature for unentitled users |
| Licensing model (User CAL vs. Device CAL) not clearly documented anywhere accessible to this review | Original licensing decision was made once, informally, and never re-documented | Treat as a finding in its own right; work with the ISSM/procurement contact to establish (or re-confirm) a documented licensing model before the next quarterly cycle |
| Usage count well under entitlement, with a large and growing gap over several quarters | Organization may be over-licensed relative to actual need | Not a compliance risk, but worth noting for the next licensing renewal/true-up conversation to potentially reduce cost — file as an informational note, not a compliance finding |

This table reflects general licensing-review practice and is not exhaustive; always defer to the specific terms of this organization's actual Volume Licensing Agreement, which can include organization-specific exceptions not reflected here.

### 5.3 Future automation note (usage-side data gathering only — not a full automated pass/fail)

While a fully automated compliance script is not appropriate for this task (see the callout at the top of this card), the *usage-count* side of Section 5.2 step 1 can be scripted with the built-in `ActiveDirectory` module (`Get-ADUser -Filter {Enabled -eq $true}`, `Get-ADComputer -Filter {Enabled -eq $true}`) and the Exchange Management Shell (`Get-Mailbox`, filtered by mailbox type to exclude shared/resource mailboxes per this organization's agreement terms). Such a script could produce the usage-side counts as a starting artifact for this review, but the entitlement-side comparison and the resulting compliance determination should remain a manual step performed against the organization's actual licensing records, not something the script itself asserts pass/fail on.
