## 4. Safety / Handling Precautions

This is a read-only verification task. The companion script (Section 5.1) never resets, unlocks, or modifies any account password or attribute — it only calls `Get-ADUser` with a read-only property projection. Confirm `-ServiceAccountOU` and `-NeverExpiresMaxAgeDays` are edited to match this organization's actual OU structure and documented service-account manual-rotation policy before relying on this script's output; the defaults shipped in the script (14-day expiry warning, 365-day never-expires rotation ceiling) are starting points, not this organization's authoritative policy values.

## 5. Procedure

This card assumes the ActiveDirectory PowerShell module (RSAT-AD-PowerShell) is installed on the host running the check, and read access to the service-account OU. No Active Directory Users and Computers (`dsa.msc`) console session is strictly required for either path below, though it is a convenient way to cross-check findings.

### 5.1 Automated path (recommended)

1. On a workstation or server with PowerShell, the ActiveDirectory module, and read access to Active Directory, obtain [`execution-plan/mrc-cards/scripts/MRC-OPS-027.ps1`](../scripts/MRC-OPS-027.ps1) from this repository.
2. Run:
   ```powershell
   .\MRC-OPS-027.ps1 -ServiceAccountOU 'OU=Service Accounts,DC=example,DC=mil'
   ```
   — Expected result: the script queries every account in `-ServiceAccountOU` via `Get-ADUser`. For accounts with `PasswordNeverExpires = $false`, it reads `msDS-UserPasswordExpiryTimeComputed` (the AD-computed expiration timestamp, which already accounts for any fine-grained password policy) and flags Warning if it falls within `-ExpiryWarningDays` (default 14) or Fail if already expired. For accounts with `PasswordNeverExpires = $true`, it instead compares `PasswordLastSet` age against `-NeverExpiresMaxAgeDays` (default 365) and flags Warning if the password is overdue for its manual rotation, since AD will never force-expire such an account on its own. Disabled accounts are excluded. **It never resets or modifies any password or account attribute.** — Capture: the script writes a timestamped report to `.\reports\MRC-OPS-027_<yyyyMMdd-HHmmss>.txt` by default; use `-OutputPath` to direct it elsewhere. — Stop/continue: if the OU cannot be queried (commonly a permissions or DN-typo issue), fall back to the manual path in Section 5.2 for this cycle and log the tooling gap as a routine finding.
3. Read the script's console summary line and check `$LASTEXITCODE` (`0` = no account is within the expiry/rotation warning window. `1` = any account is expiring, expired, or overdue for rotation, or the OU could not be queried). — Capture: console output. — Stop/continue: if exit code is `1`, proceed to step 4.
4. Open the report file's `SUMMARY` table and locate every row with `Result = Fail` or `Warning`. — Expected result: either a clean cycle (file the report and close) or an identified account needing a password reset or manual rotation. — Capture: the full report filed as this cycle's evidence. — Stop/continue: for any Fail/Warning, proceed to Section 5.3 for triage, then coordinate the actual password change with the application/service owner (this task tracks and reports the finding; it does not itself change any password).

### 5.2 Manual path (fallback / spot-check verification)

1. On a domain-joined host with the ActiveDirectory module, run the equivalent PowerShell command directly:
   ```powershell
   Get-ADUser -Filter * -SearchBase 'OU=Service Accounts,DC=example,DC=mil' -Properties PasswordNeverExpires, PasswordLastSet, 'msDS-UserPasswordExpiryTimeComputed', Enabled |
       Where-Object { $_.Enabled } |
       Select-Object Name, PasswordNeverExpires, PasswordLastSet,
           @{N='PasswordExpires';E={ if (-not $_.PasswordNeverExpires) { [datetime]::FromFileTime($_.'msDS-UserPasswordExpiryTimeComputed') } }}
   ```
   — Expected result: for `PasswordNeverExpires = $false` accounts, `PasswordExpires` is well beyond the current date plus the warning window; for `PasswordNeverExpires = $true` accounts, `PasswordLastSet` is well within this organization's manual-rotation ceiling. — Capture: the command output (screenshot or copy/paste into the evidence file). — Stop/continue: any account failing either check is a finding.
2. As a cross-check, open Active Directory Users and Computers (`dsa.msc`), navigate to the service-account OU, and confirm the "Password Never Expires" flag on the Account tab matches what the query reported for any account under review. — Capture: a screenshot if a discrepancy needs documenting. — Stop/continue: this step is optional corroboration if step 1 already produced a clear result.

### 5.3 Common failure signatures (triage reference, not exhaustive)

| Finding | Typical meaning | Immediate action |
|---|---|---|
| Account with `PasswordNeverExpires=$false` inside `-ExpiryWarningDays` | Standard AD password-policy-driven expiration approaching | Coordinate a password change with the application/service owner well before expiration to avoid a service outage from expired credentials |
| Account with `PasswordNeverExpires=$false` already expired | Password change was missed and the account is now locked out of authentication | Escalate immediately — this typically causes an active service outage, not just a future risk |
| Account with `PasswordNeverExpires=$true` over `-NeverExpiresMaxAgeDays` | Manual rotation policy for this account has lapsed silently, since AD itself will never force this password to expire | Schedule a coordinated manual password rotation with the application/service owner, updating the credential everywhere it is configured (this is typically the highest-effort finding type from this check, since a never-expiring service account credential is often embedded in multiple configuration files/scheduled tasks) |
| `msDS-UserPasswordExpiryTimeComputed` missing/null for a `PasswordNeverExpires=$false` account | Uncommon; may indicate a fine-grained password policy or account state edge case | Cross-check manually via `net user /domain` or the account's Account tab in `dsa.msc` before treating as a scripting error |

This table reflects general Active Directory password-policy behavior and is not exhaustive.
