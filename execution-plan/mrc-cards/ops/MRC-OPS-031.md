## 4. Safety / Handling Precautions

This is a read-only verification task. The companion script (Section 5.1) never creates, removes, or modifies any share, never changes NTFS/share permissions, and never starts, stops, or restarts any service — it only calls `Get-SmbShare`, `Test-Path`, `Get-Volume`, and (optionally) `Get-Service`. Remote targets are queried via `Invoke-Command`, which requires WinRM/PSRemoting access already permitted to the account running the script; do not open new remoting access solely to run this check without going through normal access-request procedures. Do not use a finding from this task as justification to delete files, resize volumes, or remove shares during the review — capacity and share-health remediation are separate, deliberate change-management actions with their own testing/notification expectations.

## 5. Procedure

This card assumes network access to each target file/print server and, for remote targets, an account with WinRM/PSRemoting access already granted (the script uses `Invoke-Command` for any `-ComputerName` other than the local host).

### 5.1 Automated path (recommended)

1. On a Windows PowerShell host with network/WinRM access to the target file/print server(s), obtain [`execution-plan/mrc-cards/scripts/MRC-OPS-031.ps1`](../scripts/MRC-OPS-031.ps1) from this repository.
2. Run:
   ```powershell
   .\MRC-OPS-031.ps1 -ComputerName fs01.example.mil -CheckPrintSpooler
   ```
   — Expected result: the script enumerates non-administrative SMB shares via `Get-SmbShare`, confirms each share's `ShareState` is `Online` and its underlying path is reachable (`Test-Path`), checks free space on each share-hosting volume via `Get-Volume` against `-DiskWarnPercentFree` (default 10), and — if `-CheckPrintSpooler` is passed — checks the Print Spooler service state via `Get-Service -Name Spooler`. **It never creates, removes, or modifies any share, permission, or service state.** — Capture: the script writes a timestamped report to `.\reports\MRC-OPS-031_<yyyyMMdd-HHmmss>.txt` by default; use `-OutputPath` to direct it elsewhere. — Stop/continue: if the script cannot reach a remote target (commonly a WinRM/firewall issue or an expired credential), fall back to the manual path in Section 5.2 for this cycle and log the tooling gap as a routine finding. Only pass `-CheckPrintSpooler` for hosts that actually serve the Print Server role — omit it for file-only servers.
3. Read the script's console summary line and check `$LASTEXITCODE` (`0` = every check passed. `1` = any check returned Warning or could not be queried). — Capture: console output. — Stop/continue: if exit code is `1`, proceed to step 4.
4. Open the report file's `SUMMARY` table and locate every row with `Result = Warning` or `Fail`. — Expected result: either a clean cycle (file the report and close) or an identified share-availability/capacity/spooler issue needing follow-up. — Capture: the full report filed as this cycle's evidence. — Stop/continue: for any Warning/Fail, proceed to Section 5.3 for triage.

### 5.2 Manual path (fallback / spot-check verification)

1. On the target server, open **Server Manager → File and Storage Services → Shares**, or run `Get-SmbShare` directly in a PowerShell session on the host. — Expected result: every expected share is listed with no unexpected state, and each share's path resolves (spot-check by browsing `\\<server>\<share>` from another machine or via `Test-Path` on the share's local path). — Capture: a screenshot of the Shares list, or the `Get-SmbShare` output. — Stop/continue: a missing expected share, or a share whose underlying path is not reachable, is a finding.
2. For each drive letter hosting a share, check free space via **Server Manager → File and Storage Services → Volumes**, or `Get-Volume` in PowerShell. — Expected result: free space comfortably above the organization's warning threshold (this card's default is 10% free). — Capture: the free-space percentage for each relevant volume. — Stop/continue: any volume at or below the threshold is a finding.
3. If this host also serves the Print Server role, check the Print Spooler service via **Services** (`services.msc`) or `Get-Service -Name Spooler`. — Expected result: status **Running**. — Capture: the service status. — Stop/continue: a stopped or otherwise non-Running Spooler service on a print server is a finding — print jobs will queue but not process.

### 5.3 Common failure signatures (triage reference, not exhaustive)

| Finding | Typical meaning | Immediate action |
|---|---|---|
| Share `ShareState` not `Online`, or underlying path unreachable | The share was removed/renamed without updating downstream references, the hosting volume was dismounted, or a permissions/path issue is blocking access | Confirm with the share owner whether this was an intentional change before treating it purely as an outage |
| Share-hosting volume free space at or below threshold | Data growth outpacing retention/cleanup policy, or an unexpected large write (e.g. runaway log, accidental bulk copy) | Identify the largest recent consumers before assuming more disk is the only fix; check for scheduled cleanup jobs that may have failed |
| Print Spooler service stopped | Spooler crashed (often due to a corrupted print job or driver issue) or was stopped manually/by policy | Restart the service through normal change-managed means if this is an expected print server, and check the spooler's queue/event log for the underlying cause before simply restarting repeatedly |
| Remote `Invoke-Command` fails against a target | WinRM not enabled/listening, firewall blocking 5985/5986, or the running account lacks remoting rights on that host | Verify WinRM service state and firewall rules on the target before assuming the share/disk data itself is unavailable |

This table reflects general practice for the assumed Windows Server File and Storage Services baseline and is not exhaustive.
