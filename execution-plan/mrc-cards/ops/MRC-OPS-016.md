## 4. Safety / Handling Precautions

This is a read-only reporting task. The companion script (Section 5.1) never requests, imports, binds, or removes a certificate — obtaining a renewed certificate, importing it, and re-running `Enable-ExchangeCertificate` to bind it to services is always a separate, deliberate, change-controlled action taken by a human. Binding a new certificate to services is itself a change that can cause a service interruption if done incorrectly (e.g., binding a certificate missing a required SAN entry, or removing a service binding from the old certificate before the new one is confirmed working) — always follow the organization's standard change-control process for the renewal/rebind itself, and never let certificate renewal happen for the first time under time pressure during an already-expired-certificate incident. Note also that a certificate bound to no services (`Services = None`) is not a continuity-of-service risk and should not be treated with the same urgency as a bound, expiring certificate.

## 5. Procedure

This card assumes access to an Exchange Management Shell session with read permissions to certificate information on each Exchange server.

### 5.1 Automated path (recommended)

1. On a workstation or server with Exchange Management Shell available, open that shell.
2. Obtain [`execution-plan/mrc-cards/scripts/MRC-OPS-016.ps1`](../scripts/MRC-OPS-016.ps1) from this repository.
3. Run:
   ```powershell
   .\MRC-OPS-016.ps1
   ```
   — Expected result: the script auto-discovers every Exchange server in the organization (falling back to the local host if that lookup fails) and reads every certificate's expiration date and bound services, flagging a certificate with a bound service as Fail if expiring within 14 days (default) or already expired, and Warning if expiring within 30 days (default). A certificate with no bound services is reported informationally and does not affect the script's overall pass/fail result. **It never modifies any certificate or its bindings.** — Capture: the script writes a timestamped report to `.\reports\MRC-OPS-016_<yyyyMMdd-HHmmss>.txt` by default; use `-OutputPath` to direct it elsewhere. — Stop/continue: if the script errors immediately (commonly because it was run outside Exchange Management Shell), fall back to the manual path in Section 5.2 for this cycle and log the tooling gap as a routine finding.
4. Read the script's console summary line and check `$LASTEXITCODE` (`0` = every bound certificate has more than the Warning-threshold days remaining; `1` = a bound certificate is expired or inside the Warning/Critical window, or a server could not be queried). — Expected result: exit code `0`. — Capture: console output. — Stop/continue: if exit code is `1`, proceed to step 5.
5. Open the report file's `SUMMARY` table and locate every row with `Result` containing `Fail` or `Warning`. — Expected result: either a clean cycle (file the report and close) or an identified list of expiring/expired certificates. — Capture: the full report filed as this cycle's evidence. — Stop/continue: for any certificate flagged Fail, immediately begin the renewal process described in Section 5.3 rather than waiting for the next monthly cycle, since a Fail means expiration is imminent or has already happened.

### 5.2 Manual path (fallback / spot-check verification)

1. On each Exchange server, in Exchange Management Shell, list certificates and their expiration:
   ```powershell
   Get-ExchangeCertificate -Server <ServerName> |
       Select-Object Thumbprint, Subject, Services, NotAfter, @{N='DaysRemaining';E={[math]::Floor(($_.NotAfter - (Get-Date)).TotalDays)}}
   ```
   — Expected result: expiration date and bound services for every certificate on that server. — Capture: the returned table. — Stop/continue: a certificate with `Services` other than `None` and `DaysRemaining` under 30 (or already negative) is a finding.
2. Cross-check the certificate's issuer and SAN entries before initiating renewal, to confirm the replacement request will match:
   ```powershell
   Get-ExchangeCertificate -Thumbprint <Thumbprint> | Select-Object Issuer, CertificateDomains
   ```
   — Expected result: full issuer and Subject Alternative Name list for the expiring certificate, needed to build an equivalent (or improved) renewal request. — Capture: the returned detail. — Stop/continue: continue to the organization's certificate-request process (internal CA or external vendor, per that certificate's issuer) — this step is informational only and does not itself renew anything.

### 5.3 Common failure signatures (triage reference, not exhaustive)

| Finding | Typical meaning | Immediate action |
|---|---|---|
| Bound certificate expiring within 30 days (Warning) | Renewal has not yet been initiated for a certificate that will soon need replacing | Log as a finding; initiate the renewal request now so there is buffer time before the Critical window |
| Bound certificate expiring within 14 days or already expired (Fail) | Imminent or actual service disruption — expired certificates commonly break OWA/ActiveSync (browser/client TLS warnings or outright connection failures) and SMTP-over-TLS mail flow to partners enforcing certificate validation | **Escalate immediately**; treat as a priority incident given the short remaining runway, and do not wait for the next monthly cycle |
| Certificate with `Services = None` flagged Fail/Warning for expiration | Informational only — an expiring certificate not bound to any service does not affect continuity of service | Log as informational; no urgent action required, though the organization may still choose to clean up unused expiring certificates during routine maintenance |
| Renewal request's SAN list does not match the original certificate's `CertificateDomains` | The replacement certificate may be missing a hostname needed by a client or partner, causing a new outage after "successful" renewal | Verify the full `CertificateDomains` list from step 2 is carried into the renewal request before submitting it |

This table reflects general practice for the assumed Exchange baseline and is not exhaustive.
