## 5. Procedure

**Pattern A — Automated Monitoring / Scan Confirmation** (assignment from `runbooks/Privileged-Users.md`)

1. In ePO (**Menu | Reporting | Queries**, System Management feature group), generate the Software/Asset Inventory report and compare current DAT/engine and application version data against the last approved baseline ([Trellix ePO Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf)). — Expected result: current inventory is fully reconciled against the approved baseline, with any deltas identified. — Capture: the exported inventory report (CSV/PDF). — Stop/continue: if the report cannot be generated (ePO unreachable, agents not checking in), stop and open a missed-cycle ticket before proceeding.
2. Run a Tenable Nessus compliance/configuration-audit scan using the applicable file-integrity or software-inventory audit policy against production hosts ([Tenable Nessus Compliance Checks Reference](https://docs.tenable.com/nessus/compliance-checks-reference/Content/PDF/NessusComplianceChecksReference.pdf)). — Expected result: a completed scan with Pass/Fail/Warning results for every in-scope host. — Capture: the exported scan results. — Stop/continue: continue to step 3 regardless of findings; findings are documented, not gated, at this step.
3. Review the scan results and the ePO Policy Compliance dashboard for unauthorized binary changes, unsigned executables, or firmware version drift from the approved baseline. — Expected result: every discrepancy is identified and listed. — Capture: annotated discrepancy list with supporting scan/dashboard data. — Stop/continue: if any true positive is CAT I (e.g., an unsigned/unauthorized binary on a high-value host), stop and escalate immediately per the Escalation block below before continuing routine triage.
4. For any discrepancy, validate against the CM baseline/change record to confirm whether the change was authorized; open a CCB ticket for unauthorized changes. — Expected result: every discrepancy is dispositioned as authorized or unauthorized. — Capture: the CCB ticket or disposition note. — Stop/continue: continue.
5. Document confirmed integrity violations and remediation actions taken (rollback, reimage, re-baseline), and determine CAT (I/II/III) per the finding's own severity source (STIG CAT rating, CVSS-derived CAT per `execution-plan/templates/VARIANCE-RISK-ACCEPTANCE-TEMPLATE.md`, or organizational policy for non-STIG/CVE findings). — Expected result: every finding has a documented remediation action and assigned CAT. — Capture: remediation record and CAT assignment. — Stop/continue: continue.
6. File or update the corresponding POA&M/tracking entry for any open finding. — Expected result: every open finding has a tracking ID. — Capture: POA&M ID. — Stop/continue: continue.
7. Export the Nessus and ePO reports and file them in the repository location specified in the Task Index alongside the reviewer's name and date. — Expected result: cycle record filed with full supporting evidence. — Capture: the filed evidence bundle and log entry. — Stop/continue: cycle complete.
