## 5. Procedure

**Pattern E — Documentation / Policy Review and Update** (underlying pattern; see step detail below for this control's specifics)

1. Pull the system's current security categorization statement (FIPS 199 / CNSSI 1253 confidentiality-integrity-availability impact levels) from the System Security Plan (SSP) and the SAP-specific overlay in the security authorization repository. — Expected result: current categorization statement and its version/date in hand. — Capture: the categorization statement excerpt or file reference, with pull date. — Stop/continue: continue.
2. Run a current Nessus credentialed scan of the enclave, configured per the organization's standard scan policy ([Tenable Nessus User Guide](https://docs.tenable.com/nessus/10_12/Content/PDF/Nessus_10_12.pdf)), and export the resulting host/asset list. — Expected result: an up-to-date asset inventory covering all in-scope hosts. — Capture: the exported Nessus scan/asset report. — Stop/continue: if the scan cannot reach part of the enclave, note the coverage gap before proceeding — do not compare against a partial inventory without flagging it.
3. Compare the scan's identified asset types, data flows, and mission-critical hosts against the categorization statement's assumptions, and cross-check with the ISSM and Security Control Assessor (SCA) whether any mission change, new interconnection, or data-type addition (e.g., a new intelligence compartment) has occurred since the last categorization cycle. — Expected result: a documented determination of whether the C, I, and A impact levels still match actual system usage and threat exposure. — Capture: the comparison notes and ISSM/SCA consultation record. — Stop/continue: continue regardless of outcome — a no-change determination still requires documented re-approval.
4. If no change is warranted, draft a no-change memo signed by the ISSM; if a change is warranted, draft the revised categorization statement for adjudication. — Expected result: a draft ready for routing (memo or revised statement). — Capture: the draft document. — Stop/continue: continue.
5. Route the categorization statement (or no-change memo) through the SCA for concurrence and the AO/DAO for approval signature. — Expected result: documented approval, concurrence, or rejection with rationale. — Capture: the signed approval/concurrence record. — Stop/continue: if rejected, return to step 4; do not publish or act on an unapproved categorization change.
6. File the signed categorization statement/memo and the supporting Nessus asset report in the security authorization repository per the Task Index, with reviewer name and date. — Expected result: complete, dated evidence package on file. — Capture: the filed package location/reference. — Stop/continue: cycle complete.
