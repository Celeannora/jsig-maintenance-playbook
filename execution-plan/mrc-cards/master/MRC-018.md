## 5. Procedure

*Authored procedure — the generic "Pattern C" refresh/patch boilerplate does not fit an event-driven personnel-notification action; superseded below with a sourced, control-specific procedure:*

1. Upon notification of a termination, transfer, or need-to-know change, confirm Personnel Security logged the event with a timestamp in the personnel tracking system, per AC-2. — Expected result: event logged with an accurate timestamp at time of notification. — Capture: personnel tracking system entry/timestamp. — Stop/continue: continue.
2. Verify the System Administrator received the notification and, using Active Directory (`Get-ADUser` and the account-disable/group-membership cmdlets), disabled or modified the affected account within the 8–24 hour window required. — Expected result: account state change completed within the required window. — Capture: AD change timestamp. — Stop/continue: if the window is at risk of being missed, stop and escalate to the ISSM immediately rather than let it lapse silently.
3. Run `repadmin /replsummary` (per [Microsoft Learn's repadmin reference](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/dcdiag)) or otherwise check AD replication status to confirm the account change replicated to all domain controllers within the window. — Expected result: `/replsummary` shows no outstanding replication failures for the domain controllers serving the affected account. — Capture: `repadmin /replsummary` output. — Stop/continue: if replication has not completed, escalate per [MRC-OPS-001](../ops/MRC-OPS-001.md)'s triage table before considering the account change organization-wide effective.
4. Cross-check the AD account status against the personnel system record to confirm account state matches the personnel action (disabled for termination, group membership updated for transfer/need-to-know change). — Expected result: AD state and personnel-system record agree. — Capture: cross-check note. — Stop/continue: continue.
5. Document the elapsed time between notification and account action to confirm the SLA was met; this task's 8–24 hour organizational window is markedly tighter than the 30-day AC-2 notification comparator in [HHS/CMS MAC ARS 5.0](https://www.hhs.gov/guidance/sites/default/files/hhs-guidance-documents/CMS/117_Systems_security-MAC-ARS.pdf) but consistent with the 24-hour comparator cited in [IRS Publication 1075](https://www.irs.gov/pub/irs-pdf/p1075.pdf). — Expected result: elapsed time calculated and within the required window, or a missed-SLA finding is opened. — Capture: elapsed-time record. — Stop/continue: if the SLA was missed, open a finding and escalate per the Escalation block below.
6. Export the AD account change log (`Get-ADUser` query output or Event Viewer account-management events) and file it in the repository location specified in the Task Index alongside the reviewer's name and date. — Expected result: cycle record filed. — Capture: the exported log. — Stop/continue: cycle complete.
