## 5. Procedure

**Pattern C — Update / Patch / Signature Refresh** (assignment from `runbooks/Privileged-Users.md`)

1. Run a Tenable Nessus credentialed vulnerability scan against all in-scope hosts to identify missing security patches published in the last 30 days ([Tenable Nessus User Guide](https://docs.tenable.com/nessus/10_12/Content/PDF/Nessus_10_12.pdf)); this cadence aligns with the monthly OS/web/database scan requirement described in the [FedRAMP Continuous Monitoring Performance Management Guide](https://www.fedramp.gov/assets/resources/documents/CSP_Continuous_Monitoring_Performance_Management_Guide.pdf). — Expected result: a completed scan with plugin-based findings for every in-scope host. — Capture: the exported scan results. — Stop/continue: continue.
2. Cross-reference the scan's plugin-based findings export against the vendor patch/advisory list and the ePO DAT/engine signature-version dashboard (**Menu | Reporting | Queries**) to confirm current update levels ([Trellix ePO Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf)). — Expected result: every finding is reconciled against known vendor advisories and current signature state. — Capture: the cross-reference worksheet. — Stop/continue: continue.
3. Verify the WSUS/patch-management console (or organization's equivalent update-management tool) shows required security updates approved and deployed to the applicable computer groups. — Expected result: approved updates show as deployed to all applicable groups. — Capture: console export/screenshot. — Stop/continue: continue.
4. For any host missing a required update past the remediation window, open a POA&M or remediation ticket with a target completion date; for a finding matching a CISA Known Exploited Vulnerability, treat the two-week federal remediation deadline referenced in [NIST SP 800-40 Rev. 4, Guide to Enterprise Patch Management Planning](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-40r4.pdf) as the priority benchmark rather than a routine 30-day window. — Expected result: every missing-patch finding has a tracking ID and target date. — Capture: POA&M/ticket ID. — Stop/continue: if a finding is CAT I or matches a KEV entry, stop and escalate immediately per the Escalation block below before continuing routine tracking.
5. Apply the update through the organization's change-control process (per `execution-plan/ROLE-CROSSWALK.md`'s CCB routing where the update is configuration-relevant). — Expected result: update applied to the affected host(s). — Capture: change-control ticket ID and applied-version confirmation. — Stop/continue: if the update requires an approved maintenance window not yet available, stop and document the compensating control/interim risk acceptance per `execution-plan/templates/VARIANCE-RISK-ACCEPTANCE-TEMPLATE.md` rather than leaving the gap silently open.
6. Re-scan remediated hosts with Nessus to confirm the missing-patch findings have cleared. — Expected result: the previously flagged findings no longer appear for the remediated host(s). — Capture: the post-remediation scan export. — Stop/continue: continue.
7. Export the before/after Nessus plugin findings and file them in the repository location specified in the Task Index alongside the reviewer's name and date. — Expected result: cycle record filed with full supporting evidence. — Capture: the filed evidence bundle and log entry. — Stop/continue: cycle complete.
