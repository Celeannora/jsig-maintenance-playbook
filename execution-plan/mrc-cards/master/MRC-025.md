## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/ISSO.md`)

1. Pull the current Nessus scan results (via the scan's vulnerabilities/findings list, per the [Tenable Nessus User Guide](https://docs.tenable.com/nessus/10_12/Content/PDF/Nessus_10_12.pdf)) and the Splunk continuous-monitoring dashboard findings for the review period, to identify new, recurring, or closed vulnerabilities. — Expected result: complete, current-month finding set pulled for both sources. — Capture: exported Nessus findings list and Splunk dashboard export, with pull timestamp. — Stop/continue: if either export is incomplete, stop and remediate the collection gap before reviewing partial data.
2. Cross-reference open POA&M line items against the latest Nessus plugin findings to confirm which weaknesses remain unresolved and which have been remediated. — Expected result: every open POA&M entry is matched to a current finding status (still open, remediated, or no longer applicable). — Capture: the annotated cross-reference. — Stop/continue: continue regardless of match count.
3. Update each open POA&M entry's status, scheduled completion date, milestones, and resources in the POA&M tracker, adding new entries for newly identified weaknesses and assigning a remediation timeline consistent with the organization's severity-based POA&M policy (e.g., the [CMS POA&M Handbook](https://security.cms.gov/learn/cms-plan-action-and-milestones-poam-handbook)'s Critical 15-day / High 30-day / Moderate 90-day / Low 365-day tiers are a commonly used federal reference point for setting these timelines if no stricter organization-specific policy exists). — Expected result: every open and new POA&M entry has a current status, milestone, and completion date. — Capture: updated POA&M tracker export. — Stop/continue: continue.
4. Close out POA&M entries with remediation evidence (e.g., a Nessus rescan showing the plugin no longer present) attached. — Expected result: every closed entry has attached rescan/remediation evidence. — Capture: rescan results attached to the closed entry. — Stop/continue: continue.
5. Route the updated POA&M to the ISSM for review and to the AO/DAO for risk-acceptance awareness on any overdue items. — Expected result: ISSM review recorded; AO/DAO notified of overdue items. — Capture: routing/notification record. — Stop/continue: if any overdue item lacks a documented justification, stop and obtain one before closing the cycle, consistent with the CMS Handbook's requirement that missed timelines carry a documented justification and revised completion date.
6. Export the updated POA&M and file it in the repository location specified in the Task Index alongside the reviewer's name and date. — Expected result: cycle record filed. — Capture: the consolidated evidence bundle. — Stop/continue: cycle complete.
