## 5. Procedure

**Pattern D — Test / Exercise** (underlying pattern; see step detail below for this control's specifics)

1. Pull the current, approved recovery/reconstitution test plan and the Contingency Plan's stated RTO/RPO targets. — Expected result: current test plan and RTO/RPO targets in hand, version confirmed. — Capture: test plan version/date and RTO/RPO values. — Stop/continue: if no current approved plan exists, stop — do not improvise an untested recovery procedure; escalate the missing-plan gap first.
2. Schedule and execute a system recovery/reconstitution test using the current backup set, restoring the system (or a designated test instance) from the most recent backup image via your backup solution's restore workflow (NetBackup's Recovery wizard / Activity Monitor job tracking, or Veeam Backup & Replication's restore job and session history) ([Veritas NetBackup Administrator's Guide](https://www.veritas.com/support/en_US/doc/150157642-165935937-0/v130722414-165935937); [Veeam Backup & Replication User Guide](https://helpcenter.veeam.com/docs/vbr/userguide/session_results_web.html)). This satisfies the "system recovery on an alternate platform from backup media" scope area called for in annual CP testing ([GSA Contingency Planning Guide](https://www.gsa.gov/system/files/Contingency-Planning-(CP)-%5BCIO-IT-Security-06-29-Rev-7%5D.pdf)). — Expected result: the restore job completes and the test instance is brought to a running state. — Capture: the backup solution's job/session log for the restore. — Stop/continue: if the restore job fails outright, stop, document the failure point, and escalate per Section 6 before continuing to validation.
3. Validate post-restoration system integrity: for AD-dependent systems, run `dcdiag` and `repadmin /replsummary` ([Microsoft Learn — Active Directory Health Monitoring](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/dcdiag)); for all systems, confirm application/service functionality against baseline. — Expected result: restored system passes health checks and core services function as expected. — Capture: `dcdiag`/`repadmin` output and application-functionality verification notes. — Stop/continue: if validation fails, document the specific failure as a test finding and continue to step 4 (do not treat a failed test as grounds to skip the after-action report).
4. Time the recovery process end-to-end and compare actual recovery time/recovery point against the RTO/RPO targets specified in the Contingency Plan. — Expected result: a documented pass/fail determination against RTO/RPO. — Capture: the timing log and RTO/RPO comparison. — Stop/continue: continue regardless of outcome.
5. Document any deviations, failures, or manual workarounds encountered during the restoration test in an After Action Report (AAR), consistent with the AAR/Lessons-Learned practice in [NIST SP 800-34 Rev. 1](https://nvlpubs.nist.gov/nistpubs/legacy/sp/nistspecialpublication800-34r1.pdf). — Expected result: a complete AAR covering what worked, what didn't, and root cause of any gap. — Capture: the AAR document. — Stop/continue: continue.
6. Update the Contingency Plan and recovery procedures to reflect lessons learned and correct any deficiencies identified during the test; for any gap, open a POA&M entry with a remediation owner and date. — Expected result: Contingency Plan revisions drafted (if needed) and every gap has a tracking ID. — Capture: the draft CP updates and POA&M ID(s). — Stop/continue: continue.
7. Route the test results and any Contingency Plan updates through the ISSM for review and ISSO for concurrence. — Expected result: documented review/concurrence. — Capture: the review/concurrence record. — Stop/continue: if rejected, address feedback and re-route before filing as final.
8. File the recovery test plan, execution log, AAR, and sign-off in the contingency planning repository per the Task Index, with reviewer name and date. — Expected result: complete, dated evidence package on file. — Capture: the filed package/location reference. — Stop/continue: cycle complete.
