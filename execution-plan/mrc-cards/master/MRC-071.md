## 5. Procedure

**Pattern E — Documentation / Policy Review and Update** (assignment from `runbooks/ISSM.md`)

Applies to tasks that periodically revise a governing document (e.g., System Security Plan, Contingency Plan, Incident Response Plan, Configuration Management Plan, family policies/procedures, privacy notices/SORNs).

1. Pull the current-version policy document for each of the 17 family -1 controls (AC-1, AT-1, AU-1, CA-1, CM-1, CP-1, IA-1, IR-1, MA-1, MP-1, PE-1, PL-1, PS-1, RA-1, SA-1, SC-1, SI-1) from the organizational policy repository (GRC document library / SharePoint policy library). — Expected result: all 17 current-version documents and their revision-history metadata in hand. — Capture: pulled document set with version numbers/dates noted. — Stop/continue: if any family's policy document cannot be located, log that as a finding in its own right (a missing -1 document is itself a control gap) and continue reviewing the remaining families.
2. Compare each policy's stated procedures against the current NIST SP 800-53 Rev.4 (JSIG-tailored) control text and against any organizational, mission, or regulatory changes since the last approval date recorded in the document's revision history. — Expected result: a per-family list of needed revisions (may be empty for some families). — Capture: the review notes/gap analysis per family. — Stop/continue: continue regardless of whether revisions are needed for a given family — a no-change review still requires documented re-approval.
3. For each family, draft redlined revisions to the policy/procedure document, or if no substantive changes are needed, draft a one-page no-change re-approval memo citing the review date and reviewer. — Expected result: 17 drafts (redline or no-change memo) ready for routing. — Capture: the draft set. — Stop/continue: continue.
4. Route each drafted policy revision or no-change memo through the Configuration Control Board (CCB) for technical review, then to the ISSM for content sign-off. — Expected result: each of the 17 documents has a documented CCB disposition and ISSM sign-off or rejection with rationale. — Capture: CCB routing/meeting records. — Stop/continue: if any document is rejected, return it to step 3; do not carry a rejected draft forward to AO/DAO approval.
5. Obtain final approval signature from the AO/DAO (or designated approval authority per the policy's governance block) for each of the 17 documents. — Expected result: signed approval for every family policy in scope. — Capture: signature/approval record per family. — Stop/continue: if the AO/DAO declines to approve, return to step 3 for that family; do not publish an unapproved revision.
6. Publish the approved/re-approved versions to the policy repository, incrementing version numbers and superseding prior copies. — Expected result: new versions live for all 17 families, prior versions archived (not deleted) per retention requirements. — Capture: published version files/locations and the archived superseded copies. — Stop/continue: continue.
7. File the signed approval memos/CCB routing records and updated policy set in the compliance repository location specified in the Task Index, annotated with the ISSM's name and approval date. — Expected result: complete, auditable cycle package for all 17 family policies. — Capture: the filed evidence package. — Stop/continue: cycle complete.
