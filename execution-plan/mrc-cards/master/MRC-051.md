## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/Privileged-Users.md`)

1. Pull the current System Security Plan (SSP) data-at-rest control implementation statement and the list of systems/media in scope (servers, workstations, removable media, databases). — Expected result: a complete in-scope asset list matching the current SSP inventory. — Capture: the pulled SSP excerpt and asset list, with pull timestamp. — Stop/continue: if the asset list is incomplete or stale, stop and reconcile it against the current inventory before proceeding.
2. On Windows hosts, run `manage-bde -status` (or `Get-BitLockerVolume | fl` from PowerShell) on each in-scope system disk to confirm BitLocker is enabled with the approved encryption method (e.g. XTS-AES 256) and protector configuration, checking the `VolumeStatus`, `ProtectionStatus`, and `KeyProtector` fields ([Microsoft Learn — BitLocker Operations Guide](https://learn.microsoft.com/en-us/windows/security/operating-system-security/data-protection/bitlocker/operations-guide)). — Expected result: every in-scope Windows disk reports `VolumeStatus: FullyEncrypted` and `ProtectionStatus: On` with an approved key protector. — Capture: the per-host command output. — Stop/continue: continue to step 3 regardless of result, noting any host that fails as a finding.
3. For database or application-level encryption, query the DBMS configuration (e.g. Transparent Data Encryption status) or file-system encryption settings and record the enabled/disabled state per instance. — Expected result: a documented encryption status per database/application instance. — Capture: the configuration query output or screenshot per instance. — Stop/continue: continue.
4. Cross-check any exceptions or systems reporting non-compliant encryption status against open Plan of Action and Milestones (POA&M) entries to confirm they are tracked. — Expected result: every non-compliant system is either remediated or has a matching open POA&M entry. — Capture: the POA&M cross-reference notes. — Stop/continue: if a non-compliant system has no POA&M entry, treat it as a new finding and proceed to step 5.
5. Document any newly discovered unencrypted asset as a finding and open a POA&M or remediation ticket with a target date in the local GRC/ticketing system. — Expected result: a ticket/POA&M ID exists for every new finding. — Capture: the ticket/POA&M ID. — Stop/continue: if the exposed data is high-sensitivity, escalate immediately per the Escalation block rather than waiting for normal ticket routing.
6. Compile the per-system encryption status into a compliance summary and file it in the repository location specified in the Task Index with the reviewer's name and date. — Expected result: cycle record filed. — Capture: the filed compliance summary. — Stop/continue: cycle complete.
