## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/ISSM.md`)

1. Pull the current-period metrics extract from the local GRC/ticketing repository (e.g., patch compliance rate, POA&M closure rate, incident count, scan finding aging). — Expected result: a complete metrics extract covering the full reporting period. — Capture: the extract file itself, with pull timestamp. — Stop/continue: if the extract is incomplete (gap in coverage), stop and remediate the collection gap before computing measures on partial data.
2. Compute each performance measure against its defined threshold/target as specified in the organization's security metrics plan. — Expected result: every measure has a computed value and pass/breach status against its threshold. — Capture: the computed-measures worksheet. — Stop/continue: continue.
3. Draft the information security performance measures report summarizing trends, threshold breaches, and root causes for the period; where POA&M closure-rate is a reported measure, frame it against the cadence used by comparable federal reporting programs — e.g., the [CMS POA&M Handbook](https://security.cms.gov/learn/cms-plan-action-and-milestones-poam-handbook)'s requirement to update POA&M status **at least quarterly** and report remediation progress **monthly**. — Expected result: a complete draft report. — Capture: the draft report document. — Stop/continue: continue.
4. Route the draft report to the ISSM for accuracy review and to the AO/DAO for briefing. — Expected result: ISSM confirms accuracy or returns correction requests; AO/DAO briefing is scheduled or delivered. — Capture: review/correction notes and briefing record. — Stop/continue: if corrections are requested, return to step 3 before proceeding.
5. Brief the Risk Executive Function on measures that breached thresholds and any resulting risk-acceptance or remediation decisions. — Expected result: Risk Executive Function has reviewed all threshold breaches and recorded a decision (accept risk, direct remediation, or request more data). — Capture: briefing minutes/decision record. — Stop/continue: if any breach represents a CAT I condition, stop and escalate immediately per the Escalation block below before closing the cycle.
6. File the finalized performance measures report in the repository location specified in the Task Index alongside the reviewer's name and date. — Expected result: a complete, dated, reviewed report is filed for the cycle. — Capture: the filed report and sign-off record. — Stop/continue: cycle complete.
