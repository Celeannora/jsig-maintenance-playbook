## 5. Procedure

**Pattern E — Documentation / Policy Review and Update** (assignment from `runbooks/Privileged-Users.md`)

1. Pull the current approved baseline configuration document (hardware/software/GPO baseline) from the CM repository for the system, along with its associated control citations/ODPs. — Expected result: current approved baseline version and version history in hand. — Capture: version number/date. — Stop/continue: continue.
2. Run an ePO Asset/Software Inventory report (Menu > Reporting > Queries & Reports, Managed Systems result type) to capture the as-built software/version inventory across all managed endpoints ([Trellix ePolicy Orchestrator Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf)). — Expected result: a complete, current as-built software/version inventory. — Capture: the inventory export. — Stop/continue: if the export is incomplete (gap in coverage), stop and remediate the collection gap before reviewing partial data.
3. Run `Get-GPOReport` (GPMC XML/HTML export) to capture the as-applied Group Policy configuration and compare it against the documented baseline GPO settings ([Microsoft Learn — Group Policy Management](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/gpresult)). — Expected result: a complete as-applied GPO configuration export, compared line-by-line against the documented baseline. — Capture: the `Get-GPOReport` export and comparison notes. — Stop/continue: continue.
4. Identify deltas between the as-built/as-applied state and the documented baseline (unauthorized software, drifted GPO settings, unpatched configuration items) — review against current control requirements and any organizational, technical, or regulatory changes since the last review. — Expected result: a complete list of deltas (may be empty). — Capture: the delta/review notes. — Stop/continue: continue regardless of whether deltas are found — a no-change review still requires documented re-approval.
5. Draft baseline configuration updates or remediation actions for identified drift (or a no-change re-approval memo if none are needed) and submit them through the CCB for review and approval. — Expected result: documented CCB approval or rejection with rationale for each proposed update. — Capture: the CCB submission and approval record/signature. — Stop/continue: if rejected, revise and resubmit; do not publish an unapproved revision.
6. Publish the updated baseline document upon CCB approval and archive the prior version per version-control procedure. — Expected result: new baseline version live, prior version archived, not deleted. — Capture: both version files/locations. — Stop/continue: continue.
7. Export the comparison report and CCB approval record and file them in the repository location specified in the Task Index, alongside the reviewer's name and date. — Expected result: complete evidence package filed for the cycle. — Capture: the filed comparison report and approval record. — Stop/continue: cycle complete.
