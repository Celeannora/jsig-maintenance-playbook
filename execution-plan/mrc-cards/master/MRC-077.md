## 5. Procedure

**Pattern E — Documentation / Policy Review and Update** (assignment from `runbooks/ISSM.md`)

Applies to tasks that periodically revise a governing document (e.g., System Security Plan, Contingency Plan, Incident Response Plan, Configuration Management Plan, family policies/procedures, privacy notices/SORNs). Per the [CMS POA&M Handbook](https://security.cms.gov/learn/cms-plan-action-and-milestones-poam-handbook), Risk-Based Decisions are reviewed at least annually and full control-effectiveness assessments occur within every 365 days — a comparable cadence to this card's Annual frequency.

1. Pull the current organizational Risk Assessment Report and prior POA&M from the GRC repository to establish the baseline of previously identified risks. — Expected result: current Risk Assessment Report and POA&M in hand. — Capture: version number/date of each. — Stop/continue: continue.
2. Run a current credentialed Tenable Nessus vulnerability scan across the system's asset inventory and export the findings report, including CVSS scores and plugin details (per the [Tenable Nessus User Guide](https://docs.tenable.com/nessus/10_12/Content/PDF/Nessus_10_12.pdf)'s credentialed-scan workflow). — Expected result: a complete scan export covering the current asset inventory. — Capture: the exported scan results file. — Stop/continue: if the scan cannot complete against the full inventory (credential failure, unreachable hosts), stop and remediate scan access before treating the assessment as complete.
3. Review the past year's incident records, audit findings, and any newly introduced hardware/software/network changes for new threat sources or vulnerabilities not captured in the prior assessment. — Expected result: a list of new/changed threat sources and vulnerabilities (may be empty). — Capture: the review notes. — Stop/continue: continue.
4. Reassess likelihood and impact ratings for each identified risk using the current scan data and threat information, updating the risk register accordingly. — Expected result: updated risk register with current likelihood/impact ratings for every tracked risk. — Capture: the updated risk register. — Stop/continue: continue.
5. Update the Risk Assessment Report narrative and risk register with new/closed risks, and reconcile against open POA&M items, consistent with the [CMS POA&M Handbook](https://security.cms.gov/learn/cms-plan-action-and-milestones-poam-handbook)'s at-least-quarterly POA&M review convention. — Expected result: risk register and POA&M cross-referenced with no orphaned entries on either side. — Capture: the reconciliation notes. — Stop/continue: continue.
6. Route the updated Risk Assessment Report through the ISSM for review, with SCA consultation, and obtain AO/DAO acknowledgment. — Expected result: documented ISSM review and AO/DAO acknowledgment. — Capture: the review/acknowledgment record. — Stop/continue: if the ISSM or SCA identifies a material gap, return to step 4 before AO/DAO acknowledgment.
7. File the signed updated Risk Assessment Report and supporting Nessus export in the repository location specified in the Task Index with the ISSM's name and review date. — Expected result: complete, auditable cycle package. — Capture: the filed evidence package. — Stop/continue: cycle complete.
