## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/ISSM.md`)

This task's quarterly cadence is consistent with the tiered privileged-account review frequency documented in the [HHS CMS MAC ARS](https://www.hhs.gov/guidance/sites/default/files/hhs-guidance-documents/CMS/117_Systems_security-MAC-ARS.pdf), used here as a federal cross-agency comparator; that source addresses privileged-account review generally rather than change-tied production access specifically.

1. Pull the change/release log from the CCB tracking system for all changes implemented in production during the quarter. — Expected result: a complete change/release log covering the full quarter. — Capture: the exported log, with pull timestamp. — Stop/continue: if the log is incomplete (gap in coverage), stop and remediate the logging/collection gap before reviewing partial data.
2. Run `Get-ADGroupMember` against groups granting production/operational deployment or administrative privileges to export the current holder list. — Expected result: a complete, current export of every production/operational-privilege group's membership. — Capture: the exported membership list. — Stop/continue: if any group cannot be enumerated, stop and resolve access before proceeding.
3. Cross-check each privileged account holder against active change tickets to confirm the access is still tied to an open or recurring authorized change role, not a stale one-time grant. — Expected result: every privileged account holder is dispositioned as still-justified or stale. — Capture: the cross-check worksheet. — Stop/continue: continue regardless of disposition count.
4. Revoke or downgrade production/operational privileges for accounts whose associated change work has closed, using Active Directory account management. — Expected result: no stale production/operational privilege grant remains active. — Capture: the revocation/downgrade action log. — Stop/continue: if a stale privileged grant shows evidence of use after its associated change closed, stop and escalate immediately per the Escalation block below.
5. Document the reassessment outcome and any access revocations in the CCB record. — Expected result: the CCB record reflects the completed reassessment and all revocations. — Capture: the CCB record update. — Stop/continue: continue.
6. Export the updated privileged-access-to-change mapping and file it in the repository location specified in the Task Index alongside the reviewer's name and date. — Expected result: a complete, dated mapping is filed for the cycle. — Capture: the filed mapping and sign-off record. — Stop/continue: cycle complete.
