## 5. Procedure

**Pattern A — Automated Monitoring / Scan Confirmation** (assignment from `runbooks/Privileged-Users.md`)

1. Review IPsec policy and VPN gateway configuration to confirm all remote-access and inter-system transmission paths are encrypted per the SSP-defined cryptographic mechanism, in the local network/VPN management console (family-default tooling per `AGENTS.md` rule 8 — the underlying transport-protection mechanism, not a dedicated JSIG-cited product in this environment). — Expected result: every remote-access and inter-system transmission path in scope shows an active, approved encryption mechanism. — Capture: the configuration review notes/export. — Stop/continue: continue to step 5 for any path found unencrypted or using a non-approved mechanism.
2. Verify TLS configuration on internal application/service endpoints enforces the approved minimum protocol version and cipher suite, checking each endpoint's TLS configuration against the SSP-defined baseline. — Expected result: every sampled endpoint enforces the approved minimum TLS version and cipher suite. — Capture: the endpoint configuration review notes. — Stop/continue: continue to step 5 for any endpoint below the approved baseline.
3. Review Splunk VPN/remote-access logs for the period to confirm no sessions were established using disallowed or unencrypted protocols, using a field-value SPL search over the relevant VPN/remote-access index and sourcetype (e.g. `index=<vpn_index> sourcetype=<vpn_sourcetype> NOT protocol IN (<approved_protocol_list>)` to surface any session using a non-approved protocol) per the [Splunk SPL search syntax reference](https://help.splunk.com/en?resourceId=Splunk_SearchReference_Search&version=splunk-9_4). — Expected result: zero sessions found using a disallowed/unencrypted protocol. — Capture: the exported Splunk search results. — Stop/continue: continue to step 5 for any disallowed session found.
4. Spot-check network captures or device configuration exports on a sample of transmission paths to confirm encryption is actually in effect (not just configured). — Expected result: sampled captures/exports confirm encrypted traffic matching the configured mechanism. — Capture: the capture/export files reviewed (handled per this card's classification/handling requirement — Section 4). — Stop/continue: continue to step 5 for any path where captured traffic does not match the configured encryption mechanism.
5. Document and remediate any transmission path found using a non-approved or disabled encryption mechanism via a change ticket to the Network Administrator in the local ticketing/GRC system. — Expected result: every finding has a tracked remediation ticket. — Capture: the ticket ID(s). — Stop/continue: continue.
6. Export the IPsec/TLS configuration review and Splunk log excerpt and file them in the repository location specified in the Task Index, alongside the reviewer's name and date. — Expected result: a complete, filed evidence package for the cycle. — Capture: the filed report package. — Stop/continue: cycle complete.
