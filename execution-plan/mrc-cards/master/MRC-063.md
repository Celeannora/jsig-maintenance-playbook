## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/Information-Owner-Steward.md`)

1. Pull the current PII data inventory / System of Records Notice (SORN) listing all PII data elements collected and their authorized sources, from the local document-repository/GRC system. — Expected result: current, approved SORN/inventory in hand. — Capture: the inventory export, with version/date. — Stop/continue: if no current SORN/inventory exists or it is out of date, stop and escalate the documentation gap before reviewing data quality against it.
2. Sample a set of records from the PII holding (HR system, access-roster database, or equivalent) and validate accuracy, completeness, and currency of key fields (name, SSN, clearance status) against the authoritative source system. — Expected result: a completed sample-validation worksheet showing match/mismatch per field per record. — Capture: the worksheet. — Stop/continue: continue regardless of sample outcome; log every mismatch for step 5.
3. Run any available data-validation or duplicate-detection query/report against the PII holding (e.g., a built-in report in the HR/access-roster system, or a GRC-tool query) to identify stale, inconsistent, or orphaned records. — Expected result: a list of flagged records (may be empty). — Capture: the query/report output. — Stop/continue: continue.
4. Confirm collection forms/intake processes still restrict input to the minimum necessary PII elements defined in the SORN/Privacy Impact Assessment. — Expected result: intake forms match the documented minimum-necessary element set, with no undocumented additional fields being collected. — Capture: the form review notes. — Stop/continue: if an intake form collects PII elements not authorized by the SORN/PIA, stop and escalate immediately per the Escalation block.
5. Document identified data-quality discrepancies (from steps 2–4) and route correction/purge actions to the Information Owner/Steward for remediation, with an assigned owner and due date for each. — Expected result: every discrepancy has a documented remediation assignment. — Capture: the discrepancy log with assignments. — Stop/continue: continue.
6. Export the data-quality review findings memo and file it in the repository location specified in the Task Index, alongside the reviewer's name and date. — Expected result: complete evidence package filed for the cycle. — Capture: the filed memo. — Stop/continue: cycle complete.
