## 5. Procedure

**Pattern A — Automated Monitoring / Scan Confirmation** (assignment from `runbooks/Privileged-Users.md`)

1. In the ePO console, confirm the On-Access Scan policy is enabled and enforced on all managed endpoints via a Policy Compliance query (**Menu | Reporting | Queries**, Policy Management Feature Group — Applied Policies / compliance query, per the [Trellix ePolicy Orchestrator Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf)). Per [FedRAMP Tailored SI-3 guidance](https://github.com/GSA/fedramp-tailored/blob/master/_guidance/controls/SI-3.md), periodic scanning must occur **at least weekly** in addition to the continuous real-time/on-access scanning verified here. — Expected result: On-Access Scan policy shows enforced/compliant on 100% of managed endpoints. — Capture: exported Policy Compliance query results. — Stop/continue: if any endpoint shows disabled/non-compliant on-access scanning, continue to step 5 for that endpoint after completing the rest of this cycle's review.
2. Verify DAT/engine signature currency by running the built-in **VSE: DAT Deployment** query (**Menu | Reporting | Queries | VSE: DAT Deployment | Actions | Run**) to confirm current definitions are deployed within the required update window across all endpoints ([Trellix ePolicy Orchestrator Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf)). Signature updates are required **whenever new releases are available** per [FedRAMP Tailored SI-3 guidance](https://github.com/GSA/fedramp-tailored/blob/master/_guidance/controls/SI-3.md), which in practice this environment implements as automated periodic (at minimum daily) update checks. — Expected result: no endpoint reporting a DAT version older than the organization's update window. — Capture: exported DAT Deployment report. — Stop/continue: continue to step 5 for any outdated endpoint.
3. Review the ePO Threat Event Log (**Menu | Reporting | Threat Event Log**) for real-time detections on externally sourced files (removable media, email attachments, downloads) during the period, sorting/filtering by Threat Source and Event Generated Time ([Trellix ePolicy Orchestrator Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf)). — Expected result: a complete list of this period's external-file detections. — Capture: exported Threat Event Log view. — Stop/continue: continue to step 4 regardless of findings.
4. Confirm quarantine/remediation actions were completed for each detected threat by checking the **Action Taken** field on each Threat Event Log entry. — Expected result: every detection shows a completed disposition (quarantined/cleaned/deleted). — Capture: the annotated Threat Event Log export. — Stop/continue: if any detection lacks a completed disposition, escalate per Section 6 before closing the cycle.
5. Remediate any endpoint found with an outdated DAT version or disabled on-access scanning by issuing an ePO Agent Wake-Up call to force policy/signature re-enforcement. — Expected result: the affected endpoint(s) report current DAT version and enabled on-access scanning on the next ePO check-in. — Capture: the Agent Wake-Up task confirmation and the follow-up compliance query showing remediation. — Stop/continue: continue.
6. Export the ePO Policy Compliance, DAT Deployment, and Threat Event Log reports and file them in the repository location specified in the Task Index, alongside the reviewer's name and date. — Expected result: a complete, filed evidence package for the cycle. — Capture: the filed report package. — Stop/continue: cycle complete.
