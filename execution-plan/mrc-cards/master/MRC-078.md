## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/PSO.md`)

Applies to tasks where a person reviews an existing list, log, or record set against a baseline or policy (e.g., access lists, physical access logs, visitor records, privileged-account lists, audit records). No reference doc in `reference/external-sources/` addresses PS-6 directly; the annual cadence below comes from the Master Calendar/`curated_actions` skeleton, cross-referenced only informally against the account-review cadence pattern in [HHS/CMS MAC ARS 5.0](https://www.hhs.gov/guidance/sites/default/files/hhs-guidance-documents/CMS/117_Systems_security-MAC-ARS.pdf).

1. Pull the current roster of cleared personnel with system access from Active Directory (`Get-ADUser` scoped to privileged/access groups via `Get-ADGroupMember`) and cross-reference against the personnel security access-agreement file. — Expected result: a complete, unaltered roster of personnel with active system access, cross-referenced against agreement records. — Capture: the AD export and the cross-reference file, with pull timestamp. — Stop/continue: if the AD export is incomplete (gap in coverage), stop and remediate the collection gap before reviewing partial data.
2. Identify personnel whose signed Access Agreement (e.g., Acceptable Use Policy / Non-Disclosure Agreement) is more than one year old or has never been executed. — Expected result: a list of personnel due for re-signature (may be empty). — Capture: the annotated roster. — Stop/continue: continue regardless of list size.
3. Distribute the current-version Access Agreement to each identified individual for review and re-signature, using the organization's personnel security tracking system. — Expected result: agreement distributed to every identified individual. — Capture: the distribution log/date. — Stop/continue: continue.
4. Collect and verify completed, signed agreements, confirming signature dates and version acknowledged match the current approved agreement text. — Expected result: signed agreements collected for every distributed individual, or a documented non-response. — Capture: the collected signed agreements. — Stop/continue: continue.
5. Update the personnel security tracking system/records to reflect the new signature date for each individual, and flag any non-responders for account suspension per policy. — Expected result: tracking system reflects current signature status for every individual in scope. — Capture: the updated tracking export. — Stop/continue: if any non-responder holds privileged access, escalate immediately per the Escalation block rather than waiting for the routine follow-up cycle.
6. Notify the ISSM of personnel who failed to re-sign within the grace period so access can be restricted in Active Directory. — Expected result: ISSM notified with a specific list of non-responders. — Capture: the notification record. — Stop/continue: continue.
7. File the collected signed access agreements and the updated tracking roster in the repository location specified in the Task Index with the Personnel Security Officer's name and completion date. — Expected result: cycle record filed. — Capture: the filed evidence package. — Stop/continue: cycle complete.
