## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/ISSM.md`)

1. Pull the current inventory of external information system service providers (cloud services, MSPs, telecom carriers, cross-domain solution providers) from the GRC/documentation repository. — Expected result: complete, unaltered provider inventory covering the full period since the last review. — Capture: the inventory export, with pull timestamp. — Stop/continue: if the export is incomplete (gap in coverage), stop and remediate the collection gap before reviewing partial data.
2. For each provider, review the current contract, Interconnection Security Agreement (ISA), or Service Level Agreement (SLA) to confirm required security controls and JSIG/NIST SP 800-53 obligations are still specified and current. — Expected result: each provider's governing agreement confirmed current, or flagged as expired/outdated. — Capture: agreement version/expiration dates. — Stop/continue: continue.
3. Request and review each provider's most recent compliance evidence (e.g., a FedRAMP authorization package, SOC 2 report, or equivalent attestation) to confirm continued compliance. — Expected result: current compliance evidence on file for each provider (may reveal gaps). — Capture: the collected evidence artifacts. — Stop/continue: continue regardless of findings — a no-gap review still requires documented re-approval.
4. Identify any providers with expired agreements, lapsed authorizations, or unresolved compliance gaps and initiate remediation or re-negotiation actions. — Expected result: every gap is dispositioned with a remediation action and target date, or escalated as a finding. — Capture: disposition notes. — Stop/continue: if a lapsed authorization or compliance gap affects a provider handling sensitive/CUI-equivalent data, stop and escalate immediately per the Escalation block rather than waiting for routine remediation tracking.
5. Update the external service provider inventory and compliance status log with findings. — Expected result: inventory/status log reflects the current review cycle's findings. — Capture: the updated inventory/log. — Stop/continue: continue.
6. Route the compliance summary to the ISSM for review and the AO/DAO for awareness. — Expected result: documented review by the ISSM and awareness confirmation from the AO/DAO. — Capture: the routing/review record. — Stop/continue: continue.
7. File the updated inventory and compliance summary in the repository location specified in the Task Index with the ISSM's name and date. — Expected result: cycle record filed. — Capture: the filed inventory and summary. — Stop/continue: cycle complete.
