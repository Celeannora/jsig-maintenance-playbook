## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/Privileged-Users.md`)

SA-22 (Unsupported System Components) is one of JSIG's three non-tailorable controls — "Added to the baseline and required to be implemented on all SAP systems" per the [DCSA JSIG source document](https://www.dcsa.mil/portals/91/documents/ctp/nao/JSIG_2016April11_Final_(53Rev4).pdf) — so this review cannot be skipped or tailored out regardless of system size.

1. Pull the current hardware/software asset inventory from the CM repository, including vendor, version, and support-status fields. — Expected result: a complete, current asset inventory with support-status data. — Capture: the exported inventory, with pull timestamp. — Stop/continue: if support-status fields are missing/incomplete, stop and remediate the inventory gap before proceeding.
2. Cross-reference each component's vendor end-of-life/end-of-support (EOL/EOS) notices and lifecycle roadmaps to identify components that have reached or are approaching EOS. — Expected result: a complete list of EOL/EOS or approaching-EOS components (may be empty). — Capture: the cross-reference worksheet with vendor notice references. — Stop/continue: continue regardless of list length.
3. For each unsupported component found, verify whether a documented risk acceptance, extended support contract, or replacement/upgrade plan is on file. — Expected result: every unsupported component is dispositioned as covered (documented mitigation on file) or uncovered. — Capture: disposition notes with supporting document references. — Stop/continue: continue.
4. For components lacking mitigation, open a POA&M item specifying compensating controls (isolation, enhanced monitoring) or a decommission/upgrade timeline, consistent with the remediation-tier and quarterly-review discipline described in the [CMS POA&M Handbook](https://security.cms.gov/learn/cms-plan-action-and-milestones-poam-handbook). — Expected result: every uncovered unsupported component has an open POA&M item with a tracking ID. — Capture: the POA&M ID and item details. — Stop/continue: if an unsupported component is internet-facing or handles sensitive data with no compensating control, stop and escalate immediately per the Escalation block below before continuing routine tracking.
5. Brief the ISSM and AO/DAO on newly identified unsupported components and proposed dispositions. — Expected result: ISSM and AO/DAO have reviewed all newly identified components and proposed dispositions. — Capture: briefing minutes/decision record. — Stop/continue: continue.
6. Export the updated unsupported-components list and file it in the repository location specified in the Task Index alongside the reviewer's name and date. — Expected result: a complete, dated list is filed for the cycle. — Capture: the filed list and sign-off record. — Stop/continue: cycle complete.
