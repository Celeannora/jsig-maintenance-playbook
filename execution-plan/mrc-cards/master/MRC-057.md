## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/Privileged-Users.md`)

1. Pull the current inventory of devices requiring identification/authentication (domain-joined workstations, servers, network devices) via `Get-ADComputer`. — Expected result: a complete current device inventory. — Capture: the exported inventory, with pull timestamp. — Stop/continue: if incomplete, stop and reconcile before reviewing partial data.
2. Verify machine-authentication certificates or Kerberos computer-account authentication are correctly configured by reviewing the AD Certificate Services issued-certificate report or running `dcdiag` (e.g. the `Advertising` and `Services` tests) to confirm computer-account trust relationships ([Microsoft Learn — dcdiag command reference](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/dcdiag)). — Expected result: all sampled devices show a healthy, valid trust/certificate relationship. — Capture: the `dcdiag` output or certificate report. — Stop/continue: continue, flagging any failure as a finding.
3. Confirm any non-Windows or IoT/network devices use an approved device-authentication mechanism (e.g. 802.1X certificate-based authentication) by checking the NPS/RADIUS authentication logs. — Expected result: all in-scope non-Windows devices authenticate via an approved mechanism. — Capture: the NPS/RADIUS log excerpt reviewed. — Stop/continue: continue.
4. Identify any device account that is stale, disabled, or missing required authentication configuration and remediate (rejoin domain, reissue certificate, or disable the device account). — Expected result: every stale/misconfigured device account is remediated or dispositioned. — Capture: the remediation ticket/record. — Stop/continue: if a device account shows signs of unauthorized use, stop and escalate immediately per the Escalation block.
5. Spot-check a sample of devices against the device-authentication baseline/STIG requirement to confirm compliance. — Expected result: sampled devices meet the baseline/STIG requirement. — Capture: the spot-check results. — Stop/continue: continue.
6. Export the device authentication compliance results and file them in the repository location specified in the Task Index alongside the Network Administrator's name and date. — Expected result: cycle record filed. — Capture: the filed compliance results. — Stop/continue: cycle complete.
