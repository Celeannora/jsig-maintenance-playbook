## 5. Procedure

**Pattern A — Automated Monitoring / Scan Confirmation** (assignment from `runbooks/Privileged-Users.md`)

1. Review Windows Defender Firewall with Advanced Security inbound/outbound rule sets on boundary-facing servers against the approved firewall rule baseline, using `Get-NetFirewallRule -PolicyStore ActiveStore` to see the merged effective rule set and `Get-NetFirewallProfile -PolicyStore ActiveStore` to confirm each profile (Domain/Private/Public) is enabled with the expected default action ([Microsoft Learn — Windows Defender Firewall command-line/PowerShell reference](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/configure-with-command-line)). — Expected result: the active rule set and profile defaults on each boundary-facing server match the approved baseline, with no unexplained enabled inbound Allow rule. — Capture: the exported `Get-NetFirewallRule`/`Get-NetFirewallProfile` output for each sampled server. — Stop/continue: continue to step 5 for any unauthorized or unexplained rule/profile setting found.
2. Confirm IPsec policy configuration enforcing encrypted boundary connections matches the SSP-defined boundary protection design (spot-check with `Get-NetIPsecRule -TracePolicyStore` to confirm rule source/GPO where applicable, per the same Microsoft Learn reference). — Expected result: IPsec policy configuration matches the SSP design; any GPO-sourced rule traces to the expected policy store. — Capture: the IPsec rule export. — Stop/continue: continue to step 5 for any mismatch.
3. Run a Nessus scan against boundary devices/servers to identify unauthorized open ports or services exposed across the boundary, using a credentialed scan where credentials are available for deeper configuration checks ([Tenable Nessus User Guide](https://docs.tenable.com/nessus/10_12/Content/PDF/Nessus_10_12.pdf)). — Expected result: no unauthorized open port/service exposed at the boundary. — Capture: the Nessus scan results for the boundary scope. — Stop/continue: continue to step 5 for any unauthorized finding.
4. If Trellix/McAfee network security modules are deployed, review their policy compliance status for boundary-related rule enforcement via an ePO Policy Compliance query (**Menu | Reporting | Queries**, Policy Management Feature Group). — Expected result: boundary-related network security policies show compliant/enforced. — Capture: the exported ePO compliance query results (or a note that no such module is deployed in this environment, if applicable). — Stop/continue: continue to step 5 for any non-compliant finding.
5. Remediate any unauthorized rule, open port, or policy drift found in steps 1–4 by submitting a change ticket through the Network Administrator in the local ticketing/GRC system. — Expected result: every finding has a tracked remediation ticket. — Capture: the ticket ID(s). — Stop/continue: continue.
6. Export the firewall rule review and Nessus scan results and file them in the repository location specified in the Task Index, alongside the reviewer's name and date. — Expected result: a complete, filed evidence package for the cycle. — Capture: the filed report package. — Stop/continue: cycle complete.
