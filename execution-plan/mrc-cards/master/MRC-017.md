## 5. Procedure

*Authored procedure (from `runbooks/ISSO.md`, not a generic pattern):*

1. For the active incident ticket in the incident-tracking system, identify the designated Incident Commander and the reporting cadence defined in [ESCALATION-MATRIX.md](../../templates/ESCALATION-MATRIX.md) and the incident response plan, per IR-6. — Expected result: cadence and Incident Commander confirmed for this incident. — Capture: cadence record noted on the ticket. — Stop/continue: continue.
2. In Splunk, verify the incident's supporting detection data (alert timeline, affected hosts/accounts, per the [Splunk Enterprise Alerting/Search Manual](https://help.splunk.com/en/splunk-enterprise/alert-and-respond/alerting-manual/9.1/create-alerts/create-scheduled-alerts)) is attached or linked to the ticket for the current update. — Expected result: current supporting data is linked/attached. — Capture: linked search/export reference. — Stop/continue: continue.
3. Confirm the ticket status field (e.g., contained, eradicated, recovering, closed — the incident-lifecycle stages described in [NIST SP 800-61 Rev. 2](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-61r2.pdf)) was updated to reflect current incident state. — Expected result: status field matches actual current state. — Capture: updated ticket status. — Stop/continue: continue.
4. Deliver a status update at each required interval covering current state, actions taken, and next steps. — Expected result: update delivered on schedule. — Capture: update log entry. — Stop/continue: if an update is missed, stop and escalate immediately rather than skipping to the next cycle.
5. Confirm the update was distributed to ISSM and, where the incident meets escalation criteria, to AO/DAO and CISO, per the Consulted/Informed parties named in the incident record. — Expected result: distribution confirmed to all required parties. — Capture: distribution log. — Stop/continue: continue until incident closure.
6. Confirm any required external reporting (e.g., to a higher-echelon CND authority per organizational policy and reporting timeline) was submitted if applicable to this incident. — Expected result: external reporting obligation, if any, confirmed met or not applicable. — Capture: external report confirmation/timestamp. — Stop/continue: continue.
7. Export the incident status update and distribution record and file them in the repository location specified in the Task Index alongside the reviewer's name and date. — Expected result: cycle record filed. — Capture: the exported update/distribution record. — Stop/continue: this update cycle is complete; repeat from step 4 at the next required interval until incident closure.
