## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/Privileged-Users.md`)

1. Identify all data transmission paths in scope (site-to-site VPN, remote access VPN, internal encrypted tunnels, web services) from the current network architecture diagram. — Expected result: a complete inventory of transmission paths to be reviewed this cycle. — Capture: the path inventory. — Stop/continue: continue.
2. Review IPsec policy configuration in Windows Defender Firewall with Advanced Security (queried via `Get-NetFirewallRule`/`Get-NetIPsecRule`, including `-TracePolicyStore` to confirm whether a rule originates from the intended GPO) or the VPN concentrator's config export, to confirm approved cipher suites (e.g. AES-256, SHA-2) are enforced for each tunnel ([Microsoft Learn — Windows Defender Firewall with Advanced Security command-line reference](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/configure-with-command-line)). — Expected result: every in-scope tunnel enforces only approved cipher suites. — Capture: the exported rule/policy configuration. — Stop/continue: continue, flagging any tunnel using a deprecated cipher as a finding.
3. Pull TLS configuration/certificate details for internal web services and confirm only approved protocol versions and cipher suites are enabled, using a Tenable Nessus scan (e.g. a Policy Compliance/Advanced Scan configured against the relevant hosts) to identify weak or deprecated TLS configurations ([Tenable Nessus User Guide](https://docs.tenable.com/nessus/10_12/Content/PDF/Nessus_10_12.pdf)). — Expected result: a scan report identifying any web service accepting a deprecated protocol version or cipher. — Capture: the exported Nessus scan report. — Stop/continue: continue, flagging any finding.
4. Review Splunk VPN/remote-access logs (a saved/scheduled SPL search over the relevant index, e.g. filtering on cipher or protocol fields) for any connection negotiated with a deprecated or unapproved cipher, and flag them as findings ([Splunk Enterprise Search/Alerting Manual](https://help.splunk.com/en/splunk-enterprise/alert-and-respond/alerting-manual/9.1/create-alerts/create-scheduled-alerts)). — Expected result: a list of any non-compliant negotiated connections this period (may be empty). — Capture: the SPL search results/export. — Stop/continue: continue.
5. Verify certificates used for transmission encryption are current (not expired) and issued by an approved CA. — Expected result: no expired or unapproved certificates on in-scope transmission paths. — Capture: the certificate inventory/expiration check output. — Stop/continue: if an expired certificate is found on a production path, treat as a priority finding and route per step 6.
6. Record findings, remediate or open a POA&M for any non-compliant path in the local GRC/ticketing system, and file the summary report in the repository location specified in the Task Index with the reviewer's name and date. — Expected result: cycle record filed with all findings dispositioned or tracked. — Capture: the filed summary report and any POA&M/ticket ID(s). — Stop/continue: cycle complete.
