## 5. Procedure

**Pattern C — Update / Patch / Signature Refresh** (assignment from `runbooks/Privileged-Users.md`)

1. Check the Nessus/Tenable feed update log to confirm the plugin/vulnerability signature set auto-updated on schedule prior to the monthly scan window, consistent with the [FedRAMP Continuous Monitoring Playbook](https://www.fedramp.gov/resources/documents/Continuous_Monitoring_Playbook.pdf)'s requirement that the scanner check for automatic signature updates at least monthly and that machine-readable evidence of the most recent update be retained. — Expected result: feed update log shows a successful update within the current cycle window. — Capture: feed update log export/screenshot. — Stop/continue: if no update occurred, continue to step 2.
2. If auto-update did not occur, manually trigger a plugin feed update from the Nessus console and verify the new plugin set version and timestamp. — Expected result: plugin feed now shows a current version/timestamp. — Capture: post-update feed version/timestamp screenshot. — Stop/continue: if the manual update also fails, stop and open a ticket in the local ticketing/GRC system before running the next scheduled scan against a stale feed.
3. Confirm the updated plugin set includes coverage for any newly published CVEs or DISA STIG audit file revisions relevant to the environment, cross-checking against the [DoD Cyber Exchange SRG/STIG Library Compilations](https://public.cyber.mil/stigs/compilations/) quarterly update release cycle for the applicable STIG audit files, per the audit-file selection process in the [Tenable Nessus Compliance Checks Reference](https://docs.tenable.com/nessus/compliance-checks-reference/Content/PDF/NessusComplianceChecksReference.pdf). — Expected result: plugin set and STIG audit files are both confirmed current for the environment's applicable platforms. — Capture: comparison notes against the STIG compilation release cycle. — Stop/continue: continue.
4. Re-validate that the compliance/configuration-audit scan policy references the correct, current STIG audit file version in the scan/policy's **Compliance** tab. — Expected result: policy's selected audit file matches the current STIG compilation release. — Capture: policy configuration screenshot. — Stop/continue: if the policy references a superseded audit file, stop and update it through the organization's change-control process before the next scheduled scan.
5. Document the plugin feed version and update timestamp confirmed prior to running the next scheduled scan. — Expected result: documented pre-scan feed-currency confirmation. — Capture: the documentation entry itself. — Stop/continue: continue.
6. Export the plugin update confirmation log and file it in the repository location specified in the Task Index alongside the reviewer's name and date. — Expected result: cycle record filed. — Capture: the exported confirmation log. — Stop/continue: cycle complete.
