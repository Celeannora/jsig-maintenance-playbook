## 5. Procedure

**Pattern C — Update / Patch / Signature Refresh** (assignment from `runbooks/ISSO.md`)

1. Run a Nessus credentialed vulnerability scan against the system, configuring host credentials under the scan/policy's Credentials tab so the scan can log in and evaluate patch/configuration state directly rather than relying on unauthenticated banner checks ([Tenable Nessus User Guide](https://docs.tenable.com/nessus/10_12/Content/PDF/Nessus_10_12.pdf)). Per the [USMC IAVM Program Bulletin](https://www.marines.mil/News/Messages/Messages-Display/Article/889863/mcbul-5239-usmc-information-assurance-vulnerability-management-iavm-program/), this scan must occur at minimum monthly, and any scan used to support a POA&M submission must be no older than 14 days. — Expected result: a completed credentialed scan covering all in-scope hosts. — Capture: the Nessus scan job/results record. — Stop/continue: continue.
2. Export the Nessus scan results and filter findings by IAVM notice number (or equivalent CVE/plugin mapping) to identify open IAVA/IAVB/TA compliance gaps. — Expected result: a complete list of open IAVM-mapped findings, each tagged by severity tier. — Capture: the exported/filtered findings list. — Stop/continue: if any finding maps to a CISA Known Exploited Vulnerabilities (KEV) Catalog entry, note the [BOD 22-01 two-week federal remediation deadline](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-40r4.pdf) and prioritize it ahead of other findings in step 3.
3. Cross-check outstanding IAVM directives against WSUS update deployment status to confirm patches have been pushed to affected hosts. — Expected result: a determination, per finding, of whether the missing patch has already been deployed via WSUS but not yet installed, or has not been deployed at all. — Capture: the WSUS deployment status export. — Stop/continue: continue.
4. Deploy any missing patches via WSUS and re-scan affected hosts with Nessus to confirm remediation (SI-2). — Expected result: the re-scan shows the previously open finding as resolved. — Capture: the WSUS deployment confirmation and Nessus re-scan results. — Stop/continue: if remediation cannot be completed within the directive's compliance window (or, for a KEV-listed vulnerability, within the 2-week BOD 22-01 deadline), stop this finding's remediation path and proceed to step 5.
5. For findings that cannot be remediated within the directive's compliance window, create or update the corresponding POA&M entry per CA-5, assigning a remediation timeline consistent with the finding's severity — the [CMS POA&M Handbook](https://security.cms.gov/learn/cms-plan-action-and-milestones-poam-handbook) documents a representative federal severity-tiered timeline (Critical 15 days / High 30 days / Moderate 90 days / Low 365 days) usable as a baseline absent a more specific organizational SLA. — Expected result: every non-remediated finding has an open POA&M entry with an assigned completion date. — Capture: the POA&M entry ID(s). — Stop/continue: continue.
6. Update the POA&M tracker with revised milestones and residual risk acceptance status for any open items; per the CMS POA&M Handbook's representative cadence, POA&Ms should be reviewed **at least quarterly** even between remediation milestones. — Expected result: the POA&M tracker reflects current milestone and risk-acceptance status for every open item. — Capture: the updated tracker record. — Stop/continue: continue.
7. Export the Nessus rescan report and POA&M update and file them in the repository location specified in the Task Index, alongside the reviewer's name and date. — Expected result: a complete, filed evidence package for the cycle. — Capture: the filed report package. — Stop/continue: cycle complete.
