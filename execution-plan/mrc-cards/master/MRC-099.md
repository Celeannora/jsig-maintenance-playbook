## 5. Procedure

**Pattern B — Manual Review of a List or Log** (underlying pattern; see step detail below for this control's specifics)

1. Pull the current Contingency Plan sections identifying the designated alternate storage site, alternate processing site, and primary/alternate telecommunications service providers, along with the system's BIA-derived RTO/RPO targets ([GSA Contingency Planning Guide](https://www.gsa.gov/system/files/Contingency-Planning-(CP)-%5BCIO-IT-Security-06-29-Rev-7%5D.pdf)). — Expected result: current CP sections and RTO/RPO targets in hand. — Capture: the pulled CP excerpt, with pull date. — Stop/continue: continue.
2. Contact or coordinate a site-readiness check with the alternate storage/processing site to confirm current operational status, physical/environmental safeguards, and data currency of replicated backups against the BIA-derived transfer-frequency requirement. — Expected result: a documented readiness confirmation or list of deficiencies. — Capture: the site-readiness check record/correspondence. — Stop/continue: continue regardless of findings.
3. Verify with the Network Administrator that alternate telecommunications circuits (e.g., backup ISP/carrier links) are provisioned, tested, and free of shared single points of failure with the primary site, supporting the internal/external connectivity readiness that a CP exercise would otherwise test ([NIST SP 800-34 Rev. 1](https://nvlpubs.nist.gov/nistpubs/legacy/sp/nistspecialpublication800-34r1.pdf)). — Expected result: a documented confirmation of circuit status and independence from the primary site's failure modes. — Capture: the telecom verification notes. — Stop/continue: continue.
4. Confirm service agreements/contracts for the alternate site and telecom services remain active and cover the required capacity and priority-of-service provisions. — Expected result: a documented current/expired status for every applicable agreement. — Capture: the contract-status review. — Stop/continue: continue.
5. Document any deficiency (e.g., lapsed contract, untested failover circuit, insufficient distance from primary site) and route corrective actions through the ISSM. — Expected result: every deficiency has a documented corrective-action owner and target date. — Capture: the deficiency list and routing record. — Stop/continue: if a deficiency means the alternate site/telecom path could not actually support recovery within the stated RTO/RPO, stop and escalate immediately per the Escalation block.
6. File the alternate-site and telecom readiness verification report in the contingency planning repository per the Task Index, with reviewer name and date. — Expected result: complete, dated evidence package on file. — Capture: the filed report/location reference. — Stop/continue: cycle complete.
