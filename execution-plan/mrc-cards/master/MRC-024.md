## 5. Procedure

**Pattern A — Automated Monitoring / Scan Confirmation** (assignment from `runbooks/Privileged-Users.md`)

1. Confirm the scheduled weekly-full and daily-incremental backup jobs completed successfully in your backup solution's job console (NetBackup Activity Monitor/Jobs list or Veeam Backup & Replication job **History**) for all in-scope systems, per the [Veritas NetBackup Web UI Administrator's Guide](https://www.veritas.com/support/en_US/doc/150157642-165935937-0/v130722414-165935937) or the [Veeam Backup & Replication User Guide](https://helpcenter.veeam.com/docs/vbr/userguide/session_results_web.html). — Expected result: every in-scope system shows a `Done`/successful job (NetBackup Status `0`) or a green/Success session (Veeam) for both the weekly-full and each daily-incremental job. — Capture: exported job-history/Activity Monitor or Veeam session-history view. — Stop/continue: if any scheduled job did not run at all, stop and open a missed-cycle ticket in the local ticketing/GRC system before proceeding.
2. Review the backup job logs (NetBackup Job Details **Detailed Status** tab or Veeam **Session Details**/Workload View) for failure, warning, or skipped-file entries, noting the affected system and cause for any anomaly. — Expected result: no unexplained non-zero NetBackup status codes or Veeam Warning/Error tasks. — Capture: annotated log excerpt per affected system. — Stop/continue: continue to step 3 regardless of findings; findings are documented, not gated, at this step.
3. Verify backup job configuration (retention, encryption, destination/offsite copy) still matches the approved backup schedule documented in the Contingency Plan, checking the NetBackup policy's Retention Periods host properties or the Veeam backup copy job's Short-Term/GFS retention settings, consistent with the BIA-driven recovery time/recovery point objectives in the [GSA Contingency Planning Guide](https://www.gsa.gov/system/files/Contingency-Planning-(CP)-%5BCIO-IT-Security-06-29-Rev-7%5D.pdf) and the daily/weekly incremental-full backup policy pattern in [NIST SP 800-34 Rev. 1](https://nvlpubs.nist.gov/nistpubs/legacy/sp/nistspecialpublication800-34r1.pdf). — Expected result: configured retention/encryption/offsite settings match the current Contingency Plan. — Capture: screenshot/export of the retention and policy configuration. — Stop/continue: if configuration has drifted from the approved schedule, stop and open a change-control ticket before altering it.
4. Re-run or manually initiate any failed backup job (via the backup solution's job console) and confirm successful completion before closing out the cycle. — Expected result: all previously failed jobs now show successful completion. — Capture: post-rerun job status. — Stop/continue: if a job fails repeatedly, escalate to the backup administrator per the Escalation block below.
5. Verify backup media/storage capacity has sufficient headroom for the next scheduled cycle, checking the backup solution's storage/repository capacity view. — Expected result: available capacity exceeds the next cycle's projected backup size. — Capture: capacity report/screenshot. — Stop/continue: if capacity is insufficient, escalate to the backup administrator/ISSM before the next scheduled cycle runs.
6. Export the backup job completion report and file it in the repository location specified in the Task Index alongside the reviewer's name and date. — Expected result: cycle record filed. — Capture: the consolidated evidence bundle. — Stop/continue: cycle complete.
