## 5. Procedure

**Pattern A — Automated Monitoring / Scan Confirmation** (assignment from `runbooks/Privileged-Users.md`)

1. Run `Get-GPOReport -All -ReportType Html` (or `-Name`/`-Guid` for a targeted GPO) against the domain to identify the GPO enforcing maximum session/re-authentication timeout values, and confirm the configured interval matches the SSP-defined interval for privilege escalation and role changes ([Microsoft Learn gpresult/Get-GPOReport reference](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/gpresult)). — Expected result: the reported GPO session-timeout/reauthentication setting matches the SSP-defined interval. — Capture: the `Get-GPOReport` HTML/XML output. — Stop/continue: continue to step 5 for any mismatch or missing GPO link.
2. Run `auditpol /get /category:*` (or `/subcategory:"Logon","Special Logon"`) to confirm logon/logoff and special-logon audit subcategories are enabled to capture re-authentication events. — Expected result: the Logon, Logoff, and Special Logon audit subcategories all show `Success and Failure` (or the organization's required setting). — Capture: the `auditpol` output. — Stop/continue: continue to step 5 for any subcategory found disabled.
3. Review the Windows Security event log (Event ID 4672 – Special privileges assigned to new logon, 4648 – Logon using explicit credentials, 4778 – Session reconnected) for a sample of privileged sessions to confirm re-authentication is enforced before a privilege change or after the idle threshold. — Expected result: sampled privileged sessions show the expected re-authentication event immediately preceding the privilege change or reconnection. — Capture: the exported event log excerpt for the sampled sessions. — Stop/continue: continue to step 5 for any sampled session missing the expected re-authentication event.
4. Test re-authentication enforcement on a sample account by triggering a privilege-escalation action and confirming a credential prompt occurs per IA-11. — Expected result: the credential prompt is presented and required before the privileged action completes. — Capture: the test record (account, action, timestamp, observed result). — Stop/continue: continue to step 5 if the test account is not prompted.
5. Document and remediate any account or system found bypassing re-authentication via a ticket to the System Administrator. — Expected result: every finding has a tracked remediation ticket. — Capture: the ticket ID(s). — Stop/continue: continue.
6. Export the `Get-GPOReport` output and Security event log excerpt and file them in the repository location specified in the Task Index, alongside the reviewer's name and date. — Expected result: a complete, filed evidence package for the cycle. — Capture: the filed report package. — Stop/continue: cycle complete.
