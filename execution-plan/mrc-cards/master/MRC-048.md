## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/ISSM.md`)

1. In ePO (**Menu | Reporting | Queries**, System Management feature group), generate the current Software/Asset Inventory report across all managed endpoints ([Trellix ePO Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf)). — Expected result: a complete inventory of installed software across every managed endpoint. — Capture: the exported inventory report. — Stop/continue: if the report cannot be generated (ePO unreachable, agents not checking in), stop and open a missed-cycle ticket before proceeding.
2. Compare the inventory against the CCB-approved authorized software whitelist/baseline document. — Expected result: a discrepancy list identifying any software present but not on the approved whitelist. — Capture: the annotated comparison. — Stop/continue: continue regardless of discrepancy count.
3. Check Group Policy-enforced AppLocker or Software Restriction Policy rules via GPMC/`Get-GPOReport` to confirm the technical whitelist enforcement matches the approved list ([Microsoft Learn — gpresult/Get-GPOReport](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/gpresult)). — Expected result: the GPO-enforced rules match the CCB-approved whitelist. — Capture: the `Get-GPOReport` export. — Stop/continue: if enforced rules diverge from the approved whitelist, treat as a finding and continue to step 4.
4. Flag any unauthorized, unapproved, or unlicensed software detected on endpoints and open a CCB ticket for disposition (approve retroactively, remove, or exception). — Expected result: every flagged software item has a CCB ticket and pending disposition. — Capture: the CCB ticket(s). — Stop/continue: if unauthorized software shows signs of malicious intent or unlicensed high-risk use, stop and escalate immediately per the Escalation block below before continuing routine disposition.
5. Coordinate removal of unauthorized software or update of the whitelist/AppLocker policy based on the CCB decision. — Expected result: every disposition is implemented (software removed or whitelist/policy updated). — Capture: the implementation confirmation. — Stop/continue: continue.
6. Export the reconciled software inventory and CCB disposition record, and file them in the repository location specified in the Task Index alongside the reviewer's name and date. — Expected result: a complete, dated, reconciled inventory and disposition record is filed for the cycle. — Capture: the filed inventory, disposition record, and sign-off. — Stop/continue: cycle complete.
