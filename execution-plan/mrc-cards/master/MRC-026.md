## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/ISSO.md`)

1. Pull the current-month Nessus vulnerability scan report and Splunk continuous-monitoring dashboard export covering the system's authorization boundary, consistent with the monthly OS/web-application/database scan cadence in the [FedRAMP Continuous Monitoring Playbook](https://www.fedramp.gov/resources/documents/Continuous_Monitoring_Playbook.pdf) and the monthly "Vulnerability and Configuration Scanning" deliverable row in the [FedRAMP ConMon Deliverables Template](https://www.fedramp.gov/resources/templates/FedRAMP-Continuous-Monitoring-Deliverables-Template.xlsx). — Expected result: complete current-month scan report and dashboard export in hand. — Capture: exported Nessus report and Splunk dashboard export, with pull timestamp. — Stop/continue: if either export is incomplete, stop and remediate the collection gap before reviewing partial data.
2. Generate the current CM-8 component inventory export (e.g., via `Get-ADComputer` plus the ePO **Asset/Software Inventory** query under Menu | Reporting | Queries, System Management feature group, per the [Trellix ePO Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf)) and reconcile it against the authorization boundary diagram, matching the monthly inventory cadence in the [FedRAMP ConMon Deliverables Template](https://www.fedramp.gov/resources/templates/FedRAMP-Continuous-Monitoring-Deliverables-Template.xlsx). — Expected result: inventory export reconciles fully against the boundary diagram, with any discrepancies flagged. — Capture: the inventory export and reconciliation notes. — Stop/continue: continue regardless of discrepancy count; discrepancies are documented, not gated, at this step.
3. Pull the updated POA&M tracker reflecting current open/closed items per the CA-5 review (see [MRC-025](MRC-025.md)). — Expected result: current POA&M export in hand. — Capture: POA&M tracker export. — Stop/continue: continue.
4. Assemble the Nessus report, inventory export, and POA&M into the monthly ConMon package per the format specified in the Continuous Monitoring Strategy. — Expected result: a complete package covering all required current-month deliverables. — Capture: the assembled package. — Stop/continue: if any required deliverable is missing, stop and obtain it before routing the package.
5. Route the assembled package to the ISSM for review and endorsement before submission. — Expected result: ISSM endorsement recorded. — Capture: review/endorsement record. — Stop/continue: if the ISSM identifies a gap, return to step 4 before proceeding.
6. Submit the endorsed ConMon package to the AO/DAO and file the submission record and package contents in the repository location specified in the Task Index alongside the reviewer's name and date. — Expected result: package submitted and cycle record filed. — Capture: the submission record and consolidated evidence bundle. — Stop/continue: cycle complete.
