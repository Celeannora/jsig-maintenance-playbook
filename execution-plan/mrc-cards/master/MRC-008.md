## 5. Procedure

**Pattern A — Automated Monitoring / Scan Confirmation** (assignment from `runbooks/Privileged-Users.md`)

1. Run `manage-bde -status` (or `Get-BitLockerVolume | fl` for a PowerShell-native equivalent) on a sample of in-scope servers/workstations to confirm BitLocker (or equivalent FIPS-validated encryption) is enabled on all data volumes ([Microsoft Learn BitLocker Operations Guide](https://learn.microsoft.com/en-us/windows/security/operating-system-security/data-protection/bitlocker/operations-guide)). Check the **Conversion Status**/`VolumeStatus` field for `Fully Encrypted`/`FullyEncrypted` and **Protection Status**/`ProtectionStatus` for `Protection On`/`On` on every sampled volume. — Expected result: every sampled data volume reports fully encrypted with protection on. — Capture: the `manage-bde -status`/`Get-BitLockerVolume` output for each sampled system. — Stop/continue: continue to step 5 for any volume reporting `Off`, `Suspended`, `Waiting for Activation`, or a conversion status other than fully encrypted.
2. Verify the encryption algorithm/key length configured meets the FIPS 140-2/3 validated module requirement specified in the SSP, reading the **Encryption Method**/`EncryptionMethod` field from the same `manage-bde -status`/`Get-BitLockerVolume` output (e.g. `XtsAes128`/`XTS-AES 128`) ([Microsoft Learn BitLocker Operations Guide](https://learn.microsoft.com/en-us/windows/security/operating-system-security/data-protection/bitlocker/operations-guide)). — Expected result: the configured encryption method matches the SSP-defined FIPS-validated algorithm/key length. — Capture: the annotated encryption-method field from step 1's output. — Stop/continue: continue to step 5 for any mismatch.
3. Check the Group Policy Management Console (or run `gpresult /r` against a sampled system) for the GPO enforcing mandatory drive encryption and confirm it applies to all in-scope OUs ([Microsoft Learn gpresult reference](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/gpresult)). — Expected result: the drive-encryption GPO is linked to, and applying without denial, in every in-scope OU. — Capture: the GPMC scope-of-management view or `gpresult` output. — Stop/continue: continue to step 5 for any OU missing the GPO.
4. Review any exception requests for unencrypted media or systems and confirm each has a documented, CCB-approved compensating control in the local GRC/ticketing/document-repository system. — Expected result: every unencrypted system/volume in scope has either passing encryption status or a CCB-approved exception on file. — Capture: the exception-request records reviewed. — Stop/continue: continue to step 5 for any unencrypted system lacking an approved exception.
5. Document any system found without encryption enabled (and without an approved exception), a non-conforming encryption method, or a GPO gap, and open a remediation ticket with the System Administrator. — Expected result: every finding has a tracked remediation ticket. — Capture: the ticket ID(s). — Stop/continue: continue.
6. Export the `manage-bde`/`Get-BitLockerVolume` status results and GPO report and file them in the repository location specified in the Task Index, alongside the reviewer's name and date. — Expected result: a complete, filed evidence package for the cycle. — Capture: the filed report package. — Stop/continue: cycle complete.
