## 5. Procedure

**Pattern E — Documentation / Policy Review and Update** (underlying pattern; see step detail below for this control's specifics)

1. Pull the current signed Configuration Management Plan (CMP) from the configuration management repository. — Expected result: current CMP version and version history in hand. — Capture: CMP version/date. — Stop/continue: continue.
2. Export the actual current AD Group Policy baseline configuration using `Get-GPOReport` (or `gpresult` for a single-host verification) ([Microsoft Learn — Group Policy Management](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/gpresult)) and pull the current managed-software inventory from the Trellix/McAfee ePO console's Queries & Reports asset/software inventory query ([Trellix ePO Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf)). — Expected result: current, exported baseline-configuration and software-inventory reports. — Capture: the `Get-GPOReport` export and the ePO inventory query export. — Stop/continue: continue.
3. Compare the CMP's documented baseline definitions, CM roles, and change workflow against the exported GPO baseline and ePO software inventory. — Expected result: a documented match/mismatch determination for baseline configuration and installed software. — Capture: the comparison notes. — Stop/continue: continue regardless of findings.
4. Confirm the CMP's listed CCB membership, meeting cadence, and change-approval thresholds still reflect current program staffing and practice. — Expected result: a documented confirmation or list of needed roster/process updates. — Capture: the CCB-roster confirmation notes. — Stop/continue: continue.
5. Identify any gap between documented CM procedures and actual practice (e.g., undocumented approved software, baseline drift) and note required plan updates. — Expected result: a complete gap list (may be empty). — Capture: the gap list. — Stop/continue: continue.
6. Draft CMP revisions addressing identified gaps, or a no-change re-approval memo if the plan remains accurate. — Expected result: draft ready for routing. — Capture: the draft. — Stop/continue: continue.
7. Route the CMP update/re-approval memo through the CCB for review and the ISSM for signature. — Expected result: documented approval or rejection with rationale. — Capture: the signed approval/CCB minutes. — Stop/continue: if rejected, return to step 6; do not publish an unapproved revision.
8. Publish the approved CMP and file it in the configuration management repository per the Task Index, with reviewer name and date. — Expected result: current, approved CMP on file; prior version archived. — Capture: both version files/locations. — Stop/continue: cycle complete.
