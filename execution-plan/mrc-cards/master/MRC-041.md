## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/Information-Owner-Steward.md`)

1. Pull the current PII inventory/system-of-records worksheet from the Privacy GRC or documentation repository, and the prior month's version for comparison. — Expected result: both the current and prior-cycle worksheet versions are in hand, covering the full inventory. — Capture: both worksheet exports, with pull timestamps. — Stop/continue: if the prior-cycle worksheet cannot be located, stop and reconstruct/confirm the last-known-good baseline before proceeding.
2. Query the Information Owner/Steward and System Administrator for any new, modified, or retired data collections, forms, or system holdings containing PII since the last update. — Expected result: a written response (email, ticket, or meeting note) from each queried party confirming changes or no changes. — Capture: the responses themselves. — Stop/continue: continue once all queried parties have responded; escalate a non-response past a reasonable follow-up window to the ISSM.
3. Cross-check any newly onboarded applications or data feeds in the system inventory against the PII holdings list to confirm none were missed. — Expected result: every newly onboarded application/feed is either reflected in the PII inventory or confirmed to hold no PII. — Capture: the cross-check worksheet or notes. — Stop/continue: if an onboarded application handling PII was omitted from the inventory, treat as a finding and continue to step 4 to correct it.
4. Update the PII inventory entries (data elements, authority to collect, storage location, retention period) in the Privacy GRC/documentation repository to reflect all confirmed changes. — Expected result: the inventory reflects the current, complete state of PII holdings. — Capture: the updated inventory file/version. — Stop/continue: continue.
5. Route the updated inventory to the Privacy Officer for review and sign-off. — Expected result: Privacy Officer confirms accuracy and completeness or returns it with correction requests. — Capture: the review record (sign-off or correction notes). — Stop/continue: if corrections are requested, return to step 4 before proceeding.
6. File the signed, dated inventory update in the repository location specified in the Task Index, alongside the reviewer's name and date. — Expected result: a complete, dated, signed-off inventory record is filed for the cycle. — Capture: the filed inventory document and sign-off record. — Stop/continue: cycle complete.
