## 5. Procedure

**Pattern A — Automated Monitoring / Scan Confirmation** (assignment from `runbooks/ISSO.md`)

1. Open the Splunk security dashboard for the system and review the current alert queue for SI-4 monitoring events (IDS/IPS, boundary, and endpoint alerts) using a saved search/scheduled alert over the relevant index(es) ([Splunk Enterprise Alerting Manual](https://help.splunk.com/en/splunk-enterprise/alert-and-respond/alerting-manual/9.1/create-alerts/create-scheduled-alerts)). — Expected result: the scheduled alert's last-run timestamp is within one cycle of due date and the triggered-alerts queue is visible. — Capture: export or screenshot of the dashboard/triggered-alerts view. — Stop/continue: if the scheduled search did not run on cadence, stop and open a missed-cycle ticket in the local ticketing/GRC system before proceeding.
2. Review the ePO Threat Event Log (**Menu | Reporting | Threat Event Log**) for the reporting period for malicious-activity detections requiring analyst triage ([Trellix ePolicy Orchestrator Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf)). — Expected result: no unreviewed threat events older than the cycle window. — Capture: exported Threat Event Log view (sorted/filtered by Event Generated Time). — Stop/continue: continue to step 3 regardless of findings; findings are documented, not gated, at this step.
3. Document analyst disposition (false positive, contained, escalated) for each unresolved Splunk alert and ePO threat event in the SOC ticketing system, using field-value/Boolean SPL queries as needed to correlate related events (e.g. `index=<security_index> (code=* OR status=*) host=<affected_host>`, per [Splunk's search-command syntax reference](https://help.splunk.com/en?resourceId=Splunk_SearchReference_Search&version=splunk-9_4)). — Expected result: every alert/event is dispositioned. — Capture: annotated alert/event list with disposition and rationale. — Stop/continue: if any true positive is CAT I, stop and escalate immediately per the Escalation block below before continuing routine triage.
4. Confirm Splunk data inputs and forwarders for monitored log sources show active, uninterrupted collection with no gaps for the period (spot-check via a raw-event search over the expected sourcetypes/hosts for the cycle window). — Expected result: no unexplained collection gap. — Capture: the verification search results/screenshot. — Stop/continue: if a forwarder/input gap is found, treat it as a finding and continue to step 5.
5. Brief the ISSO on any unresolved or escalated monitoring findings from the period via meeting minutes/decision record in the local GRC/documentation repository. — Expected result: findings and dispositions are communicated and acknowledged. — Capture: the meeting minutes/decision record. — Stop/continue: continue.
6. File the Splunk dashboard export, ePO Threat Event Log export, and meeting minutes in the repository location specified in the Task Index, alongside the reviewer's name and date. — Expected result: a complete, filed evidence package for the cycle. — Capture: the filed report package. — Stop/continue: cycle complete.
