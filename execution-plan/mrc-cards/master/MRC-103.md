## 5. Procedure

**Pattern G — Retention / Disposal** (assignment from `runbooks/ISSM.md`)

1. Pull the current Splunk audit log retention/archival policy configuration (index `frozenTimePeriodInSecs` and archive-bucket settings) for indexes ingesting Windows Security event log and other audit sources, and confirm the configured retention period meets or exceeds the applicable records-schedule figure — 6–7 years per the [IRS Safeguards Audit Requirements](https://www.irs.gov/privacy-disclosure/meeting-irs-safeguards-audit-requirements) and [IRS Publication 1075](https://www.irs.gov/pub/irs-pdf/p1075.pdf) analogs cited for this card. — Expected result: configured retention period is confirmed at or above the applicable NARA/records-schedule figure. — Capture: the index configuration export/screenshot. — Stop/continue: if configured retention is shorter than required, stop and escalate — this is a retention-policy gap, not a routine finding.
2. Run a Splunk search against the archive/frozen bucket index to confirm audit records from the oldest required retention year are still retrievable and have not been prematurely purged. — Expected result: a successful search returning records from the oldest in-scope year. — Capture: the search query and result count/screenshot. — Stop/continue: if no records return for the oldest required year, stop and escalate immediately — potential premature audit-record loss.
3. Verify offline/cold storage media (tape, WORM, or archive storage) holding audit records beyond Splunk's hot/warm retention window is indexed and retrievable, and spot-check one archived record set for integrity. — Expected result: the sampled archived record set opens/restores cleanly and matches expected content. — Capture: the spot-check result and media/location identifier. — Stop/continue: continue.
4. Cross-reference the Splunk `frozenTimePeriodInSecs` value and the archival job schedule against the organization's NARA-approved records disposition schedule to confirm no gap exists. — Expected result: no gap between Splunk's configured retention and the records schedule's required minimum. — Capture: the comparison worksheet. — Stop/continue: continue.
5. Identify any audit record sets that have reached the end of the retention period and route them for authorized disposition per the records schedule. — Expected result: a disposition candidate list (may be empty) routed for authorization. — Capture: the candidate list with each record's age and applicable schedule citation. — Stop/continue: if any candidate is under legal hold, active investigation, or open POA&M/incident reference, remove it from the disposition list and re-check at the next cycle.
6. Document the retention verification results, including Splunk configuration screenshots and sample retrieval evidence, and file them in the audit records repository with the reviewer's name and date. — Expected result: complete, signed cycle package filed. — Capture: the filed verification report. — Stop/continue: cycle complete.
