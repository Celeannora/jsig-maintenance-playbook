## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/ISSM.md`). No reference doc directly states a PM-5 cadence; this card's Monthly frequency is grounded by analogy to CM-8's "review and update the system component inventory at least monthly" requirement ([FedRAMP SSP Appendix A — Moderate Baseline, CM-8.b](https://www.fedramp.gov/resources/templates/SSP-Appendix-A-Moderate-FedRAMP-Security-Controls.docx); [FedRAMP Continuous Monitoring Deliverables Template](https://www.fedramp.gov/resources/templates/FedRAMP-Continuous-Monitoring-Deliverables-Template.xlsx)), the closest documented analogue for inventory-maintenance cadence at this level.

1. Pull the current authoritative organization-wide information system inventory record from the GRC/documentation repository. — Expected result: complete, current inventory record in hand. — Capture: the pulled record, with pull timestamp. — Stop/continue: if the record cannot be located or is stale beyond the prior cycle, stop and resolve the record-management gap before proceeding.
2. Query each subordinate ISSM/system owner for newly authorized, decommissioned, or reclassified systems since the last update. — Expected result: a complete set of responses from every subordinate system owner. — Capture: the query responses/log. — Stop/continue: if a subordinate owner does not respond, escalate the non-response rather than closing the cycle on incomplete input.
3. Cross-check reported system status against active Authorization to Operate (ATO) records and expiration dates for each system. — Expected result: every system's reported status is confirmed against its ATO record. — Capture: the cross-check worksheet. — Stop/continue: continue.
4. Update the inventory record with system name, unique identifier, authorization boundary, ATO status/expiration, and responsible ISSM for each entry. — Expected result: inventory record reflects current state for every system. — Capture: the updated inventory record. — Stop/continue: continue.
5. Flag systems with expired or soon-to-expire ATOs and notify the AO/DAO and Risk Executive Function. — Expected result: every at-risk ATO has been flagged and its owning parties notified. — Capture: notification record. — Stop/continue: if a system's ATO has already expired, escalate immediately per the Escalation block rather than waiting for the next cycle.
6. Reconcile the updated inventory count against the last reported figure and document the reason for any variance. — Expected result: every count variance is explained. — Capture: the variance note. — Stop/continue: continue.
7. Export the updated organization-wide inventory and file it in the repository location specified in the Task Index, alongside the reviewer's name and date. — Expected result: evidence package filed and retrievable for audit. — Capture: the filed export and its repository path. — Stop/continue: cycle complete.
