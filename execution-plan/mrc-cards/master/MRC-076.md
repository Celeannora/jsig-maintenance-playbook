## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/ISSM.md`)

Applies to tasks where a person reviews an existing list, log, or record set against a baseline or policy (e.g., access lists, physical access logs, visitor records, privileged-account lists, audit records). Per [FedRAMP SSP Appendix A (Moderate)](https://www.fedramp.gov/assets/resources/templates/SSP-A13-FedRAMP-Security-Controls-Moderate.docx), MA-3.b requires previously-approved maintenance tools to be reviewed at least annually, matching this card's frequency.

1. Pull the current list of maintenance tools authorized for use on the system (physical and software-based diagnostic/repair tools) from the maintenance tool inventory log or GRC asset repository. — Expected result: complete, unaltered export of the approved-tool list covering the full period since the last review. — Capture: the export file itself, with pull timestamp. — Stop/continue: if the export is incomplete (gap in coverage), stop and remediate the logging/collection gap before reviewing partial data.
2. Physically and/or electronically inspect each listed maintenance tool for unauthorized modification, unapproved software additions, or missing digital signatures/checksums where applicable. — Expected result: an inspection result (pass/flagged) recorded for every tool on the list. — Capture: inspection notes/checklist per tool. — Stop/continue: continue regardless of individual tool result; log any flagged tool as a discrepancy in step 4.
3. Verify that any media associated with maintenance tools (e.g., diagnostic USB drives, boot disks) has been scanned for malicious code prior to use, per the media protection procedure. — Expected result: a documented scan result (clean/flagged) for every piece of removable media associated with a maintenance tool. — Capture: the scan log/record. — Stop/continue: if malicious code is found, stop and quarantine the affected media/tool immediately, then escalate per the Escalation block.
4. Cross-check the maintenance tool inventory against current system administrator records to identify any tools in use that are not on the approved list, and remove or quarantine unapproved tools. — Expected result: a discrepancy list (may be empty) of in-use-but-unapproved tools. — Capture: the annotated comparison. — Stop/continue: if any unapproved tool in active use suggests unauthorized system access, stop and escalate immediately per the Escalation block; otherwise continue.
5. Update the approved maintenance tool list to add newly approved tools or retire decommissioned ones, with justification for each change. — Expected result: updated tool list draft, each change justified. — Capture: the draft list with change rationale. — Stop/continue: continue.
6. Route the updated tool list through the ISSM for review and approval. — Expected result: documented ISSM approval or rejection with rationale. — Capture: approval record. — Stop/continue: if rejected, return to step 5; do not publish an unapproved list.
7. File the signed approved maintenance tool list and inspection notes in the repository location specified in the Task Index with the System Administrator's name and review date. — Expected result: cycle record filed. — Capture: the filed evidence package. — Stop/continue: cycle complete.
