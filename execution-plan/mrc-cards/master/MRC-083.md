## 5. Procedure

**Pattern E — Documentation / Policy Review and Update** (assignment from `runbooks/ISSM.md`)

1. Pull the current Incident Response Plan (IRP) document and compare it against the incident types and alert categories currently configured in Splunk's incident-detection saved searches/correlation rules, using the saved-search/scheduled-alert configuration described in the [Splunk Enterprise Alerting Manual](https://help.splunk.com/en/splunk-enterprise/alert-and-respond/alerting-manual/9.1/create-alerts/create-scheduled-alerts). This review satisfies the **at-least-annual** plan-review requirement in [NIST SP 800-61 Rev. 2 §2.3.2](https://csrc.nist.gov/pubs/sp/800/61/r2/final). — Expected result: a mapping of IRP-documented incident types to configured Splunk detections, with gaps identified. — Capture: current IRP version/date and the Splunk saved-search/alert inventory pulled for comparison. — Stop/continue: continue.
2. Review Splunk's incident/case history for the past cycle to identify any incident types, escalation paths, or notification gaps not currently addressed in the IRP. — Expected result: a list of needed revisions (may be empty). — Capture: the review notes and supporting incident-history export. — Stop/continue: continue regardless of whether revisions are needed — a no-change review still requires documented re-approval.
3. Confirm IRP contact lists, escalation chain, and external reporting requirements (e.g., required breach/incident reporting timelines) are current. — Expected result: contact/escalation/reporting sections confirmed current or flagged for update. — Capture: confirmation notes. — Stop/continue: continue.
4. Draft plan revisions reflecting any organizational, technical, or Splunk detection-capability changes, or a no-change re-approval memo if none are needed. — Expected result: draft (or re-approval memo) ready for routing. — Capture: the draft/memo. — Stop/continue: continue.
5. Route the revised or re-approved IRP through the ISSM for review and the AO/DAO for approval. — Expected result: documented approval or rejection with rationale. — Capture: approval record/signature. — Stop/continue: if rejected, return to step 4; do not publish an unapproved revision.
6. Publish the approved IRP to the documentation repository and notify the IR team and CISO of the update. — Expected result: new version live and stakeholders notified; prior version archived, not deleted. — Capture: both version files/locations and the notification record. — Stop/continue: continue.
7. File the approved plan and approval memo in the repository location specified in the Task Index with the ISSM's name and approval date. — Expected result: cycle record filed. — Capture: the filed plan and approval memo. — Stop/continue: cycle complete.
