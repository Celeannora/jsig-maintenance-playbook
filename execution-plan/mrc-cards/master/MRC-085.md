## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/Privileged-Users.md`)

1. Run `gpresult /r` (or `Get-GPOReport` for a fuller export) against representative domain systems to pull the current Group Policy-enforced service and port configuration, per the RSoP reporting documented in [Microsoft Learn's `gpresult` reference](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/gpresult). — Expected result: a complete, unaltered export of applied GPOs and enforced settings covering the current baseline. — Capture: the `gpresult`/`Get-GPOReport` output file, with pull timestamp. — Stop/continue: if the export is incomplete (gap in coverage), stop and remediate the collection gap before reviewing partial data.
2. Generate a Trellix/McAfee ePO Software/Asset Inventory report via the Queries & Reports engine (Query Builder wizard: **Menu | Reporting | Queries**) to identify all installed applications and running services across managed endpoints, per the [Trellix ePO Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf). — Expected result: a current inventory export of installed applications/services. — Capture: the exported query result (CSV/PDF), with pull timestamp. — Stop/continue: continue.
3. Compare both outputs against the system's approved ports/protocols/services (PPS) baseline in the CCB-approved configuration document to identify unauthorized or unnecessary functions. — Expected result: a discrepancy list of unauthorized/unnecessary ports, protocols, or services (may be empty). — Capture: the annotated comparison. — Stop/continue: continue regardless of discrepancy count.
4. Disable or remove any identified unnecessary services, ports, or protocols via Group Policy or ePO policy enforcement, or submit a CCB exception request if a business need exists. — Expected result: every discrepancy is either remediated or dispositioned with a documented exception. — Capture: change tickets and/or exception requests. — Stop/continue: if any unexplained discrepancy suggests unauthorized access or a compromise indicator rather than routine configuration drift, stop and escalate immediately per the Escalation block.
5. Document findings and remediation actions in a PPS review report, including before/after counts of disabled items. — Expected result: complete review report. — Capture: the PPS review report. — Stop/continue: continue.
6. Route the report through the CCB for review and the ISSM for approval. — Expected result: documented approval or rejection with rationale. — Capture: approval record/signature. — Stop/continue: if rejected, return to step 4.
7. File the signed report in the repository location specified in the Task Index with the System Administrator's name and date. — Expected result: cycle record filed. — Capture: the filed report. — Stop/continue: cycle complete.
