## 5. Procedure

**Pattern C — Update / Patch / Signature Refresh** (assignment from `runbooks/Privileged-Users.md`)

1. Pull the current Nessus scan report's flaw/patch-related findings (missing-patch plugins) for the review month, using the scan's vulnerabilities/findings list per the [Tenable Nessus User Guide](https://docs.tenable.com/nessus/10_12/Content/PDF/Nessus_10_12.pdf). — Expected result: complete list of missing-patch findings for the current month. — Capture: exported findings list. — Stop/continue: continue.
2. Cross-reference the Nessus findings against the WSUS console's Update Status report to identify hosts pending approved patches or reporting deployment failures. — Expected result: every missing-patch finding is matched to a WSUS approval/deployment status. — Capture: annotated Nessus-to-WSUS cross-reference. — Stop/continue: continue.
3. Verify patch deployment compliance percentage against the JSIG-required remediation timeline for critical/high severity flaws, using [CISA's Known Exploited Vulnerabilities Catalog 2-week (BOD 22-01) federal remediation deadline](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-40r4.pdf) as the compliance benchmark for any finding also listed in the KEV Catalog. — Expected result: compliance percentage calculated, with any KEV-listed finding checked against the 2-week deadline. — Capture: compliance calculation and KEV cross-check notes. — Stop/continue: if a KEV-listed finding is past its 2-week deadline, stop and escalate immediately per the Escalation block below.
4. Approve and push any pending patches in WSUS for non-compliant hosts through the organization's change-control process (per `execution-plan/ROLE-CROSSWALK.md`'s CCB routing where the patch is configuration-relevant), and re-scan affected hosts in Nessus to confirm remediation. — Expected result: previously non-compliant hosts show the patch applied and the corresponding Nessus plugin no longer present on rescan. — Capture: WSUS deployment confirmation and Nessus rescan results. — Stop/continue: if a patch cannot be deployed in this cycle (e.g., no approved maintenance window), stop and document the compensating control/interim risk acceptance per `execution-plan/templates/VARIANCE-RISK-ACCEPTANCE-TEMPLATE.md` rather than leaving the gap silently open.
5. Document any patches that cannot be applied on schedule with justification and add them to the POA&M tracker (see [MRC-025](MRC-025.md)). — Expected result: every delayed patch has a documented justification and open POA&M tracking ID. — Capture: POA&M ID(s). — Stop/continue: continue.
6. Export the WSUS Update Status report and Nessus rescan results and file them in the repository location specified in the Task Index alongside the reviewer's name and date. — Expected result: cycle record filed. — Capture: the consolidated evidence bundle. — Stop/continue: cycle complete.
