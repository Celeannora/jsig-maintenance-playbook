## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/Privileged-Users.md`). CM-8 requires the system component inventory to be reviewed and updated **at least monthly** ([FedRAMP SSP Appendix A — Moderate Baseline, CM-8.b](https://www.fedramp.gov/resources/templates/SSP-Appendix-A-Moderate-FedRAMP-Security-Controls.docx); corroborated by the [FedRAMP Continuous Monitoring Deliverables Template](https://www.fedramp.gov/resources/templates/FedRAMP-Continuous-Monitoring-Deliverables-Template.xlsx), which lists the CM-08 Inventory deliverable as Monthly), matching this card's frequency.

1. Run a Trellix/McAfee ePO Asset/Software Inventory report (**Menu | Reporting | Queries**, a System Management / Managed Systems query, or the built-in inventory query types) to pull the current list of managed endpoints and installed software versions ([Trellix ePolicy Orchestrator Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf)). — Expected result: a complete, current export of managed endpoints and installed software. — Capture: the exported query results (CSV/XML/HTML/PDF), with pull timestamp. — Stop/continue: if the export is incomplete (a gap in ePO coverage), stop and remediate the collection gap before reviewing partial data.
2. Run a `Get-ADComputer -Filter * -Properties *` query (or equivalent AD query) to pull the current list of domain-joined system components. — Expected result: a complete, current export of domain-joined computer objects. — Capture: the query output file. — Stop/continue: continue.
3. Compare the ePO and AD outputs against the baseline system component inventory record to identify additions, removals, or discrepancies. — Expected result: a discrepancy list (may be empty) of untracked or missing components. — Capture: the annotated comparison. — Stop/continue: continue regardless of discrepancy count.
4. Verify components flagged in ePO as unmanaged or not communicating are investigated and either re-enrolled or formally removed from inventory. — Expected result: every flagged component is dispositioned (re-enrolled or removed). — Capture: disposition notes per component. — Stop/continue: if an unmanaged/non-communicating component suggests an unauthorized or compromised device, stop and escalate immediately per the Escalation block.
5. Update the authoritative component inventory record with any confirmed additions/removals and note the associated CCB change ticket number for each. — Expected result: inventory record reflects current state with full change traceability. — Capture: the updated inventory record. — Stop/continue: continue.
6. Route inventory updates exceeding baseline scope to the CCB for change-control disposition. — Expected result: every out-of-baseline addition/removal has a CCB disposition (approved, rejected, deferred). — Capture: CCB routing ticket(s). — Stop/continue: continue.
7. Export the reconciled inventory report and file it in the repository location specified in the Task Index, alongside the reviewer's name and date. — Expected result: evidence package filed and retrievable for audit. — Capture: the filed export and its repository path. — Stop/continue: cycle complete.
