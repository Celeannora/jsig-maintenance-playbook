## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/ISSO.md`)

1. Review Windows Security event log and Splunk index access-control lists (ACLs) to confirm only authorized ISSO/audit personnel accounts have read/write/delete permission on audit log stores. — Expected result: only authorized personnel hold access to audit log stores. — Capture: the access-control review notes. — Stop/continue: if an unauthorized account has access, stop and escalate immediately per the Escalation block.
2. Confirm Splunk's index retention and role-based access control configuration prevents modification or deletion of ingested audit data by non-privileged accounts, consistent with the hot/warm/cold/frozen bucket retention lifecycle ([Splunk Enterprise Search/Alerting Manual and index retention documentation](https://help.splunk.com/en/splunk-enterprise/alert-and-respond/alerting-manual/9.1/create-alerts/create-scheduled-alerts)). — Expected result: retention/RBAC configuration confirmed to prevent unauthorized modification or premature deletion. — Capture: the retention/RBAC configuration review notes. — Stop/continue: continue.
3. Check `auditpol /get` on source Windows systems to confirm audit-policy and event-log-clearing events are themselves being logged and forwarded to Splunk. — Expected result: audit-policy-change and log-clearing events are logged and forwarded. — Capture: the `auditpol` output. — Stop/continue: continue.
4. Query Splunk (a saved/scheduled SPL search over the relevant index) for any Event ID 1102 (audit log cleared) or unauthorized access attempts to the audit log storage/directories and investigate any hits ([Splunk Enterprise Search/Alerting Manual and index retention documentation](https://help.splunk.com/en/splunk-enterprise/alert-and-respond/alerting-manual/9.1/create-alerts/create-scheduled-alerts)). — Expected result: no unexplained audit-log-clear or unauthorized-access events found. — Capture: the SPL search results. — Stop/continue: if a hit is found, stop and escalate immediately per the Escalation block — an unexplained cleared audit log is a potential CAT I/II finding.
5. Verify backup/archival of audit logs to a separate protected repository is occurring on schedule per the log-management SOP. — Expected result: audit-log backups/archives are current and complete. — Capture: the backup/archival verification notes. — Stop/continue: continue.
6. Document the access-control and log-integrity verification results and file the report in the repository location specified in the Task Index alongside the ISSO's name and date. — Expected result: cycle record filed. — Capture: the filed verification report. — Stop/continue: cycle complete.
