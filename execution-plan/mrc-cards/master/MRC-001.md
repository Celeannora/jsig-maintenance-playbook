## 5. Procedure

**Pattern A — Automated Monitoring / Scan Confirmation** (assignment from `runbooks/Privileged-Users.md`)

1. Export the current AD-joined device and account roster: run `Get-ADComputer -Filter *` and `Get-ADUser -Filter *` (with the relevant properties, e.g. `Name, OperatingSystem, LastLogonDate`) from a domain-joined management workstation or DC. — Expected result: a complete, current CSV/text export of all AD-joined computer and user objects. — Capture: the exported roster file. — Stop/continue: continue regardless of result.
2. In the ePO console, generate the asset/software inventory report: **Menu | Reporting | Queries**, run (or build via the Query Builder wizard against the **System Management** Feature Group / **Managed Systems** Result Type) the managed-systems inventory query, and export results to CSV ([Trellix ePolicy Orchestrator Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf)). — Expected result: a CSV of installed software/product versions and system properties across all managed endpoints. — Capture: the exported ePO inventory CSV. — Stop/continue: continue.
3. Cross-reference the ePO software inventory and the AD roster against the CM-8 authorized baseline/hardware-software list to identify unauthorized or missing components. — Expected result: a reconciled diff list (present-but-unauthorized, authorized-but-missing, or matched). — Capture: the reconciliation worksheet. — Stop/continue: if any unauthorized component is found, continue to step 4 before closing the cycle.
4. Query ePO Policy Compliance data (**Menu | Reporting | Queries**, Policy Management Feature Group — Applied Policies / Broken Inheritance / compliance queries per the [Trellix ePolicy Orchestrator Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf)) for any user-installed software not on the approved application allowlist per CM-11. — Expected result: a list of any non-compliant endpoints/software. — Capture: the exported Policy Compliance query results. — Stop/continue: continue.
5. Open a CCB change ticket in the local GRC/ticketing system for any unauthorized software or hardware found in steps 3–4, and track it to removal or formal approval. — Expected result: every finding has a CCB tracking ID. — Capture: the ticket ID(s). — Stop/continue: continue.
6. Update the system component inventory baseline in the configuration management database with the reconciled results — per [NIST SP 800-40 Rev. 4](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-40r4.pdf), inventories should be constantly/continuously maintained rather than refreshed only on a monthly/quarterly scan cycle, consistent with this task's Continuous frequency. — Expected result: the CMDB/baseline record reflects the current reconciled inventory. — Capture: the updated baseline record or its change log entry. — Stop/continue: continue.
7. Export the reconciliation report (AD roster + ePO inventory/compliance exports + CCB ticket references) and file it in the repository location specified in the Task Index, alongside the reviewer's name and date. — Expected result: a complete, filed evidence package for the cycle. — Capture: the filed report package. — Stop/continue: cycle complete.
