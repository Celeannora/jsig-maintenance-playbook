## 5. Procedure

**Pattern D — Test / Exercise** (assignment from `runbooks/ISSM.md`)

Applies to tasks that execute a planned test against a written procedure (e.g., backup restoration, contingency plan exercise, incident response exercise, information system recovery/reconstitution, fire-suppression test). Per the [GSA Contingency Planning Guide](https://www.gsa.gov/system/files/Contingency-Planning-(CP)-%5BCIO-IT-Security-06-29-Rev-7%5D.pdf) and [NIST SP 800-34 Rev.1](https://nvlpubs.nist.gov/nistpubs/legacy/sp/nistspecialpublication800-34r1.pdf), the CP must be exercised/tested at least annually (announced or unannounced), and for low-impact systems a yearly tabletop exercise covering notification procedures, alternate-platform recovery, connectivity, and reconstitution is sufficient.

1. Schedule and conduct the annual contingency plan exercise (tabletop walkthrough or functional recovery test) per the test plan defined in the current Contingency Plan. — Expected result: current test plan in hand, version confirmed, exercise scheduled per the [GSA CP Guide](https://www.gsa.gov/system/files/Contingency-Planning-(CP)-%5BCIO-IT-Security-06-29-Rev-7%5D.pdf)'s at-least-annual cadence. — Capture: test plan version/date and exercise schedule. — Stop/continue: if no current approved plan exists, stop — do not improvise an untested procedure; escalate the missing-plan gap first.
2. Execute the defined recovery procedure against a test/non-production target, restoring a representative server or dataset using your backup solution's recovery tooling (the NetBackup Recovery wizard's Regular recovery workflow, or Veeam's SureBackup full-recoverability test in an isolated virtual lab — see the [NetBackup Web UI Administrator's Guide](https://www.veritas.com/support/en_US/doc/150157642-165935937-0/v130722414-165935937) and the [Veeam Backup & Replication User Guide](https://helpcenter.veeam.com/docs/vbr/userguide/session_results_web.html) respectively) to verify the documented recovery steps and RTO/RPO are achievable. — Expected result: every planned step executed with a recorded actual result; restore job completes with a success status (NetBackup job status `0`, or a Veeam SureBackup pass). — Capture: step-by-step execution log plus the restore/SureBackup job report. — Stop/continue: if a step fails in a way that risks the production environment, stop the test immediately and document the abort point.
3. Record test participants, start/end times, each procedural step executed, and any deviations or failures encountered during the exercise. — Expected result: pass/fail determination against the plan's overall success criteria. — Capture: the comparison and determination. — Stop/continue: continue regardless of outcome.
4. Identify corrective actions for any step that failed or exceeded the target recovery time, and log them as findings with assigned owners and due dates. — Expected result: every gap has a tracking ID and owner. — Capture: POA&M ID(s). — Stop/continue: continue.
5. Update the Contingency Plan to reflect lessons learned and corrected procedures based on the test results. — Expected result: CP updated where the test surfaced a procedural error, consistent with the Lessons-Learned convention in [NIST SP 800-34 Rev.1](https://nvlpubs.nist.gov/nistpubs/legacy/sp/nistspecialpublication800-34r1.pdf). — Capture: the updated CP section(s). — Stop/continue: continue.
6. Brief the ISSM and ISSO on test outcomes and obtain ISSM sign-off on the after-action report. — Expected result: AAR reviewed and signed. — Capture: the signed AAR file. — Stop/continue: continue.
7. File the signed after-action report, test log, and any CP updates in the repository location specified in the Task Index with the test date and ISSM's name. — Expected result: complete cycle package filed. — Capture: filed package. — Stop/continue: cycle complete.
