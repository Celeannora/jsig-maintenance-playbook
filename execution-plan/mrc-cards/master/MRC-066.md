## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/Privileged-Users.md`)

1. Open the ePO console (Menu > Reporting > Queries & Reports) and run the anti-spam/email-gateway module's policy compliance query for all managed endpoints/mail relays ([Trellix ePolicy Orchestrator Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf)). — Expected result: a complete policy-compliance report covering every managed endpoint/relay in scope. — Capture: the exported report (CSV/PDF). — Stop/continue: if coverage is incomplete (systems missing from the report), stop and remediate the agent/reporting gap before proceeding.
2. Confirm spam-filter signature/definition versions are current by running the ePO DAT/engine signature-version compliance query and comparing results against vendor release dates ([Trellix ePolicy Orchestrator Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf)). — Expected result: all managed systems report a current DAT/engine version, or every out-of-date system is identified. — Capture: the query output. — Stop/continue: continue; flag out-of-date systems for step 5.
3. Query the ePO Threat Event Log (Menu > Reporting > Threat Event Log) or the Splunk mail-gateway index for spam-detection events over the review period and verify quarantine/block actions were correctly applied ([Trellix ePolicy Orchestrator Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf)). — Expected result: a complete event list with disposition (quarantined/blocked) per detection. — Capture: the event log export. — Stop/continue: continue.
4. Sample a set of quarantined messages to confirm no false-positive legitimate mail was blocked, and confirm (via user report or help-desk ticket review) that no spam reached end-user inboxes undetected. — Expected result: sample shows correct disposition with no confirmed false positives/negatives, or every exception is documented. — Capture: the sample review worksheet. — Stop/continue: continue; log every exception for step 5.
5. Run a Nessus compliance/audit-file scan against the mail relay/gateway configuration to confirm anti-spam settings meet the applicable STIG baseline ([Tenable Nessus User Guide](https://docs.tenable.com/nessus/10_12/Content/PDF/Nessus_10_12.pdf)). — Expected result: a compliance scan result showing pass/fail per STIG check. — Capture: the Nessus compliance scan report/XCCDF export. — Stop/continue: if the scan surfaces a failed check indicating spam protection is disabled or misconfigured, stop and escalate immediately per the Escalation block.
6. Export the ePO policy compliance report, Threat Event Log/Splunk query results, and Nessus compliance scan report, and file them in the repository location specified in the Task Index, alongside the reviewer's name and date. — Expected result: complete evidence package filed for the cycle. — Capture: the filed reports. — Stop/continue: cycle complete.
