## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/ISSO.md`)

1. Pull the current inventory of publicly accessible information systems/pages (public-facing web servers, portals, or shared content areas) in scope. — Expected result: a complete inventory covering all currently published public-facing systems/pages. — Capture: the inventory, with pull timestamp. — Stop/continue: if the inventory is incomplete, stop and reconcile it before reviewing partial data.
2. Review the designated content-approval workflow records to confirm all currently published public content has a documented authorization/review sign-off. — Expected result: every published item has a matching approval record. — Capture: the approval-record cross-reference notes. — Stop/continue: continue, flagging any unapproved item as a finding.
3. Manually inspect the live public-facing content (or use a web-content/vulnerability scan tool, e.g. a Tenable Nessus scan configured against the public-facing hosts, per the general credentialed/compliance scanning capability described in the [Tenable Nessus User Guide](https://docs.tenable.com/nessus/10_12/Content/PDF/Nessus_10_12.pdf)) to check for inadvertent exposure of nonpublic, CUI, or classified information. — Expected result: no nonpublic/CUI/classified information found exposed. — Capture: the inspection notes or scan report. — Stop/continue: if sensitive information is found exposed, stop and escalate immediately per the Escalation block rather than waiting for normal ticket routing.
4. Remove or request removal of any unauthorized or sensitive content discovered and document the corrective action. — Expected result: all unauthorized/sensitive content is removed or removal is requested. — Capture: the corrective-action ticket/record. — Stop/continue: continue.
5. Confirm the personnel authorized to post to the public-facing system are current by cross-checking against `Get-ADGroupMember` output for the publishing role/group. — Expected result: the publishing-authorization list matches current, active personnel only. — Capture: the `Get-ADGroupMember` output. — Stop/continue: continue, documenting any account removal needed as a routine finding.
6. File the review findings, corrective actions, and the reviewed content inventory in the repository location specified in the Task Index alongside the ISSO's name and date. — Expected result: cycle record filed. — Capture: the filed findings package. — Stop/continue: cycle complete.
