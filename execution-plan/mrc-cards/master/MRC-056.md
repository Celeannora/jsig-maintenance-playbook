## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/ISSO.md`)

1. Export the current firewall/boundary-device rule base covering access-enforcement and information-flow rules, e.g. via `Get-NetFirewallRule` combined with the matching filter cmdlet (`Get-NetFirewallPortFilter`, `Get-NetFirewallApplicationFilter`) in Windows Defender Firewall with Advanced Security, or the perimeter firewall's config export ([Microsoft Learn — Windows Defender Firewall with Advanced Security command-line reference](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/configure-with-command-line)). — Expected result: a complete current rule-base export. — Capture: the exported rule set, with pull timestamp. — Stop/continue: if the export is incomplete, stop and remediate the collection gap before reviewing partial data.
2. Run `Get-ADGroupMember` and `Get-ADUser` against the access-control groups referenced in the rule set to confirm rule assignments still map to authorized, active accounts/roles. — Expected result: every group/role referenced by a rule maps to current, active personnel. — Capture: the group-membership export. — Stop/continue: continue.
3. Review the rule set for overly permissive entries (e.g. any-any rules, unused legacy rules) and compare against the approved firewall rule justification/change-request records — using `Get-NetIPsecRule -TracePolicyStore` where needed to confirm whether a given rule originates from the intended GPO versus local policy ([Microsoft Learn — Windows Defender Firewall with Advanced Security command-line reference](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/configure-with-command-line)). — Expected result: a discrepancy list of overly permissive or unjustified rules (may be empty). — Capture: the annotated rule review. — Stop/continue: continue regardless of discrepancy count.
4. Validate flow-enforcement boundaries (e.g. VLAN/security zone segmentation, data-flow labels) against the current network architecture diagram to confirm no unauthorized cross-domain paths exist. — Expected result: no unauthorized cross-domain flow path identified. — Capture: the validation notes. — Stop/continue: if an unauthorized cross-domain path is found, stop and escalate immediately per the Escalation block.
5. Submit any required rule changes through the CCB change-request process and document the ticket number. — Expected result: every required change has an associated CCB ticket. — Capture: the CCB ticket number(s). — Stop/continue: continue.
6. Export the validated rule set and file it in the repository location specified in the Task Index alongside the reviewer's name and date. — Expected result: cycle record filed. — Capture: the filed validated rule set. — Stop/continue: cycle complete.
