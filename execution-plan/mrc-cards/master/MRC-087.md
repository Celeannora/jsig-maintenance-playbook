## 5. Procedure

**Pattern E — Documentation / Policy Review and Update** (assignment from `runbooks/ISSM.md`)

1. Pull the current System Security Plan (SSP) from the GRC/documentation repository and compare its control implementation statements against the current authorization boundary, system architecture diagrams, and POA&M items. — Expected result: current SSP version and a list of any boundary/architecture/POA&M deltas in hand. — Capture: SSP version/date and the comparison notes. — Stop/continue: continue.
2. Interview or coordinate with system owners and ISSOs to identify any hardware, software, network, or mission changes since the last SSP update. — Expected result: a documented list of changes since the last cycle (may be empty). — Capture: interview/coordination notes. — Stop/continue: continue regardless of whether changes are found — a no-change review still requires documented re-approval.
3. Update control implementation descriptions, system boundary diagrams, and interconnection details in the SSP to reflect current state, or draft a no-change re-approval memo if the system is unchanged. — Expected result: draft SSP revision or re-approval memo ready for routing. — Capture: the draft/memo. — Stop/continue: continue.
4. Reconcile the SSP's control baseline against the latest JSIG/NIST SP 800-53 Rev.4 tailoring guidance (`reference/JSIG/control-families/` in this repository) to confirm no applicable controls are missing. — Expected result: confirmed complete control baseline, or a documented gap list. — Capture: the reconciliation notes. — Stop/continue: continue.
5. Route the updated SSP through the ISSO for technical review and the AO/DAO for formal approval/re-authorization. — Expected result: documented approval or rejection with rationale. — Capture: approval record/signature. — Stop/continue: if rejected, return to step 3; do not publish an unapproved revision.
6. Publish the approved SSP version to the GRC repository, superseding the prior version. — Expected result: new version live, prior version archived, not deleted. — Capture: both version files/locations. — Stop/continue: continue.
7. File the approved SSP and approval record in the repository location specified in the Task Index with the ISSM's name and date. — Expected result: cycle record filed. — Capture: the filed SSP and approval record. — Stop/continue: cycle complete.
