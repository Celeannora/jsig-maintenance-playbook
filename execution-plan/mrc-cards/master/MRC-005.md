## 5. Procedure

**Pattern A — Automated Monitoring / Scan Confirmation** (assignment from `runbooks/Privileged-Users.md`)

1. Run `Get-ADGroupMember` against each privileged AD security group (e.g. Domain Admins, Enterprise Admins, and any organization-defined privileged-role groups) to verify current membership matches the approved access list (AC-6). — Expected result: every member of every privileged group is on the approved list; no unexplained additions. — Capture: the exported group-membership listing. — Stop/continue: continue to step 5 for any unapproved member found.
2. Run `gpresult /r` (or `/h` for an HTML report) against a sample of workstations/servers to confirm the GPO enforcing session lock timeout and screen-lock policy is applied (AC-11), reviewing the applied-GPOs list and any denied GPOs with their denial reason ([Microsoft Learn gpresult reference](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/gpresult)). For a point-in-time audit record of the GPO's actual configured settings, also pull `Get-GPOReport -Name <SessionLockGPO> -ReportType HTML` ([Microsoft Learn Get-GPOReport reference](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/gpresult)). — Expected result: the sampled systems show the session-lock GPO applied (not denied/filtered out), with a timeout value matching the SSP-defined interval. — Capture: the gpresult output and Get-GPOReport export for the sampled systems. — Stop/continue: continue to step 5 for any system showing the GPO missing, denied, or misconfigured.
3. Review Local Security Policy / Security Configuration and Analysis snap-in settings for session termination thresholds on the sampled systems and confirm they match the SSP-defined values (AC-12). — Expected result: sampled systems' session-termination settings match the SSP. — Capture: the snap-in export or screenshot for each sampled system. — Stop/continue: continue to step 5 for any mismatch.
4. Query `auditpol /get /category:*` (or the relevant subcategories) to confirm access-enforcement-related audit subcategories (logon, privilege use, object access) are enabled per AC-3. — Expected result: the required audit subcategories show "Success and Failure" (or the organization-defined auditing level) enabled. — Capture: the auditpol output. — Stop/continue: continue to step 5 for any subcategory found disabled.
5. Identify any account with excess privilege, stale group membership, a missing/misconfigured session-lock GPO, a session-termination mismatch, or a disabled required audit subcategory, and submit a remediation ticket to the System Administrator in the local ticketing/GRC system. — Expected result: every finding has a tracking ticket. — Capture: the ticket ID(s). — Stop/continue: continue.
6. Export the `Get-ADGroupMember`, `gpresult`/`Get-GPOReport`, Local Security Policy, and `auditpol` outputs and file them in the repository location specified in the Task Index, alongside the reviewer's name and date. — Expected result: a complete, filed evidence package for the cycle. — Capture: the filed report package. — Stop/continue: cycle complete.
