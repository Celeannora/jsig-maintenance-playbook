## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/ISSO.md`)

1. Run the Splunk saved search against the Windows Security event log index covering the review week, filtering for Event IDs 4624/4625 (logon), 4720/4726 (account changes), 4732/4756 (privileged group changes), and 4688 (process creation), using field-value and Boolean syntax (e.g. `EventCode IN (4624,4625,4720,4726,4732,4756,4688)`) per the [Splunk Search Reference](https://help.splunk.com/en?resourceId=Splunk_SearchReference_Search&version=splunk-9_4). — Expected result: complete result set covering the full week since the last review, with no index/collection gaps. — Capture: exported search results with pull timestamp. — Stop/continue: if the export shows a coverage gap (missing days/hosts), stop and remediate the logging/collection gap before reviewing partial data.
2. Review the Splunk audit-review dashboard (a scheduled alert or saved search configured per the [Splunk Alerting Manual](https://help.splunk.com/en/splunk-enterprise/alert-and-respond/alerting-manual/9.1/create-alerts/create-scheduled-alerts)) for any triggered correlation alerts from the review period. — Expected result: every triggered alert for the week is listed. — Capture: dashboard/alert export. — Stop/continue: continue to step 3 regardless of alert count.
3. Triage each flagged event and alert as benign, expected, or requiring escalation, cross-checking anomalies (e.g., after-hours privileged logons, repeated failed authentications) against the current access roster via `Get-ADGroupMember` for sensitive groups. — Expected result: every flagged event/alert is dispositioned. — Capture: annotated disposition list with analyst name and rationale. — Stop/continue: if any disposition indicates unauthorized access or privilege escalation, stop and escalate immediately per the Escalation block before continuing routine triage.
4. Document findings and dispositions for each flagged event in the weekly audit review log, noting analyst name and resolution. — Expected result: every finding has a documented resolution. — Capture: the weekly audit review log entry. — Stop/continue: continue.
5. Escalate any unresolved or suspicious findings to the ISSM per the incident-handling procedure. — Expected result: unresolved findings have an open escalation record. — Capture: escalation ticket/notification record. — Stop/continue: continue.
6. Export the Splunk search results and disposition log and file them in the repository location specified in the Task Index alongside the reviewer's name and date. — Expected result: cycle record filed. — Capture: the consolidated evidence bundle. — Stop/continue: cycle complete.
