## 5. Procedure

**Pattern E — Documentation / Policy Review and Update** (underlying pattern; see step detail below for this control's specifics)

1. Pull the current Privacy Impact Assessment (PIA) on file for the system from the privacy documentation repository. — Expected result: current PIA version and version history in hand. — Capture: PIA version/date. — Stop/continue: continue.
2. Compare the PIA's data-collection, use, and sharing descriptions against the current SSP data flow diagrams and any new PII-processing functionality added since the last PIA cycle. — Expected result: a list of needed revisions (may be empty). — Capture: the comparison/review notes. — Stop/continue: continue regardless of whether revisions are needed — a no-change review still requires documented re-certification.
3. Interview the Information Owner/Steward to identify any new or discontinued PII collection points, storage locations, or third-party disclosures. — Expected result: a confirmed, current picture of PII collection/use/sharing. — Capture: interview notes. — Stop/continue: continue.
4. Update the PIA sections affected (data elements collected, purpose, retention, access controls, sharing arrangements), or draft a no-change certification memo if no material change occurred. — Expected result: draft ready for routing. — Capture: the draft PIA update or certification memo. — Stop/continue: continue.
5. Route the updated PIA (or no-change certification) through the ISSM for security-control concurrence and the Information Owner/Steward for signature. — Expected result: documented approval or rejection with rationale. — Capture: the signed approval record. — Stop/continue: if rejected, return to step 4; do not publish an unapproved PIA revision.
6. Publish the approved PIA update and file it in the privacy program repository per the Task Index, with reviewer name and date. — Expected result: current, approved PIA on file; prior version archived. — Capture: both version files/locations. — Stop/continue: cycle complete.
