## 5. Procedure

**Pattern D — Test / Exercise** (assignment from `runbooks/SCA.md`)

Applies to tasks that execute a planned test against a written procedure (e.g., backup restoration, contingency plan exercise, incident response exercise, information system recovery/reconstitution, fire-suppression test).

1. Develop or update the Security Assessment Plan identifying the controls in scope for this cycle's independent assessment, consistent with the system's control baseline. — Expected result: current, approved assessment plan in hand, version confirmed. — Capture: assessment plan version/date and control scope list. — Stop/continue: if no current approved plan exists, stop — do not improvise an untested procedure; escalate the missing-plan gap first.
2. Execute a credentialed Tenable Nessus vulnerability/compliance scan against the in-scope hosts using the appropriate DISA STIG audit file (selected on the scan's **Compliance** tab per the [Tenable Nessus User Guide](https://docs.tenable.com/nessus/10_12/Content/PDF/Nessus_10_12.pdf)), and export the scan results report (JSON or XCCDF compliance export). — Expected result: completed scan with a Compliant/Non-Compliant/Inconclusive determination per host and a downloadable results export. — Capture: the exported scan results file(s). — Stop/continue: if the scan cannot complete (credential failure, unreachable hosts), stop and remediate scan access before proceeding to manual assessment steps.
3. Conduct manual control assessment procedures (interview, examine, test) for controls not verifiable via automated scanning, documenting evidence for each control's Assessment Objective. — Expected result: every planned step executed with a recorded actual result. — Capture: step-by-step examination/interview notes and supporting evidence. — Stop/continue: if a step would require touching a production system in a way that risks it, stop and follow the organization's standard change-control/maintenance-window process first.
4. Cross-reference Splunk continuous-monitoring dashboards or a scheduled saved search/alert (per the [Splunk Enterprise Alerting Manual](https://help.splunk.com/en/splunk-enterprise/alert-and-respond/alerting-manual/9.1/create-alerts/create-scheduled-alerts)) for relevant log-based evidence (e.g., audit logging, account management activity) supporting the controls under review — and, if a CP-9 (System Backup) control is in scope, cross-check backup-job history in your backup solution's console (NetBackup Activity Monitor/Jobs list or Veeam Backup & Replication job History, per the [NetBackup Web UI Administrator's Guide](https://www.veritas.com/support/en_US/doc/150157642-165935937-0/v130722414-165935937) and [Veeam Backup & Replication User Guide](https://helpcenter.veeam.com/docs/vbr/userguide/session_results_web.html)) as supporting evidence. — Expected result: pass/fail determination for each control supported by log or backup-job evidence where applicable. — Capture: the comparison/determination and exported dashboard or job-history evidence. — Stop/continue: continue regardless of outcome.
5. Document assessment results, findings, and residual risk in a Security Assessment Report (SAR), assigning a satisfied/not-satisfied determination per control. — Expected result: SAR document with a determination for every in-scope control. — Capture: the SAR file. — Stop/continue: continue.
6. Deliver the SAR to the ISSM and AO/DAO with any recommended Plan of Action and Milestones (POA&M) entries for unsatisfied controls, sized using a defensible severity-to-timeline convention (e.g., the [CMS POA&M Handbook](https://security.cms.gov/learn/cms-plan-action-and-milestones-poam-handbook)'s Critical/High/Moderate/Low tiers) where the organization has not defined its own. — Expected result: every gap has a tracking ID, severity, and target remediation date. — Capture: POA&M ID(s) and severity ratings. — Stop/continue: continue.
7. File the signed SAR, supporting Nessus scan exports, and POA&M updates in the repository location specified in the Task Index with the SCA's name and assessment date. — Expected result: complete cycle package filed. — Capture: filed package. — Stop/continue: cycle complete.
