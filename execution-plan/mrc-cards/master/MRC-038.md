## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/Privileged-Users.md`). MA-4 requires organizations to maintain records of nonlocal maintenance/diagnostic activity, use strong authentication for such sessions, and terminate sessions/connections on completion ([FedRAMP SSP Appendix A — Moderate Baseline, MA-4](https://www.fedramp.gov/resources/templates/SSP-Appendix-A-Moderate-FedRAMP-Security-Controls.docx)); NIST SP 800-137 identifies MA-4 nonlocal-maintenance records as a control whose CA-7 monitoring frequency should increase when risk assessment flags related threats/vulnerabilities ([NIST SP 800-137](https://nvlpubs.nist.gov/nistpubs/legacy/sp/nistspecialpublication800-137.pdf)).

1. Run a Splunk saved search (**Search and Reporting** app, scheduled as a report or alert per Splunk's standard scheduling mechanism) against VPN/remote-access and jump-server logs to pull all nonlocal (remote) maintenance sessions for the review month ([Splunk Enterprise — Scheduled Alerts and SPL Search Syntax](https://help.splunk.com/en/splunk-enterprise/alert-and-respond/alerting-manual/9.1/create-alerts/create-scheduled-alerts)). — Expected result: a complete list of nonlocal maintenance sessions for the full review month. — Capture: the search results export, with search string and time range noted. — Stop/continue: if the search returns a coverage gap (e.g., a log source known to be active shows no events), stop and remediate the logging gap before reviewing partial data.
2. Verify each session record includes date/time, maintenance personnel identity, systems accessed, and business justification/ticket reference. — Expected result: every session record is complete against this field set. — Capture: the annotated session list noting any incomplete records. — Stop/continue: continue regardless of completeness findings, but flag incomplete records as findings.
3. Confirm each nonlocal maintenance session was authorized in advance per the maintenance request/change ticket and used an approved encrypted remote-access method (e.g., VPN with MFA) — consistent with MA-4's requirement to employ strong authenticators for nonlocal maintenance sessions ([FedRAMP SSP Appendix A — Moderate Baseline, MA-4.c](https://www.fedramp.gov/resources/templates/SSP-Appendix-A-Moderate-FedRAMP-Security-Controls.docx)). — Expected result: every session is matched to an authorization ticket and an approved access method. — Capture: the cross-reference worksheet. — Stop/continue: if any session lacks prior authorization, stop and escalate immediately per the Escalation block.
4. Check session termination logs to confirm sessions were properly closed and remote-access accounts disabled/expired after completion — MA-4 requires terminating session and network connections when nonlocal maintenance is completed ([FedRAMP SSP Appendix A — Moderate Baseline, MA-4.e](https://www.fedramp.gov/resources/templates/SSP-Appendix-A-Moderate-FedRAMP-Security-Controls.docx)). — Expected result: every session shows a clean, timely termination. — Capture: the termination-log excerpt. — Stop/continue: if a session shows an open/lingering connection, stop and escalate immediately.
5. Cross-reference session activity against the Splunk continuous-monitoring dashboard (CA-7) to confirm no unauthorized commands or lateral movement occurred during the session. — Expected result: no unauthorized activity correlated to any session. — Capture: the correlation search results. — Stop/continue: if unauthorized activity is found, stop and escalate immediately per the Escalation block.
6. Escalate any unauthorized or unlogged nonlocal maintenance session to the ISSM/ISSO for investigation. — Expected result: every anomaly has an assigned investigation owner. — Capture: escalation ticket. — Stop/continue: continue.
7. Export the Splunk nonlocal-maintenance session report and file it in the repository location specified in the Task Index, alongside the reviewer's name and date. — Expected result: evidence package filed and retrievable for audit. — Capture: the filed export and its repository path. — Stop/continue: cycle complete.
