## 5. Procedure

**Pattern B — Manual Review of a List or Log** (assignment from `runbooks/ISSO.md`). No reference doc on file addresses AR-4/privacy-monitoring specifics (SORN, PIA); the steps below follow general defensible privacy-compliance practice, with only the Splunk search mechanics grounded to a reference source ([Splunk Enterprise Admin/Alerting Manual](https://help.splunk.com/en/splunk-enterprise/alert-and-respond/alerting-manual/9.1/create-alerts/create-scheduled-alerts)).

1. Run a Splunk saved search/dashboard against systems processing PII to identify access, export, and query events involving privacy-designated data fields for the review month ([Splunk Enterprise — Scheduled Alerts and SPL Search Syntax](https://help.splunk.com/en/splunk-enterprise/alert-and-respond/alerting-manual/9.1/create-alerts/create-scheduled-alerts)). — Expected result: a complete list of PII access/export/query events for the full review month. — Capture: the search results export, with search string and time range noted. — Stop/continue: if the search returns a coverage gap (a known PII-processing system shows no events), stop and remediate the logging gap before reviewing partial data.
2. Compare identified access/export events against the approved user list authorized for PII access per the Privacy Impact Assessment (PIA). — Expected result: every access/export event is matched to an authorized user. — Capture: the cross-reference worksheet. — Stop/continue: if any event involves an unauthorized user, stop and escalate immediately per the Escalation block.
3. Review data loss prevention or file-transfer logs for any bulk export of PII to removable media or external destinations. — Expected result: no unauthorized bulk export identified, or every bulk export is matched to an approved business purpose. — Capture: the DLP/file-transfer log excerpt. — Stop/continue: if an unapproved bulk export is found, stop and escalate immediately.
4. Cross-check any flagged anomalous access against open incident tickets to confirm privacy incidents were properly reported per breach-notification procedures. — Expected result: every anomaly is either linked to an existing incident ticket or newly ticketed. — Capture: the ticket cross-reference. — Stop/continue: if a privacy incident was not reported per procedure, stop and escalate immediately.
5. Verify the System of Records Notice (SORN) and PIA remain current for the systems audited and note any needed updates. — Expected result: SORN/PIA currency confirmed or update need identified. — Capture: the currency-check notes. — Stop/continue: continue.
6. Brief the Privacy Officer and Information Owner/Steward on findings and required corrective actions. — Expected result: findings and corrective actions have been briefed to both roles. — Capture: briefing record/notes. — Stop/continue: continue.
7. Export the Splunk privacy-monitoring report and file it in the repository location specified in the Task Index, alongside the reviewer's name and date. — Expected result: evidence package filed and retrievable for audit. — Capture: the filed export and its repository path. — Stop/continue: cycle complete.
