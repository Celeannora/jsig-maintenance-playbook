## 5. Procedure

**Pattern A — Automated Monitoring / Scan Confirmation** (assignment from `runbooks/Privileged-Users.md`)

1. Open the ePO console and pull the **Threat Event Log** (Menu | Reporting | Threat Event Log) filtered to the review week to confirm on-demand and on-access scans completed on all managed endpoints, per the [Trellix ePolicy Orchestrator Product Guide](http://b2b-download.trellix.com/PRODUCTS/naibeta-download/epo_460/previous%20postings/epo_460_beta2_productguide.pdf). — Expected result: scan-completion events are present for all in-scope endpoints within the weekly window, consistent with the [FedRAMP Tailored SI-3 "at least weekly" scan-frequency guidance](https://github.com/GSA/fedramp-tailored/blob/master/_guidance/controls/SI-3.md). — Capture: exported Threat Event Log (CSV/PDF). — Stop/continue: if an endpoint shows no scan event for the period, continue to step 2 but flag it for remediation.
2. Run the ePO **Policy Compliance** query (Menu | Reporting | Queries, Policy Management feature group) to identify any endpoints that missed their scheduled scan or show a non-compliant scan policy. — Expected result: a complete, exportable list of non-compliant endpoints (may be empty). — Capture: exported query results. — Stop/continue: continue to step 3 regardless of findings.
3. Check the ePO **VSE: DAT Deployment** query (Menu | Reporting | Queries) to confirm all endpoints are reporting the current signature set as of the scan date, consistent with the "whenever new releases are available" DAT-currency expectation in the [FedRAMP Tailored SI-3 guidance](https://github.com/GSA/fedramp-tailored/blob/master/_guidance/controls/SI-3.md). — Expected result: all managed endpoints report the current DAT/engine version. — Capture: exported DAT Deployment query results. — Stop/continue: continue to step 4 regardless of findings.
4. Investigate and remediate any endpoint shown as non-compliant or with a stale DAT, using ePO **Agent Wake-Up** to force an immediate scan/update. — Expected result: previously non-compliant/stale endpoints show a current scan event and DAT version after wake-up. — Capture: post-remediation query re-run showing the corrected status. — Stop/continue: if an endpoint remains non-compliant after wake-up, escalate per step 5's CAT logic below.
5. Review any detections logged in the Threat Event Log during the period and confirm each was quarantined/cleaned with no unresolved threats remaining; determine CAT (I/II/III) for any unresolved detection per organizational policy. — Expected result: every detection has an `Action Taken` value of quarantined/cleaned, or an assigned CAT and open tracking entry if unresolved. — Capture: annotated Threat Event Log with disposition. — Stop/continue: if any unresolved detection is CAT I, stop and escalate immediately per the Escalation block below.
6. File or update the corresponding POA&M/tracking entry for any open finding (non-compliant endpoint, stale DAT, or unresolved detection). — Expected result: every open finding has a tracking ID. — Capture: POA&M ID. — Stop/continue: continue.
7. Export the ePO Threat Event Log and Policy Compliance report and file them in the repository location specified in the Task Index alongside the reviewer's name and date. — Expected result: cycle record filed. — Capture: the consolidated evidence bundle. — Stop/continue: cycle complete.
