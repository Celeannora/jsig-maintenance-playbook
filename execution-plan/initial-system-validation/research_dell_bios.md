# Dell BIOS Research: Reading BIOS Settings via PowerShell and Manual UEFI Navigation

Scope: Dell business/enterprise client PCs — OptiPlex, Latitude, Precision (and Dell also references Vostro/select XPS for some of the consumer-adjacent overlap). This report covers (1) Dell Command | PowerShell Provider (DCPP) for reading BIOS settings from Windows, and (2) manual BIOS/UEFI setup-menu navigation. All claims are cited to Dell's own documentation, PowerShell Gallery listings of the official Dell package, or other primary/near-primary sources; anything not documented is flagged explicitly rather than guessed.

---

## Part 1: Dell Command | PowerShell Provider (DCPP)

### 1.1 What it is

Dell Command | PowerShell Provider is a Windows PowerShell module ("DellBIOSProvider") that exposes Dell BIOS/UEFI configuration as a PowerShell provider drive (`DellSmbios:`), allowing BIOS settings to be read and changed from the OS instead of the manual F2 setup screen. Per Dell's own product page: "Dell Command | PowerShell Provider is a module that makes BIOS configuration manageable through the Windows PowerShell interface. It works for local and remote systems, and even in a Windows Preinstallation Environment (WinPE)" ([Dell Command | PowerShell Provider – Dell US](https://www.dell.com/support/kbdoc/en-us/000177240/dell-command-powershell-provider)). The Dell-authored PowerShell Gallery help text describes it more precisely: "The Dell Command PowerShell Provider (DCPP) provides BIOS reporting and configuration capability on Dell Optiplex, Latitude, Precision, and Venue 11 systems using PowerShell," implemented as "a PowerShell provider for configuring the SMBIOS on Dell Business Client systems" ([DellBIOSProvider 2.8.0 help file, PowerShell Gallery](https://www.powershellgallery.com/packages/DellBIOSProvider/2.8.0/Content/en-US%5Cabout_DellBIOSProvider.help.txt)).

It is scoped to Dell **enterprise/business client** systems — the original release notes state it provides "BIOS configuration capability to Dell client systems such as OptiPlex, Latitude, Venue Pro Tablet, XPS, and Dell Precision workstation" ([Dell Command | PowerShell Provider 1.0 Release Notes, PDF](https://dl.dell.com/manuals/all-products/esuprt_software/esuprt_client_comnd_suite/esuprt_comnd_pwrshl_prvdr/dell-command-powershell-provider-v1.0_release%20notes1_en-us.pdf)). It does **not** work on non-Windows Dell client systems, per Dell's own FAQ: "Can I use Dell Command | PowerShell Provider in non-Windows Dell client systems? No, Dell Command | PowerShell Provider can be used only on systems running Windows PowerShell console" ([Dell Command | PowerShell Provider 2.8.0 User's Guide FAQ](https://www.dell.com/support/manuals/en-lt/command-powershell-provider/dcpp_2_8_ug/frequently-asked-questions-for-dell-command-powershell-provider-280?guid=guid-d1dc47b8-e30c-41b4-9cc9-268c89a40ed1&lang=en-us)).

**Supported operating systems (current release):** Windows 11, Windows 10, and Windows Preinstallation Environment (WinPE 4.0 onward) ([Dell Command | PowerShell Provider – Dell US](https://www.dell.com/support/kbdoc/en-us/000177240/dell-command-powershell-provider)).

### 1.2 Is it a separate download / not built into Windows? — Confirmed: Yes, separate

DCPP is **not** part of the Windows OS or a default PowerShell module; it must be obtained from Dell (or the Microsoft PowerShell Gallery, where Dell publishes it) and installed/imported before use.

- Dell's own installation instructions describe it as software that "can be installed as plug-in software registered within the PowerShell environment," obtained via drivers & downloads ([Dell Command | PowerShell Provider – Dell US](https://www.dell.com/support/kbdoc/en-us/000177240/dell-command-powershell-provider)).
- The older (2.3/2.4) User's Guide describes manually downloading a `.zip` from Dell's Drivers & Downloads page under "Systems Management," e.g. `DellCommandPowerShellProviderDell_<build number>.zip`, and then running `Find-Module DellBIOSProvider` / `Install-Module DellBIOSProvider` (or `DellBIOSProviderX86` for 32-bit) from an elevated PowerShell console ([PowerShell Provider Version 2.4 User's Guide, PDF](https://dl.dell.com/topicspdf/command-powershell-provider_users-guide_en-us.pdf)).
- Current driver-page installation instructions (2.10.1) show manual installation as an alternative to the PowerShell Gallery: download and unblock the `DellCommandPowerShellProvider2.10.1_.zip`, extract it, create a module folder at `${env:ProgramFiles}\WindowsPowerShell\Modules` (optionally via `New-Item -Type Container -Force -path ...`), then copy files from the architecture-specific subfolder (`DellBIOSProviderx86`, `DellBIOSProvider` for AMD/x64, or `DellBIOSProviderARM64`) into that module folder, and finally verify with `Get-Module -ListAvailable` ([Dell Command | PowerShell Provider Driver Details, Dell US](https://www.dell.com/support/home/en-us/drivers/driversdetails?driverid=twkmg)).
- The module is also distributed through the Microsoft-hosted **PowerShell Gallery** as `DellBIOSProvider`, described there as providing "native configuration capability of Dell Optiplex, Latitude, Precision, XPS Notebook and Venue 11 systems within PowerShell" ([DellBIOSProvider 2.3.0, PowerShell Gallery](https://www.powershellgallery.com/packages/DellBIOSProvider/2.3.0)). Typical install pattern from the gallery: `Install-Module -Name DellBIOSProvider` (as an administrator; NuGet provider install is prompted the first time) ([Virtualization Review – Using PowerShell to View and Change Dell BIOS Settings](https://virtualizationreview.com/articles/2024/02/27/powershell-dell-bios.aspx)).
- Prerequisites documented by a widely cited third-party sysadmin write-up (which references and links Dell's official guides) are: Windows Management Framework 3.0 / PowerShell 3.0+, the Microsoft Visual C++ Redistributable 2015–2022 (or its DLLs `msvcp140.dll`, `vcruntime140.dll`, `vcruntime140_1.dll` copied to `Windows\System32`), and Dell SMBIOS version 2.4 or newer (apply a BIOS update if not met); for use inside a WinPE boot image, the `WinPE-NetFx`, `WinPE-Scripting`, `WinPE-WMI`, and `WinPE-PowerShell` optional components must also be added ([Working with the Dell Command | PowerShell Provider — ConfigJon](https://www.configjon.com/working-with-the-dell-command-powershell-provider/)).
- After installation, the module must be **imported** into a session before use — `Import-Module DellBIOSProvider` (or `Import-Module DellBIOSProviderX86 -Verbose` for 32-bit) — which then exposes a new PSDrive, `DellSmbios:` ([Working with the Dell Command | PowerShell Provider — ConfigJon](https://www.configjon.com/working-with-the-dell-command-powershell-provider/); [Dell Command | PowerShell Provider Version 2.3 User's Guide](https://www.dell.com/support/manuals/en-us/command-powershell-provider-v2.3/dellcommandpowershellprovider_ug_2.3/downloading-and-installing-the-dell-command-powershell-provider-23-module-from-microsoft-gallery?guid=guid-26cadf20-bb44-4a53-bce6-98b2d20dc3fb&lang=en-us)).

**Bottom line:** DCPP requires an explicit download/install step (from Dell's site or the PowerShell Gallery) and an `Import-Module` step — it is confirmed **not** a component that ships pre-installed with Windows.

### 1.3 How settings are read: the `DellSmbios:` provider drive

Once imported, DCPP creates a custom PSDrive, `DellSmbios:`, that mirrors the BIOS setting categories as a navigable "file system." Settings are read using standard PowerShell item cmdlets rather than Dell-specific "Get-DellBiosSetting"-style verbs for most individual attributes:

- Generic read syntax (from Dell's own module help file): `cd <Category>`, `Dir <attribute>`, `Get-Item .` ([about_DellBIOSProvider.help.txt, PowerShell Gallery, v2.8.0](https://www.powershellgallery.com/packages/DellBIOSProvider/2.8.0/Content/en-US%5Cabout_DellBIOSProvider.help.txt)).
- Generic write syntax: `Set-Item <attribute> -value <possible value> -password <PW value>` (same source).
- Built-in help is available directly from the module, e.g. `Get-Help About_DellBIOSProvider`, `Get-Help DellSmbios`, `Get-Help Get-ChildItem -Path DellSmbios:\Security -full` (same source).

This means an inspector/auditor primarily uses `Get-Item` / `Get-ChildItem` against specific `DellSmbios:\<Category>\<Attribute>` paths, plus a small number of true custom cmdlets (`Get-DellBiosSettings`, `Get-DellBIOSPasswordPath`, `Clear-DellAdminPassword`, `Read-DellBIOSPassword`, `Write-DellBIOSPassword`, `Set-Dell1stBootdevice`, `Set-DellAutoOnForSelectDays`) that Dell ships as custom functions alongside the provider.

The Dell-verified plural form is `Get-DellBiosSettings` (returns *all* settings, piped/filtered by the caller — there is no documented singular per-setting "Get" cmdlet; individual settings are read via `Get-Item -Path DellSmbios:\<Category>\<Attribute>`). I am flagging `Get-DellBiosSetting`/`Get-DellBiosPassword`/`Connect-DellCommand` as **unverified/likely inaccurate** and have excluded them from the confirmed table above.

### 1.4 Reading specific security-relevant settings (documented paths and examples)

The table below gives **documented** `DellSmbios:` paths for the categories the task asked about, with the exact syntax found in Dell's own module help file, Dell KB articles, or the official module User's Guides.

**USB boot enable/disable and Virtualization (VT-x) — not confirmed in official DCPP documentation.** I searched Dell's own module help text, the User's Guides (2.3, 2.4, 2.8, 2.9), and the Reference Guide, and could not find a documented `DellSmbios:` path or worked example specifically for USB boot enable/disable or for virtualization support (VT-x/VT-d) settings read through DCPP. Dell's help file explicitly lists `DellSmbios:\VirtualizationSupport` and an "Integrated Devices\USB" category exist conceptually as BIOS screen sections (see Part 2 below, where these appear as BIOS UI screens on OptiPlex/Latitude/Precision setup guides), and since `Get-DellBiosSettings` / the full enumeration script above will surface **any** attribute exposed by the provider on a given system, virtualization and USB-boot settings are very likely readable the same generic way (e.g., something like `Get-Item -Path DellSmbios:\VirtualizationSupport\Virtualization` or an "Integrated Devices" category path). However, I could not find an official Dell document that names the exact attribute string for these two settings, so I am **not fabricating** a specific path for them. An auditor should run `Get-DellBiosSettings` or the enumeration script above on the actual target machine to discover the exact attribute name/path live, since attribute availability and naming can also vary by system generation.

## Part 2: Manual BIOS/UEFI setup menu navigation

### 2.1 Key sequence to enter setup

Across current-generation OptiPlex, Latitude, and Precision systems, Dell's own documentation consistently uses **F2** (pressed repeatedly/immediately at the Dell logo during POST) to enter BIOS/UEFI System Setup, and **F12** for the one-time boot-device menu:

- "Press F2 once a second when the Dell logo appears" — general TPM enablement guide covering Latitude, OptiPlex, Precision, Vostro, and select XPS ([Dell KB 000189676 – How to Enable TPM 2.0](https://www.dell.com/support/kbdoc/en-us/000189676/windows-10-how-to-enable-the-tpm-trusted-platform-module)).
- "Press F2 immediately to enter the BIOS setup program" — Precision 5540 Setup and Specifications guide ([Precision 5540 Setup and Specifications, PDF](https://dl.dell.com/topicspdf/precision-15-5540-laptop_owners-manual2_en-us.pdf)).
- "Press F2 several times as soon as you see the Dell logo... The BIOS setup screen will appear. Alternative method: Press F12 at the Dell logo. Select 'BIOS Setup' or 'System Setup' from the menu. If F2 doesn't work, try pressing Fn + F2 together, or press F2 repeatedly rather than holding it down" ([Dell BIOS and UEFI Update Download and Installation Guide](https://www.dell.com/support/kbdoc/en-us/000124211/dell-bios-updates)).
- "During Boot, Press <F2> or <Del> to enter BIOS setup" and "Press F12 during boot to access the boot menu" also appear in Dell's own broader-platform documentation and in Dell KB troubleshooting steps for Secure Boot ([Dell KB 000483242 – Cannot boot from USB media with Secure Boot enabled](https://www.dell.com/support/kbdoc/en-ba/000483242/cannot-boot-from-usb-media-with-secure-boot-enabled-after-installing-may-2026-kb5089549-windows-update)).
- Legacy OptiPlex documentation confirms the same pattern is long-standing: "During the Power-on Self Test (POST), when the Dell logo appears, you can: Access System Setup by pressing <F2> key; Bring up the one-time boot menu by pressing <F12> key" ([Dell OptiPlex 7020 Small Form Factor Owner's Manual, PDF](https://dl.dell.com/topicspdf/optiplex-7020-desktop_owners-manual2_en-us.pdf)).

**Note:** on systems where fast boot/BIOS POST time is set very low, F2 may need to be triggered via Windows' Advanced Startup ("UEFI Firmware Settings") instead of catching the keypress at boot, per a Dell community discussion referencing a Latitude 3440 ([Dell Community — Disable SafeBIOS thread](https://www.dell.com/community/en/conversations/device-management/disable-safebios/647fa22ff4ccf8a8de79d59a)). This is community-sourced, not an official KB, and is noted here as a caveat rather than a documented procedure.

### 2.2 Two BIOS UI generations — confirmed to differ

Dell's own support content confirms there have been **at least two distinct BIOS/UEFI user-interface generations** on business client systems, with materially different navigation:

**(a) Classic/legacy Dell BIOS UI** (older OptiPlex/Latitude/Precision, generally pre-~2021 systems): a left-aligned or tab-based menu tree navigated primarily with keyboard arrow keys, Tab, and Enter; typical top-level sections include General/System Information, Boot Sequence, System Configuration, Security, Secure Boot, Intel Software Guard Extensions, Performance, Power Management, POST Behavior, Manageability, Virtualization Support, Wireless, Maintenance, System Log, and Advanced Configuration — this exact section list appears on the OptiPlex 7460 All-in-One's official setup guide ([Dell OptiPlex 7460 All-in-One Setup and specifications guide](https://www.dell.com/support/manuals/en-us/optiplex-7460-aio/optiplex_7460_setup_specs/entering-bios-setup-program?guid=guid-1432a924-49e9-4080-961d-2afbdaf42039&lang=en-us&lang=en-us)). A detailed community walkthrough of this style of menu (Precision Fixed Workstation) documents keyboard-only traversal, e.g., to disable Secure Boot: "F2 (to get into BIOS) → ArrowLeft (close 'General') → 4x ArrowDown (to 'Secure Boot') → ArrowRight (expand) → ArrowDown (to 'Secure Boot Enable') → Tab → Enter (select 'Disabled') → Enter (confirm) → Esc → Enter (save)" ([Dell Community — Navigating BIOS blindly with keyboard](https://www.dell.com/community/en/conversations/precision-fixed-workstations/navigating-bios-blindly-with-keyboard/647fa3f4f4ccf8a8de9fdcb1)). This is a community forum post (not an official KB), but it corroborates the menu hierarchy Dell's own manuals describe (General → Boot Sequence / Advanced Boot Options → Security → Secure Boot → Secure Boot Enable) and is included as a practical navigation illustration, clearly labeled as community-sourced.

**(b) "New Dell Branded BIOS" / modern BIOS UI ("BIOS 4.0")** — Dell explicitly documents this as a distinct, restructured interface:
- A Dell KB article on password clearing explicitly distinguishes behavior: *"The BIOS password is not cleared because this new BIOS requires different steps to clear a previously set BIOS password. On previous BIOS versions, users did not have to perform any action in the blank new password field. The new Dell Branded BIOS requires the user pressing the enter key in the Blank Password and Confirm Password fields. Click the Apply Changes button to set a blank password."* This article is explicitly scoped to "computers were released in May 2021 or later" ([Dell KB 000190038](https://www.dell.com/support/kbdoc/en-us/000190038/my-computer-keeps-asking-for-the-bios-password-when-booting-after-removing-a-previous-bios-password)).
- Dell's own product video "What is new in BIOS Setup?" describes **BIOS 4.0** as "the latest BIOS update from Dell Technologies," with the UI "enhanced, restructured, and simplified": option tiles are shown in a **left pane**, selecting an option displays its subsections on the **right side**, classic checkboxes/radio buttons (e.g., for "TPM 2.0 Security" or "Adapter Warnings") were replaced with **toggle switches**, and inline help text was added under each setting. The upper-left area has an **Advanced Setup** toggle (to show/hide advanced sections like Connection, Power, Security), a **Help Text** toggle, and an **Admin Password** tile (used to unlock all settings if an admin password has been set). The upper-right area has a **Search** icon and a **View All** icon (a single hyperlinked index of all options and subsections) ([Dell Support video: What is new in BIOS Setup?](https://www.dell.com/support/contents/en-uk/videos/videoplayer/what-is-new-in-bios-setup/1701474957333093963)).
- A community discussion corroborates that this modern interface look ("looks like a webpage with tiles/toggles") is associated with newer Dell BIOS builds (e.g., seen on a Latitude 5520 and a newer Inspiron 3593) versus older devices still using an Insyde H2O–style or AMI Aptio–style interface (e.g., an older Inspiron 3537) ([Reddit r/Dell — "Are Dell updates supposed to look like this?"](https://www.reddit.com/r/Dell/comments/1e1kfkx/are_dell_updates_supposed_to_look_like_this/)). This is community-sourced and used only as corroborating color, not as a primary citation for menu paths.

**Net assessment:** Dell has **officially and explicitly acknowledged** a UI/behavior change between "previous BIOS versions" and the "new Dell Branded BIOS" (introduced around systems released May 2021 and later, and further evolved into the tile/toggle "BIOS 4.0" interface). An inspector auditing a fleet spanning several purchase years should expect to see both the classic tab/tree UI and the newer tile-based UI depending on device age and BIOS revision, and should not assume identical keystrokes or click paths across the fleet.

**Honesty note on generation-specific menu paths:** Dell's per-model "Setup and Specifications" manuals (e.g., for Latitude 5540) list "System setup options," "Boot sequence," "Security," and "TPM" as manual sections, but the fetched page content for that specific current-generation manual did not expose the underlying key-sequence or exact click-path text through the automated fetch used for this research (the manual page structure returned only a table of contents). This report is transparent that this specific current-gen manual's granular navigation text was **not independently verified word-for-word**, even though the general category names (Boot Sequence, Security, Secure Boot, TPM 2.0 Security, Virtualization Support, Integrated Devices) are corroborated across multiple other official Dell sources cited above and are consistent across OptiPlex/Latitude/Precision documentation for many years of models. If an inspector needs the literal current-model manual text, it should be pulled directly from Dell's manuals for that exact model/service tag at support.dell.com.
