| ISCP Coordinator | Typically a functional or resource manager within the organization; develops the strategy in cooperation with other functional and resource managers associated with the system or the mission/business processes supported by the system; typically manages development and execution of the contingency plan |
| Senior management | Must support a contingency program and be included in the process to develop the program policy |
| Designated authority | Has the authority to activate the contingency plan; only one individual should have this authority; a successor should be clearly identified to assume that responsibility if necessary |
| Plan development roles | Roles and responsibilities section presents the overall structure of contingency teams, including hierarchy and coordination mechanisms and requirements among the teams; teams and team members should be designated for specific response and recovery roles during contingency plan activation |
| Management team | Provides overall guidance following a major system disruption or emergency; responsible for activating the contingency plan and supervising the execution of contingency operations; facilitates communications among other teams and supervises information system contingency plan tests and exercises |
| Team leader | Directs overall team operations, acts as the team’s representative to management, and liaises with other team leaders; disseminates information to team members and approves any decisions that must be made within the team; should have a designated alternate |
| Senior management official | Such as the CIO; has ultimate authority to activate the plan and to make decisions regarding spending levels, acceptable risk, and interagency coordination; typically leads the management team |
| Outage Assessment Team | Representative title; notified after disruption for outage assessment |
| Team staffing guidance | Personnel should be chosen based on skills and knowledge; ideally, teams are staffed with personnel responsible for the same or similar functions under normal conditions; teams should be sufficient in size to remain viable if some members are unavailable to respond; alternate team members may be designated; personnel from another geographic area or contractors/vendors may be coordinated and trained as an alternate team |

| BIA purpose | Identify and prioritize system components by correlating them to mission/business process(es) the system supports, and use this information to characterize the impact on the process(es) if the system were unavailable |
| BIA steps | 1. Determine mission/business processes and recovery criticality. 2. Identify resource requirements. 3. Identify recovery priorities for system resources. |
| Impact categories example | Cost |
| Example impact values for cost | Severe; Moderate; Minimal |

| RTO definition | Maximum amount of time that a system resource can remain unavailable before there is an unacceptable impact on other system resources, supported mission/business processes, and the MTD |
| RPO definition | Point in time, prior to a disruption or system outage, to which mission/business process data must be recovered after an outage |
| BIA time values example | Pay vendor invoice MTD 72 hours; RTO 48 hours; RPO 12 hours (last backup) |
| BIA output example resource priority | Web Server 1; Optiplex GX280; 24 hours to rebuild or replace |

| Alternate processing site types | Cold Sites; Warm Sites; Hot Sites; Mobile Sites; Mirrored Sites |
| Cold site characteristics | Basic infrastructure and environmental controls available; no equipment or telecommunications established or in place; sufficient room to house needed equipment; least expensive alternate processing site solution; recovery time longest |
| Warm site characteristics | Basic infrastructure of cold sites; sufficient computer and telecommunications equipment installed and available; equipment not loaded with software or data required to operate the system; more expensive than a cold site; recovery can take several hours to several days |
| Hot site characteristics | Fully operational equipment and capacity to quickly take over system operations; sufficient equipment and most current version of production software installed; adequate storage for production system data; most expensive option |
| HA definition | Uptime of 99.999 percent or better |
| HA deployment note | HA can be implemented at a single site; HA processes should be extended to an alternate location; block mirroring to an alternate site should be considered |
| Telecommunications link types | T-1; T-3; Frame Relay; Asynchronous Transfer Mode (ATM); Synchronous Optical Network (SONET) |
| T-1 details | Dedicated phone connection supporting data rates of 1.544 Megabits per second (Mbps); 24 individual 64-kbps channels |
| T-3 details | Dedicated phone connection supporting data rates of about 45 Mbps; 672 individual channels each supporting 64 kbps; also referred to as Digital Signal (DS) 3 |
| Frame Relay details | Packet-switching protocol for connecting devices on a WAN; data routed over virtual circuits; support data transfer rates at T-1 and T-3 speeds |
| ATM details | Transfers data at high speeds using packets of fixed size; support data transfer rates from 25 to 622 Mbps and provide guaranteed throughput |
| SONET details | Standard for synchronous data transmission on optical media; supports gigabit transmission rates |
| Remote access security requirements | Verify user identity through electronic authentication (e-authentication); four levels of protection from minimal identity verification (Level 1) to cryptographic two-factor authentication keys (Level 4); multifactor authentication and data encryption should be implemented if communications contain FIPS 199 moderate- or high-impact information |
| Wireless contingency security | Data encryption should be employed if communications traffic contains FIPS 199 moderate- or high-impact information |
| Mainframe contingency measures | Store backup media offsite; document system configurations and vendors; coordinate with network security policy and system security controls; utilize results from the BIA |
